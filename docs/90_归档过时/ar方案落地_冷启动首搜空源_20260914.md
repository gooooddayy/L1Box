## 二、用户新报的问题：冷启动首搜「空源」

> 完全划掉 App（清后台）→ 打开 → 搜一个词 → 有时候会是空源状态，回到首页再次搜索就又显示正常了。
> 空源状态下完全退出软件，再次进入第一次启用源的话跟之前一样。

这是**纯逻辑时序问题，与崩溃无关**，日志里也查不到崩溃（0 次）。

### 根因链路（逐步实证）

1. 站点池有两个容器：`sourceBeanList`（订阅站点池，来自线路配置）与 `homeSiteList`（内置首页源，来自 assets）。两者**都是异步装载**的。
2. 冷启动时，订阅要发网络请求、内置首页源要等 `HomeFragment` 走到 `loadLocalHomeConfig`，**两者存在一段同时为空的窗口**。
3. `FastSearchActivity.search()` 取站点池快照：
   ```
   searchRequestList.addAll(ApiConfig.get().getSourceBeanList())
   val home = ApiConfig.get().homeSourceBean
   searchRequestList.remove(home); searchRequestList.add(0, home)
   ```
   冷启动窗口内 `getSourceBeanList()` 返回**空表**（首页源兜底条件 `!homeLocalLoaded && sourceBeanList.size() > 0` 也要求订阅池非空，所以兜底也不生效）。
4. 循环收集可搜索站点时 `siteKey` 为空 → 命中这段判空：
   ```kotlin
   if (siteKey.isEmpty()) { showEmpty(); cancel(); return }
   ```
   → 用户看到的"空源"。点得越快越容易撞上，这就是"有时候"的来源。
5. **加剧因素**：`SearchHelper.getSourcesForSearch()` 在站点池为空时回退到 `getSources()`，而后者遍历空池得到**空表**。搜索侧原来的判据是 `mCheckSources != null && !mCheckSources.containsKey(key)` → 空表把**全部站点**都判为"未勾选"而滤掉，得到同样的空源。
6. 回首页再搜就正常：此时 `reloadSitePool()` 已完成，站点池非空 → `siteKey` 非空 → 结果正常。**这不是"修复"，只是时间过去了。**

一句话：**把"还没加载好"误判成了"没有源"。**

## 三、修法（5 处，全部为机制性判定，不依赖机型与竞速运气）

### 1) `ApiConfig.java` —— 新增装载定论标志

```java
private volatile boolean sitePoolSettled = false;
public boolean isSitePoolSettled() { return sitePoolSettled; }
```

**四个装载出口全部置位**（只置位、不复位）：

| 出口 | 语义 |
|---|---|
| `parseJsonInternal()` 站点解析完 | 订阅装载完成，解析出 0 个站点也算有定论 |
| `loadConfig()` 无 apiUrl 分支 | 确实没订阅 → 明确空态，不该等待 |
| `loadLocalHomeConfig()` 首页源解析后 | 内置首页源就绪，即便订阅还在途中也有源可搜 |
| `doLoadConfigRequest.onError()` 重试用尽 | 装载失败也是定论，避免搜索侧无限等待 |

为什么必须用独立标志：站点池为空时，"没订阅"和"还在装载"在列表上**完全同形**，只靠列表判空无法区分。

### 2) `FastSearchActivity.kt` —— 未就绪时等待重试，而不是甩空态

```kotlin
if (siteKey.isEmpty()) {
    if (!ApiConfig.get().isSitePoolSettled() && readyRetry < READY_RETRY_MAX) {
        readyRetry++
        searchWatchdogHandler.postDelayed(readyRetryRunnable, READY_RETRY_DELAY_MS)
        return
    }
    showEmpty(); cancel(); return     // 真空态才给空态
}
readyRetry = 0
```

节奏：**4 次 × 500ms = 最多等 2 秒**，覆盖冷启动订阅拉取 + 首页源解析窗口。重试只重跑 `searchResult()`，不重复走 `search()` 的 UI 复位与历史写入。用户在重试期间**不需要退回首页**。

### 3) `FastSearchActivity.kt` —— 空勾选集合不等于"全都不选"

```kotlin
if (mCheckSources != null && mCheckSources!!.isNotEmpty() && !mCheckSources!!.containsKey(bean.key)) continue
```

空表 = 没有过滤意图 = 全选。原来的写法会把冷启动回退出的空表当成过滤条件，把全部站点滤掉。

### 4) `DetailActivity.java` —— 详情页换源搜索同一处判据对齐

同一根因的第二个触点，一并加上 `!mCheckSources.isEmpty()`。

### 5) `check_l1box_regressions.sh` —— 新增 V 节 8 条断言

覆盖定论标志存在性/volatile、四处置位（`count = 4`）、getter、搜索侧未就绪判定、重试必须真的排上定时任务、重试计数复位、空勾选集合语义、详情页判据一致。
