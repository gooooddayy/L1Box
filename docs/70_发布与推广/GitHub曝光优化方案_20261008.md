### ③ README 首段 —— 补技术关键词（收益中高）

**现状首段**：

> 基于开源播放器框架二次开发的 **竖屏手机版**。

**建议改成**（保留原意 + 埋入可被搜索的技术词）：

> 基于开源播放器框架二次开发的 **Android 竖屏手机版**（Kotlin / Java）。
> 面向**手机竖屏**场景重写了布局与手势，并提供播放内核选择、缓冲水位按设备分档、磁盘缓存、
> 搜索并发收敛、订阅数据容错等能力。自身**不含任何内容源**。

**再在 README 里加一个「主要技术特性」小节**（GitHub 搜索会索引 README 正文）：

```markdown
## 主要技术特性

- **竖屏布局与手势**：左栏分类滑动、右侧惯性自研（指数衰减，非线性插值）
- **播放内核**：ExoPlayer / ijkplayer 双内核，按设备档位选择与回退
- **缓冲与缓存**：缓冲水位按设备分档、磁盘缓存（可开关）、冷启动清理陈旧缓存
- **搜索链路**：多站点并发收敛、假空结果的结构性排除、超时收尾
- **订阅与数据**：配置解析容错、多线路切换、首页冷启动缓存
- **工程**：Gradle 构建 + 源码级回归闸门（800+ 静态断言）+ dex 符号校验
```

> 这些描述**每一句都是真实存在的实现**，不是堆词 —— 这也是它能被搜索引擎"认真对待"的原因。

## 四、⚠️ 全场景红线词表

**任何对外文字**（Description / Topics / README / Release / 文章 / 社交平台）都**不要**出现：

```
TVBox、影视、追剧、看片、片源、资源站、线路、聚合、免费、VIP、会员、
破解、解析接口、m3u8、iptv、直播源、爬虫/spider、点播、动漫、美剧、港剧
```

**可安全使用的技术词**（本方案里已用的都是这类）：
```
播放器 / player、媒体 / media、框架 / framework、解码 / decode、缓冲 / buffer、
```

> 注：「解析」单独作为技术词（如「配置解析容错」）是安全的；危险的是「**VIP 解析**」「**解析接口**」这类组合。

## 五、期望管理（说实话）

1. **安全词域的流量天花板是有限的**。`android video player` 在 GitHub 上有上万个仓库，光靠关键词配置冲不到前面 —— 关键词只解决"能搜到"，不解决"排前面"。
2. **真正拉开差距的是内容与活跃度**：持续提交、Release 更新、技术文章被引用、被 awesome 列表收录。
3. **受众错位要提前认清**：这个项目装上**没有内容**，普通影视用户用不了。
   ⇒ 吸引他们 = 负资产（来问"怎么没源"、给差评）。
   ⇒ **应该瞄准的是 Android 开发者**（学播放器架构、缓存策略、竖屏适配的人）—— 人少但对口，star 质量高。
4. **一句话**：本方案能让你"被对的搜索引擎搜到"，但不能让"影视用户"找到你 —— 后者本来就不该是目标。
