> 用户口径（原话）：**「只播放能正常播放的源，需要解析的按照正常加载，加载不出会自动报错，不要另加判错(防止误判)，一定要从全局视角重新优化一下方案，不要在错误的问题上修补」**
>
> 因此本方案的第一步是**撤除我自己加的所有"判错/预判"逻辑**，然后从"主线程负载 + 请求生命周期"两个全局视角重做。

## 一、先撤掉"判错"（这是本轮的核心，不是补丁）

| # | 撤除项 | 为什么必须撤 | 撤掉后的行为 |
|---|---|---|---|
| 1 | `PlayFragment.isPlayableUrl()` 门闸（"不含 `://` 就判死，跳过播放器与兜底链"） | 它是我早前为防空转加的**预判**。cb 日志里<站点I> `YYNB-<32hex>` 这类**令牌地址被它整类判死**（×6），而正确做法是**交给原有流程**（`parse` 标志决定走解析；其余直连，播不了自然会报错） | 地址一律按原有流程处理：能播就播；播不了由内核报错、按原有兜底链走完、给提示。**可能多花几秒，但不误杀** |
| 2 | 图片"可见优先"门闸 `ImageWindowGate`（按 position 判 + 下载线程按 URL 跳过） | 两套判据不一致、过滤模式窗口来源错（`mGridView` 当时是 GONE）⇒ **点左侧站点时图片全不加载**（cb 实测 `取出=16 跳过=15`）。而且"贴"它只会再犯错 | **所有图片照常请求**（一张不漏、不预判），改由"**在途请求及时取消**"解决吞吐（见 §二） |
| 3 | 收尾时"对可见区间强制重绑"（`notifyItemRangeChanged`） | 它是为 gate 兜底的补丁，而且每次重绑 ~8 项 = 一次多余主线程负载（与跟手卡顿同向） | 删除。图片靠"绑定即请求"自然加载 |
| 4 | 方案里曾提的"**地址形态判定**"（媒体/网页/令牌分流） | 同属预判，按你的口径**作废** | 不实施 |

**保留（都不是判错，是纯增强/纯可见性）**：
- 图片并发 4→8、独立 Dispatcher/连接池、超时收紧到 4s/6s、浏览器 UA + 按域名补 Referer；
- 结果落地限流 12 条/拍、`itemAnimator = null`、左栏 `suppressLayout` 批量布局；
- 错误码/失败原因**只记日志不判行为**（`PlayErrCode` 归因、图片账本）；
- I2「同址同类已试过 ⇒ 不再重复走同一档」——**依据是"已经发生过的事实"，不预判地址**（若你也不想要，说一声我撤）。

## 二、图片：从"不发请求"改成"及时取消在途请求"（全局视角的正解）

**问题本质**：250+ 张图、8 路并发、且 **Picasso 的下载不可取消**（`Downloader` 接口没有 cancel）
⇒ 滑动时大量"已经划过去的图"仍在下载，占着 8 条道，你真正要看的图排在后面。

**新做法（不再是 gate，不预判任何东西）**：

| 步骤 | 说明 |
|---|---|
| ① 照常请求 | adapter 绑定即请求（恢复原行为），**不判断可见性、不跳过** |
| ② 登记在途 | 下载器把每个请求的 `Call` 登记到 `L1ImageInflight`（URL → Call） |
| ③ **停稳/切换站点时取消越界的在途请求** | 用"可见 ±3 项"的 URL 集合做**保留集**，其余**已经滚出屏幕、正在下载的**立刻 `call.cancel()` → 下载线程**秒级释放** |
| ④ 滚回来会重新加载 | 取消只影响"当前看不到的"，item 再回到可见区时重新绑定 → 重新请求（Picasso 不缓存失败）⇒ **不会漏图** |
| ⑤ 保留统计 | `图片队列：取出=N 取消=K 在途=S` + 原成功率账本（纯日志） |

**与 gate 的本质区别**：gate 决定"**要不要发请求**"（会漏、会误判）；本方案**请求照发**，只是在它**已经确定看不到时**把它取消（不误判、不漏，还省线程与流量）。

## 四、播放：恢复"自然行为"（不判错）

- 撤门闸后，播放链回到：`parse=1` 或 `jx=1` → 走原有解析通道；否则直连 → 内核播不了就报错 → 原有兜底链（变形/降级/重取）→ 明确提示。
- **代价（如实说明）**：像<站点I>那种"非 URL 令牌地址"，会从"1 次判死"变成"走完兜底链再提示"，单次多花约 4~6 秒；但换来的是**不误杀任何可播地址**（你要的优先项）。
- 归因**只改文字不改行为**：Exo `3xxx` 从"解码"改标为"解析/容器"（原来标错了），方便日后按日志判断，但**不据此跳过任何步骤**。

## 五、验收指标

| 指标 | 现状（cb） | 目标 |
|---|---|---|
| 点左侧站点后图片 | 不加载（gate 误判） | **正常加载**（请求照发 + 停稳取消越界） |
| 图片队列账 | `取出=6~64 跳过=94%` | `取出` ≈ 命中图数量级；`取消` 只发生在滚走的图上；`在途` 收敛到个位/十位 |
| 帧卡顿（>32ms） | 3 次/轮（最差 331ms，且只统计了搜索期） | 先量准（常开 + 阶段 + 分段计时），再做定向优化 |
| 播放失败 | 令牌地址被判死（×6） | **不判死**：走原有流程，播不了自然报错 |
| 早收尾/条数 | 命中 266~522 | 不变（不动判定逻辑） |
