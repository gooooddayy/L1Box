## 五、我的改动可能改变了什么（**待日志验证，不是结论**）

我改的是 `ApiConfig` 的**清池行为**：换源（地址变过）失败时调 `clearPoolInternal()`，而它会把 **`spider = ""` 一起清掉**。

| 推测 | 机制 | 对用户症状的影响 |
|---|---|---|

⇒ **用户"经常遇到"是事实，但它对应的是「jar 装载失败」本身**；

## 10.5 修复方案（**待确认，本轮未动手**）

### A. 内容校验：非 zip/dex **一律不落盘**（治本，最重要）

把 `convertResponse` 改成"**先读进内存 → 校验 → 才删旧文件 → 才写**"：

```java
byte[] data = isJarInImg ? getImgJar(response.body().string()) : response.body().bytes();
if (!looksLikeJar(data)) {                      // 头 2 字节必须是 'P''K'，或 'd''e''x'
    throw new IOException("jar 内容非法（HTTP " + response.code() + " 长度 " + data.length + "）");
}
if (cache.exists()) cache.delete();
... 写入 data ...
```

**抛出异常会发生什么（这是关键）**：OkGo 走 `onError`，而 `downloadJar` 的 `onError` **本来就有兜底**：

```java
public void onError(Response<File> response) {
    if (cache.exists() && cache.length() > 0) {          // 旧 jar 还在（因为没删）
        loadJarFileAsync(cache, ..., "网络不佳，已使用缓存数据源");   // ← 用旧 jar 顶上
        return;
    }
    callback.error("");
}
```

⇒ **一举两得**：
- `csp.jar` **不再被摧毁**（旧 jar 始终可用）
- 用户看到的是 **「网络不佳，已使用缓存数据源」**，而**不是**「线路切换失败」+ 首页不加载

## 10.6 副作用与兼容性

| 项 | 影响 |
