# ap 落地说明：批次二（装载复用）+ 批次三（受控接力）

日期：2026-09-14　产物：`FreeBox-src/L1Box_v1.1.1_release_20260914ap.apk`（60,860,024 B，MD5 `64373a044bce47e1601a74b6b44d8d2f`）

---

## 一句话

把「每次重载配置就重建一代 ClassLoader」改成「**一个 jar 在整个进程生命周期内只装一次**」，
并补上由此**必需**的「代理持有者换届规则」。

---

## 一、三个文件改了什么

### 1. `JarLoader.java` —— 装载复用（批次二）

| 改动 | 内容 |
|---|---|
| 新增静态复用表 | `REUSED`：key = jar 绝对路径，值 = 指纹 + DexClassLoader + 是否家族 + Proxy 方法。容量 20、LRU、**淘汰时跳过当前持有者** |
| `loadJarInternal` | 先中和（幂等）→ 取**文件指纹** → 查复用。命中就直接挂回本实例路由表，**跳过下载、全量 dex 扫描、建类、原生初始化** |
| `loadClassLoader` | 同样先查复用；装载成功后写入复用表（连带 Proxy 方法，复用时不需重新反射） |
| `load()` | **不再**无条件重置进程级单飞 / 清路由账本；只有主实例的 load 才重新打开接力窗口 |
| `getSpider` | 命中持有者的 jar 就关闭接力窗口（放在最前面，连缓存命中也算「用过」） |
| 删除 | JarLoader 自己那份 `proxyHolderKey` —— 持有者身份与 key 从此只有一处 |

**指纹口径**：固定取「中和之后的文件内容 md5」。不用订阅声明的 md5 —— 中和器会改写缓存文件，
声明值天然对不上，用它当复用依据等于永远不复用。文件内容才是「这个 loader 装的是什么」的唯一可靠描述，
也天然满足「服务端换版必须重建」（换版 = 内容变 = 指纹变），所以「下拉刷新能让 jar 更新」这条铁律没被动过。

### 2. `ProtectedInitJar.java` —— 持有者身份单一化 + 受控接力（批次三）

- 新增 `PROXY_HOLDER_KEY`：与 `PROXY_HOLDER` **同锁更新**，身份和它的 key 永远是同一份真相。
  （am 会话「账本上没有、方法还能调」的空洞，就是双份状态各自过期的产物。）
- 新增 `HOLDER_USED` 与 `takeoverWanted()`：**旧持有者在本代已无人请求**时才允许换届。
- `init(clz, key)`：在 `NATIVE_INIT_LOCK` 内先做接力判定，再启动代理；持有者一确立就置位 `HOLDER_USED`
  —— 这一条是防「首轮多个家族 jar 并发装载时互判可接力、各启一次代理」的关键。
- `resetProxyFlight` 不再清 `PROBE_CACHE`（复用时代整体清空会让服役中的 loader 白探测一遍），
  改由新增的 `forgetLoader` 在真正丢弃某个 loader 时精确清理。

### 3. `JarKillNeutralizer.java` —— 顺带修一个真缺陷

「已处理」记账从「路径」改成「**路径 + 大小 + 修改时间**」。
旧写法在 jar 换版（下拉刷新下载新 jar 覆盖缓存）之后会**跳过中和**，新 jar 里的自杀调用就没人管了。

## 二、为什么批次二、批次三必须一起做

批次二删掉了「每次重载都重置持有者」这条旧规则。**如果不补换届规则**，切线路之后新线路的家族 jar
永远拿不到持有者身份 → 它的网盘代理源恒 503。

一个是「不重建」，一个是「谁接手」，是同一个改动的两面，拆开做必然中途破功能。

---

## 三、三条机制性保证（不依赖具体机型）

1. **类不换代** → native 侧记着的 `jmethodID` 不会失配 → 治「退出→重进→立刻搜索必崩」。
   （原理：「退出」不杀进程，「重进」复用进程重新 loadConfig；旧逻辑每次都 new 一代 ClassLoader，
   而进程内已 dlopen 的原生库不随之卸载。）
2. **代理只有一个持有者，换届只发生在「旧持有者本代无人请求」时** → 不复活 killall 互杀链。
   判定与执行同处 `NATIVE_INIT_LOCK` 一个临界区，不存在两个 jar 各判可接力的窗口。
3. **`/proxy` 的身份终审 + 运行时探测不依赖静态判据正确** → 即使某个未知变体骗过静态判据、
   走了普通路径装载，它也依然打不到 native（这一层与「判据是否正确」解耦）。

## 四、本轮一次测完的口径

挂的日志：`logcat_ap_20260914.log`（全 buffer，含 crash）。设备已连、APK 已装。

| # | 场景 | 次数 |
|---|---|---|
| 1 | 冷启动 → 进入软件 → **立刻**搜索 | 5 轮 |
| 2 | **退出软件 → 重进 → 立刻搜索**（本轮主目标） | 5 轮 |
| 3 | 切换线路，确认新线路的网盘类源仍能用 | 2 次 |

**通过判据**：`Fatal signal 6` = 0、`JNI DETECTED ERROR` = 0，且能正常出搜索结果。
**功能不降级**：加固 jar 的网盘源仍可用（证明没被过度拒载）。

### 预期

- 「退出重进」不再崩 —— 本轮主目标
- **重进后的首搜明显快于之前**：不再重新下载 + 重新抽解原生库 + 重新初始化（`killall` 降到 0~1 次）
- 首搜本身仍与 ab 同速（并发口径没动，仍是全员 10 + 两参）

### 如果还崩，日志会直接指路

新增两句日志，出现哪一句就说明走到了哪条路径：

- `运行时探测命中家族 jar（静态判据漏判，已改走受控路径）：<key>` —— 静态判据又漏了，但运行时探测兜住了
- `受控接力：旧持有者本代未被请求，交由新的家族 jar 接管本地代理` —— 换届发生了

## 五、两次改动累计（相对 ab）

| 维度 | 相对 ab | 依据 |
|---|---|---|
| 崩溃（「退出重进」路径） | **机制性消除** | 类不换代 = `mid==null` 不成立 |
| 崩溃（未知 jar 变体） | **机制性消除** | 运行时权威探测 + `/proxy` fail-safe（与判据正确性解耦） |
| 重进后的首搜速度 | **提升** | 免下载/免扫描/免抽解/免初始化 |
| 首搜速度 | 持平 | 并发与调用口径仍是 ab |
| 功能完整性 | 持平或更好 | 受控接力让切线路后的家族网盘源可用；中和器修好换版后失效的缺陷 |

## 六、本轮**没有**做的事（以及原因）

- **结果缓存（同词二搜）**：要引入失效策略，是新的脏数据风险面。零收益的变量留给下一轮独立验证。
- **慢源分档超时**：要动搜索收尾逻辑。当前 120ms 攒批 + 全局 30s 看门狗工作正常，属于体感优化，不是本轮目标。
- **分源并发**：已按你的决定整条撤除，不再考虑。
- **并发数 / 预热 / `quick` / 家族 jar 提前加载**：四条永久移出，已被 ae/ai/al/am 四版实验逐一否掉。
