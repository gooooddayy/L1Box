## 3. 改前代码的机制缺陷（逐条 `git show HEAD` 核实，8/8 命中）

| # | 改前是什么样（HEAD 原始代码） | 会造成什么 | 现在 |
|---|---|---|---|
| ① | `PlayFragment` 里 **`Watchdog` 出现 0 次** —— 没有任何看门狗 | 黑屏转圈**不算失败**，永远等不到兜底；取链卡住则永远停在「正在获取播放信息」 | 起播 20s / 取链 15s 看门狗，判死前先复核 |
| ② | `retriedSwitchPlayer` 只有"声明 + 置位"（HEAD 161/727/729），**没有任何清零** | 第一集触发过之后，**后面每一集都没这层保护**；且它直接 `mPlayerBtn.performClick()`（会唤起 MX/VLC） | 删掉该开关，改由按集复位的降级阶梯统一覆盖；自动只切内置 |
| ③ | 取链回调的 `catch` 是空的（`errorWithRetry` 被注释掉） | 异常时界面**永远**停在「正在获取播放信息」 | catch 里留痕，超时由取链看门狗兜底 |
| ④ | 取链空返回走 `errorWithRetry(..., true)` → **只弹 2 秒 Toast、不关 loading 浮层** | 提示一闪而过 + 界面继续转圈（实测 **65 秒**） | **第四批 aw** 统一为"错误态 + 可点重试" |
| ⑤ | 净化预取**没有独立超时**（HEAD 里没有 `PURIFY_TIMEOUT_MS`） | 用默认 10s 超时、有跳转要拉两遍 ⇒ 起播前最长白等 **约 20 秒** | 独立 2.5s 超时，超时立刻用原始地址直连起播 |
| ⑥ | 去 BOM 把**整份清单外发**第三方 `home.jundie.top:666/unBom.php` | 凭空多一个外网失败点，且清单内容外流 | 改本地实现（自己拉、自己剥 BOM、经内置代理喂播放器） |
| ⑦ | `RemoteServer.m3u8Content` 是 `public static String`（**非 volatile**） | OkGo 回调线程写、NanoHTTPD 工作线程读，可能读到空内容 | 加 `volatile` |
| ⑧ | Exo 数据源是**共享单例** + `setDefaultRequestProperties(headers)`（HEAD 177/203 行）；`setEnableDecoderFallback` 未开；IJK 无 `rw_timeout` | 请求头**跨源残留**（上一个源的 Referer/UA 带到下一个源 → 可能 403）；硬解失败不回退；IJK 对端不吐数据时无限挂死 | 每源独立 Factory（UA 走 `setUserAgent`）；Exo 开解码回退；IJK 补 `rw_timeout`（仅订阅未指定时） |

> ①②③⑤⑥ 是"改前会卡死/白等"的根因，④⑦⑧ 是"改前会播不出/播错"的根因。

## 4. `aw`（第四批）改了什么

| # | 改动 | 依据（实测证据） | 预期效果 |
|---|---|---|---|
| **1** | **失败出口统一**：删掉 `errorWithRetry(err, finish)` 的"只弹 Toast"分支，所有失败一律关掉转圈、留错误态、带一个可点的「重试」 | av 实测：取链空返回后界面转了 **65 秒**（Rebo 第 1/3 集） | 用户从"以为卡死、只能退出重进"变成"看到原因、点一下重试" |
| **2** | **本机代理地址不做 http↔https 变形**：守卫从"只认 `/l1.m3u8`"改成"任何 127.0.0.1 / localhost" | av 实测：把 `http://127.0.0.1:9978/proxy?...` 变形出 `https://127.0.0.1:9978/proxy?...`（TLS 必失败） | 少一次必然失败的尝试 |
| **3** | **不是 URL 的地址早判**：起播前判 `不含 "://"`（迅雷通路 magnet/ed2k/torrent 例外），直接给准确提示、不进兜底链 | av 实测：站点下发 `Ksvideo-<hex>`（全工程无此协议），每次白耗 **6.1~6.3 秒**（起播→尝试→兜底降级→失败） | 预期每次 **~0.3 秒**出结论（首次尝试即刻判掉 + 静默重取一次），省约 6 秒/次 |

**闸门**：新增 `AA` 节 10 条断言，与原有 A~Z 节共 **235 条**全部通过（`check_l1box_regressions.sh`）。
**产物**：`FreeBox-src/L1Box_v1.1.1_release_20260915aw.apk`　60,864,120 B　MD5 `c71be0e96c16fc637a6c71e9e86809f1`；签名 v1/v2/v3 同一证书；dex 内已确认含 `needRetryLink` / `isPlayableUrl` / `isLoopbackUrl` / `站点返回的地址无法播放` / 新埋点阶段 `地址`。

### 本批的风险面（要在下一轮实测里确认，不藏）
- 出口统一后，**所有**失败都会留错误态（包括"嗅探错误""解析错误"）。核对过这三类发生时页面都没有正在播放的画面被遮挡，但只有真机能确认。
- 早判放行了迅雷那条专用通路（`magnet:` / `ed2k:` / `.torrent` 都不含 `://`），逻辑上不受影响，同样要真机确认一次。

## 6. 结论（一句话版）

- **可测的提升**：点播后"有明确结论"的比例 **68% → 95.3%**；"界面什么都不说"的比例 **32% → 4.7%**；失败留痕与归因 **0% → 100%**。
- **机制上的提升**：改前 8 条"会卡死 / 会白等 / 会播不出"的缺陷，逐条有代码证据地修掉了 5 条、本批又补了 3 条（可见性、代理变形、地址判据）。
- **没有提升的**：起播速度（基本持平，且不可直接比较）；源侧三类不可播（占了 av 全部 7 次失败）。
- **一次真实回退发生过**：第二批的 C1 Referer 污染，已定位、修复并加进闸门。此后 av/aw 未再出现任何"改前能播、改后播不了"的实例（av 的 11 次净化命中、18 次补 Referer 全部正常起播）。
