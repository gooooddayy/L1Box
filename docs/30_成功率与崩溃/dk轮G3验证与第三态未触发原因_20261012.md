### ⚠️ 唯一的残留（应用无权消除）

那 5 行 `E AndroidRuntime: FATAL EXCEPTION: Thread-N` **不是我们打的**，是 ART 的**前置处理器**（`RuntimeInit$LoggingHandler`）
在"应用处理器之前"统一输出的 —— 应用层没有任何合法手段抑制它。**能改的只有我们自己的那两行**（落盘 + `E App` 堆栈），而这两行确实已经没有了。

> 换句话说：**日志里仍会看到那一小段 FATAL 文本，但 `files/crashes/` 不再因此涨文件** —— 这正是 G3 要的效果。

## 二、⚠️ 但 G3 的另一半（第三态生效）**本次现场没有触发**

`加固 jar 自检未通过（…）⇒ 它自己跳过了初始化…` —— **0 次**。而自杀线程确实起了（3 次噪声分流为证）。
即：**"自检失败确实发生了"，但我们新加的第三态一次都没走到。**

### 根因：**`Init.init` 有第二处调用点，哨兵只装在其中一处**

```
grep -rn 'getMethod("init"' FreeBox-src/app/src/main/java/
  JarLoader.java:318          ← 普通分支：直接反射调 Init.init，success = true（无条件）
  ProtectedInitJar.java:471   ← 受控分支：invokeSelfInit（dk 在这里装了哨兵）
```

`JarLoader.loadClassLoader()` 的逻辑是：
```java
boolean family = isFamily(classLoader, jar, key);
if (family)  success = protectedInitJar.init(classInit, key);   // ← 有哨兵
else {                                                            // ← 没有哨兵
    classInit.getMethod("init", Context.class).invoke(null, bridged);
    success = true;                                               // ← 无条件认为成功
}
```

### 现场证据（17:22:25，可直接对上号）


**判据**：`ProtectedInitJar` 的三条出口（手绑成功／交还自身入口／初始化失败）**每一条都会打日志**；
17:22:25 那次**一条都没有** ⇒ 它根本没走受控路径 ⇒ **就是 `JarLoader:318` 那条普通分支**。

⇒ 也解释了为什么本次 **G1（不拒载）其实没被真正检验**：第三态没触发，`selfCheckBailed` 这个字段这一次全程为假。
G1 通过只能说明"**这次改动没有造成回归**"，**不能**证明第三态本身安全。这一点必须如实记下。

### 顺带两个事实

1. `JarLoader:318` 的普通分支**无条件 `success = true`**，且**不登记 `protectedJarKeys`** ——
   与 2026-09-14 ap 轮记录的"直接调 `Init.init` ⇒ 内部 killall 共享代理 ⇒ 原生 abort"**是同一个入口**。
2. 本次那份 jar 判据失败后，紧接着 17:22:26.644 出现 `SpiderLog: Failed to connect to /127.0.0.1:8964`
   ⇒ **它自己的初始化确实跳过了起代理**，与反汇编结论一致（`goto 0x00a1` 跳过 `startGoProxy`）。
   ⚠️ 但注意：这条分支下我们**本来也没有**把它记成代理持有者（因为不是受控路径）——
   ⇒ **"讹记代理持有者"的危害面，只在受控路径（家族 jar）上存在；普通路径的问题是另一件事**（无条件当成功 + 不登记）。

## 四、下一步（等用户决定，**本轮未动代码**）

要让第三态真正生效，需要把哨兵覆盖到 **`JarLoader:318`** 那条分支。两种做法：

| 方案 | 内容 | 代价 / 风险 |
|---|---|---|
| **甲（最小、只观测）** | 普通分支也取一次哨兵序号、事后比对，**只多打一条日志**（`该 jar 自检未通过，但它走的是普通分支`），**不动任何控制流** | 零风险；但"讹记"问题在普通分支上本来就不存在，所以收益≈把这类 jar 的规模量出来 |
| **乙（把普通分支也纳入受控路径）** | 一旦发现自检失败 ⇒ 改走 `protectedInitJar.init()` | 收益：可能顺带修掉 ap 轮那个"直呼会 killall 共享代理"的隐患；风险：改变现有分支走向，需要一轮完整回归（G1 必须重测），且本次那份 jar 就是普通分支、**当前它是可用的**，动它有回退风险 |

⚠️ 建议：**先走甲（观测一轮，量出这类 jar 到底有多少）**，再决定要不要走乙。
另：崩溃目录 `/data/data/…/files/crashes` 在 release 包上**读不到**（`run-as` 报 not debuggable），
所以"文件不再增加"最终要靠 App 内「崩溃日志」页面确认 —— 或下一版加一条落盘计数日志。
