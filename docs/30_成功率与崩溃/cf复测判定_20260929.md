### 【判定 2】A 项（`routeDo` 埋点）——**埋点是"诚实的"，但语义表述仍有坑**

**ce 轮的错误**：`route = (key != null && key.equals(recentJarKey)) ? "recent" : "do"` —— 用 `key`（已经路由后的结果）去和 `recentJarKey` 比，而 `getSpider()` 刚跑完，两者天然相等 ⇒ **恒为 `recent`**，是纯埋点 bug。

**cf 的改法**：先算 `mapped = siteJarKeys.get(doKey)`，再 `routeDo = mapped != null && !mapped.isEmpty()` ⇒ **直接问"映射表里到底有没有这个 do"，不再绕道比较结果**。

**本轮数据**：`路由=recent(回退)` **13/13 次**。逐条核对：

- `do=<站点E>`（11 次）：**`siteJarKeys` 里确实没有 `<站点E>`** ⇒ 回退到 `recentJarKey` 是**真实行为**，标签说的是实话 ✅
- `do=ck`（2 次）：`<站点E>`/`ck` 这类站点是否注册进 `siteJarKeys` 取决于该站点用的 jar 是否走 `getSpider`。本轮 `do=ck` 却拿到了 **`返回=200`**，且 `key` 分别是 `0b9565d6a6`（有手绑账本）和 `ae48218142`（账本=`无`）—— **同一个 `do=ck` 被路由到了两个不同的 jar**，说明 `siteJarKeys` 在这里也没命中，两次都是 `recentJarKey` 碰运气，**恰好碰对了**。

⇒ **判定：`路由=` 标签现在是诚实的**（说的是真话），**但"13 次 do 一次都没命中映射表"这个事实本身才是真问题**：`siteJarKeys` 在这套配置下**几乎是空的**。

**这可能有两种解释，本轮数据无法区分**：

2. `siteJarKeys` 的写入时机/键名（`params.get("do")` 的取值格式）与实际调用时的 `do` 对不上。

⚠️ **这一条判不出，需要下一轮在日志里补一个"`siteJarKeys` 规模/内容"的探针**（例如打印 `size` 或首次写入时的 key）才能定性。
