## 二、测试任务（按顺序做，共 4 段）

### 第 1 段 —— 冷启首搜（最重要）

1. 把 App **从后台完全划掉**（不是返回，是划掉，让进程真正死掉）
2. 打开 App → 等首页出来
3. 进 **搜索** → 输入**固定关键词** → 搜
4. 心里数两个数（估个大概就行）：
   - **T1**＝按下搜索 → **看到第一条结果**，大约几秒
   - **T2**＝按下搜索 → **结果不再变化（刷完）**，大约几秒
5. 不做别的，**回到这里跟我说一句"第1段好了"**（我打标记，顺便先看一眼日志对不对）

> 这一轮日志里应该出现：`搜索轮次：可搜站点=N`、`搜索首条结果：耗时=…ms`、`搜索耗时：收尾 …DNS(窗口内)…`

### 第 2 段 —— 同会话再搜一次（热态）

1. **不要退出 App**（这一步关键，要的是"spider 已经在内存里"的状态）
2. 返回搜索页，**再搜同一个关键词**
3. 同样估 T1 / T2
4. 跟我说"第2段好了"

> 预期：第 2 段明显快于第 1 段。**两段之差就是"冷启成本"**，也就是那段 ≈10 秒的 jar 装载。

### 第 3 段 —— DNS A/B（这一段的结论直接回答"是不是 DNS 的锅"）

⚠️ **规则：冷启必须对冷启。** 不能拿"冷启+DoH关"去比"热态+DoH开"，那样比出来的是 jar 冷热差异，不是 DNS。

1. 进 **设置** → 找到**安全DNS** → **关掉**（显示应为"关闭"）
2. 把 App **划掉** → 重新打开 → 冷启 → 搜**同一个关键词** → 估 T1 / T2
3. 回 **设置** → **安全DNS 重新打开**（显示应为"腾讯"）
4. App **划掉** → 重新打开 → 冷启 → 搜**同一个关键词** → 估 T1 / T2
5. 跟我说"第3段好了"

> ⚠️ 第 3 段**故意多花你几秒**：安全DNS 开关是**实时生效**的，所以这一段不用等任何东西就能做。
> 判读：**关 ≈ 开 ⇒ 与 DNS 无关**；**关 明显快 ⇒ DoH 在你的网络上是负担**，我按这个方向改。

### 第 4 段 —— 播放回归（确认 bn 的 `safeDns` 收口没弄坏取链）

1. 回首页 → 随便点开一个片子 → **播放**（起播快不快）
2. **拖一下进度**（看会不会卡住/重新缓冲）
3. 跟我说"第4段好了，可以收了"

> 为什么必测：bn 动了 `Spider.safeDns()`（jar 走的就是这条 DNS 入口）。**搜索能搜到 ≠ 取链能取到**，必须单独点一次播。

**最好**直接跟我说"好了"，我读日志里这三行给你精确数字（体感容易高估）：

```
搜索首条结果：耗时=XXXXms 站点=N 关键词=…
搜索耗时：<收尾> 站点=N 命中=M 首条=XXXXms 总耗时=XXXXms 本轮装载增量=K DNS(窗口内):DoH命中=N 失败=N 熔断跳过=N 直连=N
搜索轮次：可搜站点=N 站点池定论=…
```

`DNS(窗口内)` 那一串是新的，**它一回话，'DNS 到底参没参与、参与了几次'就再也不是猜了**：
- `DoH命中` 高、`失败=0` ⇒ DoH 在正常工作，且走的是缓存
- `失败` 高 / `熔断跳过` 高 ⇒ DoH 在拖后腿，这就是你要的证据
- 全是 `直连` ⇒ 根本没走 DoH

## 附：这一批埋点分别对应"哪个嫌疑"

| 日志行 | 回答的问题 |
|---|---|
| `本轮装载增量=K` | 这一轮**新创建了多少个 spider**（含 jar 下载）⇒ jar 重下占了多少 |
| `搜索首条结果：耗时` | **真正的用户体感**（第一条出来要多久） |
| `搜索耗时：…总耗时` | 整轮到底跑了多久、有没有**整轮重搜** |
| `DNS(窗口内)` | DNS 有没有参与、DoH 成功/失败/熔断/直连各几次 |
| `搜索轮次：可搜站点=N` | 站点池对不对（换源串源也会在这里露） |
| `加固 jar 手绑成功` / `JarKillNeutralizer` | 加固 jar 装载是否在关键时间窗里 |
