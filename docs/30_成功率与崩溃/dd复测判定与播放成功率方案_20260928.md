## 二、失败分三类，逐条排除

### A 类：`127.0.0.1:9978/proxy` —— **我们自己的本地代理拒了它**（唯一"我们能救"的一类）

**证据链（全部来自日志/代码，无推测）**

1. 站点下发的是**本地代理形式**地址（原版 TVBox 的 `do=<站点key>` 代理），由**我们自己的** RemoteServer(9978) 的 `/proxy` 路由处理。
2. 蜘蛛确实找到了我们的服务器：`SpiderLog: Found local server port 9978`。
3. 蜘蛛只在**构造**该地址时打过日志（`<站点B>播放代理 ckLen=84, url=…`，3 次＝3 次播放尝试），时间戳 19:50:10.**325** **早于** `净化 开始` 19:50:10.**333** ⇒ 这条日志来自 `playerContent`，**不是** `localProxy`。
   ⇒ **jar 的 `localProxy` 从头到尾没被调用过。**
4. 我们自己的预取 **7 ms 就失败**（若是真的去访问上游，往返至少几十毫秒）⇒ **瞬时拒绝**。
5. 代码路径：`RemoteServer./proxy` → `ApiConfig.proxyLocal` → `JarLoader.proxyInvoke`。而 `proxyInvoke` 开头有三道"事前拒绝"门禁，命中即 `return proxyNotReady()` ＝ **HTTP 503**（`Exo 2004`＝非 2xx、OkGo `HttpException` 完全吻合）。
6. 其中一道是：`protectedJarKeys.contains(key) && !key.equals(proxyHolderKey())` → 503。
   本轮进程里**有两个加固 jar**：
   - `8ad2ef8d7eeffb609891efb759086509` 19:48:19 **接管**本地代理（＝holder）
   - `0b9565d6a6b5ecd989a7de9e1d50677e` 19:48:26 **手绑成功**（承接已有代理，**不是** holder）
   而 `key` 取的是 `recentJarKey`（＝最近一次取蜘蛛所用的 jar）。
   ⇒ **只要最近用的是那个"手绑"的 jar，它的 `/proxy` 一律 503。**
7. **"手绑成功"本身就证明这个 jar 的原生代理可用**（它的 `getLoader` 成功连上了正在跑的代理）；但 `occupyProxy()` 只在"jar 自己重启代理"时才调用 ⇒ 手绑的 jar **永远进不了 holder 名单** ⇒ 被永久挡死。

**对照上游原版**（`git show f834e74`）：原版 `proxyInvoke` 没有任何门禁，只按 `proxyMethods.get(recentJarKey)` 直接调用。
⇒ **门禁是本 fork 为防原生 SIGABRT 后加的，副作用是把手绑 jar 的 /proxy 全挡了。**

**跨轮次复核**：`/proxy` 这条路在 **cb(18:16)、cc(19:17)、dd(19:50) 三轮实测中从未成功过一次**（每次都停在同一处）。

### B 类：`<源站地址>/hls/…?token=…` —— 远端真的拒绝，但**我们看不见状态码**

- 地址是 IP + 非标准端口，`token` 每次重取都变（说明源侧在换发令牌），但**两个内核与我们的预取全部拿到非 2xx**。
- 预取耗时 66~108 ms ⇒ **是真实的网络往返**，不是被本地组件挡掉。
- **逐条排除**：
  | 假设 | 判定 | 依据 |
  |---|---|---|
  | DNS 被拦 | ❌ | 同轮 `DoH命中=4 失败=0 直连=6`；且地址是 IP 字面量，本就不需要解析 |
  | m3u8 重写坏了 | ❌ | 这两次净化**没走到重写**（预取就失败了） |
  | 解码/编码不支持 | ❌ | Exo 报的是 **2xxx（HTTP 类）**；解码是 3xxx/4xxx |
  | 内核差异 | ❌ | Exo 2004 与 Ijk -10000 **双双失败** |
  | 设备解码器/隧道 | ❌ | 同机同内核另一条源 632 ms 就绪 |
  | 地址过期 | ⚠️ 待定 | 重取 2 次拿到的是**同一个地址**，无法据此排除 |
  | 防盗链（403）/ 路径失效（404） | ⚠️ **待定 —— 状态码被我们丢掉了** | `purifyFailKind()` 只打异常类名 `HttpException`，没打 `.code()` |
- **结论：这一类的修法必须先拿到 HTTP 状态码**。403 ⇒ 补请求头/Referer/UA；404 ⇒ 重取无意义、应更早收手；5xx ⇒ 源站问题。**现在三种可能混在一个字符串里，任何"定向优化"都是猜。**

### C 类：`YYNB-<32位hex>` —— 非 URL 的令牌串，需要二次解析

- Exo 把它当**本地文件**找：`FileNotFoundException: YYNB-aac3ccf…: open failed: ENOENT`；Ijk `-10000`。
- cb 那轮同一站点下发的也是同类串（`YYNB-2ad7b8b4…`）⇒ **该站点的地址形态本来就如此**。
- 这类**只有解析/嗅探通道能救**：项目本就带 `initParse` / 默认解析接口 / `parse:` `json:` 前缀 / 嗅探机制，但
  ①这两部片 `parse≠1` 且站点未配解析对 ②**你的播放器里没有配任何解析接口** ⇒ 目前必然失败。

## 三、图片：你"没法判断哪个图该出不该出"是真的 —— **我上轮加的度量坏了**

本轮埋点：`图片加载：成功=6 失败=0 成功率=100.0%` / `图片队列：取出=6 取消=0 在途=0` / `图片发起：发起=6 空地址=0`，最后一行 `可见图片：未体检`。

| 现象 | 判定 |
|---|---|
| `可见图片：未体检` | **是我上轮新加的"可见图片体检"没生效**，两个叠加 bug：①它用 `visibleRange()` 取可见范围，而那个函数**写死在 `mGridView` 上** —— 过滤/点站点模式下列表是 GONE ⇒ 返回 null ⇒ 直接 `return`，永远不体检；②**结论只在"搜索收尾"那一刻打印**，而你滑列表是在收尾之后 ⇒ 永远打不到这个数 |
| `发起=6`（命中 522 条） | 符合当前设计：**绑定即请求**，只有当屏可见的那几个 item 会去请求；其余 500 多张滑到才请求。这也是为什么"你看不出该出几张" |
| 图片加载快了 / 分站点正常 | ✅ 与你的体感一致，cc 的误判门闸确实已修好 |

⇒ 缺的不是图片功能，而是**一个能看懂的实时数字**。

## 五、方案

### P1（本轮建议做，全部低风险）

| # | 项 | 做法 | 预期 |
|---|---|---|---|
| **P1-1** | **修 `/proxy`（A 类）** | ①把**手绑成功的 jar** 纳入"可代理"范围，但**带世代校验**：记录"绑定时的 holder + 世代号"，只有与当前一致才放行（防持有者换届后打到已被 killall 的旧原生对象 —— 这正是当初加门禁要防的 SIGABRT）；②保留 `nativeInitInProgress` 全进程门禁与 ClassLoader 终审；③`RemoteServer./proxy` 对 `rs == null` 做空安全（不再 NPE→500） | A 类从 **100% 失败** 变为可播（jar 侧 upstream 若本身可用即成功） |
| **P1-2** | **净化失败带状态码**（纯日志） | `purifyFailKind` 从 `HttpException` 取 `.code()`，超时/连接失败按异常类型区分 ⇒ 打 `远端地址/Http403`、`远端地址/超时`、`本地代理地址/Http503` | 下一轮给 **B 类定刀**（403/404/5xx 三种修法完全不同，现在无法区分） |
| **P1-3** | **`/proxy` 全程日志** | 每次请求打一行：`do=` / `recentJarKey` / holder / 门禁判定 / 返回码 / 耗时 | 一句话确认 P1-1 是否真的修好，不用再猜 |
| **P1-4** | **修我自己的图片度量** | ①可见范围按**当前活跃列表**取（过滤模式用过滤列表，与已修的 `cancelOutOfWindowImages` 同一套）②体检结论**每次体检完就打一行**（不再只挂收尾），与 `图片发起/可见图片` 合成一行"图片实况" | 你就能**直接看到数字**："当前屏 6 张，已加载 4 / 未加载 2" |
| **P1-5** | 归因文字修正 | Exo `2xxx` 归"网络/HTTP"（已对）、`3xxx` 归"解析/容器"、`4xxx` 归"解码"（`classify` 已按此，本轮日志确认生效） | 纯日志 |

### P2（需要你拍板）

| # | 项 | 问题 |
|---|---|---|
| **P2-1** | **C 类令牌地址（`YYNB-…`）** | 要不要配一个**解析/嗅探接口**？配了这类源能救回来（走项目原有的 `initParse` 通道）；不配就永远失败。**这不是判错，是补一条正确的加载路径。** |
