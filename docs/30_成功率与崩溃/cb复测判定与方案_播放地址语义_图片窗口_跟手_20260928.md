## 一、播放失败：根因是「地址语义」，不是网络/解码/DNS

**日志证据（完整链路，同一部片每次都是同样的地址）**

| 站点 | 站点下发的"直链" | 播放器反应 |
|---|---|---|
| 华谊 | `YYNB-2ad7b8b41a766a4f5c49af1eb6d58848`（**不是 URL**） | 被我们自己的闸门判掉：`播放失败：地址 reason=站点下发的地址不是 URL（不含 ://），跳过播放器与兜底链` ×6 |
| 天堂 | `https://www.iqiyi.com/v_19rrdoa488.html`（**是网页**） | `code=Exo:3002`（清单解析失败）→ 变形 → `Exo:3003`（容器不支持）→ 降级 IJK → `Ijk:-10000/0` → 重取 ×2 仍同一地址 → 失败 |
| 苹果 | `https://www.iqiyi.com/v_19rrdoa488.html`（同上） | 同上（Exo 3002 → Ijk -10000） |

对照：**同一轮里能正常播的都是真媒体直链** —— 例：`18:13:11 站点=WexAiGuaZi url=…/index.m3u8 → 起播已就绪，耗时 734ms 内核=Exo`。

**结论：站点把"需要二次解析的地址"当直链下发，我们的播放链把它当媒体地址直接丢给内核。**

### 可能原因逐条排除（你要的"排除一遍"）

| 可能原因 | 判定 | 依据 |
|---|---|---|
| DNS / 域名解析被拦 | ❌ **排除** | `DoH命中=6~71 失败=0~4`；且 DNS 失败会走 Exo `2001` |
| 网络层（403/404/超时） | ❌ **排除** | 全程**没有出现 Exo 2xxx（IO 类）**；403/404 会报 `2004`。站点请求是**成功**的（18:14:44.064 就拿到了地址） |
| Referer / UA 被拒 | ❌ **排除** | 日志有 `请求头 补同源 Referer=https://www.iqiyi.com/`；且被拒会表现为 2004 |
| 编码/解码不支持 | ❌ **排除** | 解码类错误码是 **4xxx**；本次全是 **3xxx（解析）** |
| 设备解码器 / 隧道模式 | ❌ **排除** | 同设备同内核 734ms 就播好了另一条源（`c2.qti.avc.decoder` 工作正常） |
| 我们的 m3u8 重写/净化改坏清单 | ❌ **排除** | 这两次失败**根本没走到净化**（日志无 `净化 开始`），且地址是 .html/非 URL |
| 播放器内核版本差异 | ❌ **排除** | Exo 与 IJK **双双失败**，且都表示"打不开内容" |
| 兜底链本身有问题 | ⚠️ **部分成立（是放大器）** | 同一地址、同类失败下，"变形 http↔https → 降级内核 → 重取×2"**全部无效**，却耗掉 **每次约 5.4~6 秒**（天堂 ep0：18:14:43.4→49.4；ep1：54.0→59.6；苹果：18:15:05.3→10.7，三段合计 26 秒）；华谊那类更冤：地址一次都没变过，仍**重取 2 次耗 4.2 秒** |
| **地址语义：站点给的是"待解析"地址** | ✅ **成立（根因）** | 华谊=`YYNB-<32hex>` 令牌串；天堂/苹果=`iqiyi.com/v_xxx.html` 网页 |

### 另一个自身缺陷（本次新发现）

`isPlayableUrl()`（`PlayFragment:1544`）只认"含 `://`"——**这是我自己之前加的闸门**（为避免 `Ksvideo-<hex>` 空转 12 秒）。
它把"站点下发令牌串"这一整类**直接判死**，而不是**送去解析**；对天堂/苹果这类"是 URL 但是网页"的它又放行了，于是每次**空转 5.4~6 秒**（三段合计 26 秒）。
→ 判据需要从"含不含 `://`"升级为"**像不像媒体直链** + **不像就走解析**"。

### 项目里其实有解析通道（只是没被触发）

`PlayFragment:2407 initParse(flag, useParse, playUrl, url)` + `ApiConfig.getDefaultParse()/getParseBeanList()`：
- `parse=1`（默认）或 `jx=1` → 走解析；`json:`/`parse:<名字>` 前缀也有专路；
- 本次这两部片的播放信息里 `parse` 不是 1、也没有 `jx` → 走"直连"分支 → 直接把令牌/网页丢给内核。
- 另有 **嗅探** 通道（本轮 `嗅探` 埋点 0 行 = 从未触发）。

## 二、图片：点特定站点不加载 ＝ 我上一版"可见优先"的实现缺陷

**证据（5 轮图片队列账）**

| 轮次 | 取出 | 跳过 | 窗口 | 成功 | 说明 |
|---|---|---|---|---|---|
| 18:03 | 6 | 0 | 9 | 5 | 正常 |
| 18:06 | 64 | 26 | 11 | 29 | 跳过 29% |
| 18:07 | 6 | 0 | 9 | 5 | 正常 |
| **18:10** | **16** | **15** | **9** | **1** | 跳过 **94%** ← 明显异常 |
| 18:14 | 24 | 6 | 12 | 18 | 跳过 25% |

而命中是 266~522 条结果（该有几百张图）→ **"取出"总数只有 6~64**，说明**绝大多数图片请求根本没发起**（被 gate 挡在 bind 里），不是"跳过"造成的。三个缺陷：

| # | 缺陷 | 机制 |
|---|---|---|
| 1 | **gate 用 position 判定，downloader 用 URL 判定** —— 两套判据不一致 | `FastSearchAdapter` 的 gate 传 `getLayoutPosition()`（绑定过程中可能返回 `-1`/过期位置）→ 误挡；而下载线程按 URL 判窗口 → 又挡一次。窗口只有 9 个 URL 时，两边都容易错 |
| 2 | **过滤模式（点左侧站点）时窗口来源错了** | 过滤模式显示的是 `mGridViewFilter` + `searchAdapterFilter`，而 `refreshImageWindow()` 读的是 **`mGridView`**（此时 GONE → `findFirstVisibleItemPosition()` 返回 `NO_POSITION` → **窗口永不更新**，仍是上一次的旧集合）→ 该站点的图 URL 全不在旧窗口里 ⇒ **一张都不加载**（就是你的现象）；且 `searchAdapterFilter` **没设 gate**、`mGridViewFilter` **没挂滚动监听**、也没有停稳补刷 |
| 3 | **窗口更新时机不全** | 只在"滚动/落地/停稳"更新；**切换站点（filterResult）/进入过滤模式时没有更新** |

## 四、方案（待确认）

### P1-1 播放失败：按"地址语义"分流（核心）
| # | 改动 | 效果 |
|---|---|---|
| A1 | **新增地址形态判定**（替代现在的"含不含 `://`"）：<br>· 像媒体直链（`.m3u8/.mp4/.flv/.ts/.mkv/.mpd/.avi/.mov/.m4a/.mp3`，或路径带这些）→ 直连播<br>· **URL 但是网页**（`.html/.htm/.php/.asp/.jsp`，或 `iqiyi/youku/qq/mgtv/bilibili` 等站的播放页）→ **走解析通道**<br>· **不是 URL**（`YYNB-<hex>` 这类令牌/编码串）→ **也走解析通道** | 把"必然失败"变成"有机会成功" |
| A2 | 走解析时：优先**默认解析接口**（`getDefaultParse()`），无则用 `ParseBean(type=0)`；**若一个解析接口都没配** → 直接给明确文案「**该源地址需解析，请在设置里配置解析接口**」，**不进兜底链** | 不再空转 26 秒 |
| A3 | **兜底链按失败类短路**：解析类失败（Exo `3xxx` / Ijk `-10000` 且地址非媒体）**跳过"变形/降级/重取"**，直接提示 | 单次失败从 ~26 秒降到 ~2 秒 |
| A4 | **归因修正**：`PlayErrCode.classify()` 把 Exo **3xxx 归"解析/容器"**（现在错归"解码"）、Ijk `-10000` 归"内容无法打开" | 日志/账本可用于二期定刀 |
| A5 | 埋点补：地址形态类别（`媒体/网页/令牌`）+ 实际交给谁（直连/解析/拒绝） | 下一轮能直接看构成 |

### P1-2 图片：把"可见优先"做对（不推翻机制，只修实现）
| # | 改动 |
|---|---|
| B1 | **判据统一到 URL**：adapter 绑定前直接算该 item 的规范化 URL，用 `L1ImageDemand.needed(url)` 判定（与下载线程**同一个函数**），彻底去掉 position 判据 |
| B2 | **窗口来源＝当前活跃列表**：过滤模式下用 `mGridViewFilter` + `searchAdapterFilter` 的数据；一张图都看不到时**不挡**（保守放行） |
| B3 | **切换站点（filterResult）/进入过滤模式时立即刷新窗口**；`mGridViewFilter` 也挂滚动监听 + 停稳补刷；`searchAdapterFilter` 也设 gate |
| B4 | 收尾账本加：`窗口来源=主列表/过滤` 与 `被挡=N`，便于验证 |

### P1-3 跟手：先量准，再优化
