# 订阅源解析 第二批：内容层增强 + 安全DNS 回退（2026-09-19 · 产物 `bm`）

> 上一批（`bl`）修的是**地址层 + 结果层**的确定性缺陷（漏写协议头、`;pk;` 越界、裸 base64、
> 切源残留旧线路）。本批按方案文档的顺序做 **A 档 7 项 + B1+B2**，重点是**内容层**与**DNS 层**。

拍板原话：**"可以，按你说的先做 A 档 7 项 + B1+B2"**。

## 一、本批范围与落点

| 项 | 解决什么 | 落点 |
|---|---|---|
| **A1** | 源站把配置改坏时，本地有缓存却被直接报错 | `ApiConfig.useCacheFallback()` + 两条调用路径 |

## 二、开工前摸出来的两个事实（决定了 B1 的真实内容）

方案里 B1 写的是"DoH 失败自动回退系统 DNS"。真去读内嵌实现后发现**回退其实已经存在**，
但旁边还有两个更致命的坑 —— 也就是说 **B1 的价值不在"补回退"，而在"堵这两个坑"**。

### 事实 1：内嵌 DoH 对**私有地址**是直接抛异常，且**不回退**（致命）

```java
// DnsOverHttps.java
static boolean isPrivateHost(String host) {
    return PublicSuffixDatabase.get().getEffectiveTldPlusOne(host) == null;   // 没有有效 TLD+1 就算 private
}
// Builder 默认：resolvePrivateAddresses = false
if (privateHost && !resolvePrivateAddresses) throw new UnknownHostException("private hosts not resolved");
```

`127.0.0.1`、`192.168.x.x`、`localhost` 全部命中 private ⇒ **直接抛异常**。
而本 App 的核心链路恰好全在 `127.0.0.1` 上：

- 净化路由 `/l1.m3u8`（去广告后的清单）
- 网盘代理 `/proxy`
- 首页路由 `/l1home`

⇒ 若只是"把默认值改成开启"，打开的瞬间**这些请求会全部解析失败**，表现为
「开了安全DNS 之后播放就不行了」，而且是**必现**，跟机型无关。

### 事实 2：DoH 查询失败时它自己会静默回退系统 DNS

```java
if (!results.isEmpty()) return results;
return Dns.SYSTEM.lookup(hostname);        // ← 回退已存在
// return throwBestFailure(hostname, failures);
```

回退本身是对的，但**外部完全无法感知失败**：外层既不能计数、也不能熔断，
DoH 被阻断时**每个未命中的域名都要白等一次 HTTP 超时**（客户端默认 10 秒），请求一多就是全局变慢。

**本批的处理**：把失败如实抛出，回退职责上移到 `L1FallbackDns` —— 对请求层行为不变
（照样回退系统 DNS），但失败可见、可计数、可熔断。前提是**所有 `builder.dns(...)` 注入点
都换成回退层**，这一点由闸门的 `mustnot 'dns(dnsOverHttps)'` 守住。

## 三、逐项改动

### A1 缓存回退 —— 坏内容不许覆盖好缓存

关键顺序（**改造前就是这样，本批显式写进注释**）：`parseJson` 先成功、再写缓存。
所以源站把内容改坏时，坏内容不会覆盖掉本地那份好缓存 —— 那份缓存正是回退的依托。

- 新增 `ApiConfig.useCacheFallback(apiUrl, cache, activity, tip)`；
- 两条调用路径：**内容坏了**（`onSuccess` 的 catch）与**网络重试用尽**（`onError` 末尾，原来是内联代码，改为一处实现）；
- 缓存文件名是 `MD5(完整地址)` ⇒ **换源天然对不上**，不存在"用上一个源的配置"；
- 缓存自身也坏掉时只返回 false，**不删文件**（不可逆动作，且它只有几 KB）。

`ApiConfig.java` 里 `useCacheFallback` 出现 3 次：1 个实现 + 2 个调用（闸门按 3 计数）。

### A2 顶层数组

`[{...}]` 用"首个 `{` 到末个 `}`"切出来是 `{...},{...}` —— 不是合法 JSON，
但它含订阅特征字段，于是会一路带到 Gson 才炸，报出来还是笼统的"解析配置失败"。

- 新增 `startsWithArray()`：跳过前导空白后以 `[` 开头即认定为数组形态，**只走数组分支**；
- `pickFromArray()`：括号配对 + 字符串感知扫描，取第一个含订阅特征字段的对象；
- 数组里没有订阅对象 ⇒ 返回 `null`（不误认），不会退回"半截合法"的中间产物。

### A3 宽松清洗 + 结果守门

- `cleanJson()`：删块注释 `/* */` 与尾逗号（`[1,2,]`、`{...,}`）。**字符串感知** ——
  站点名/地址里带 `//` 或逗号是常态，全局替换会把内容改坏。
- `looksParsable()`（新增守门，见第四节）：括号平衡 + 字符串闭合 + 字符串外无注释残留。

### A4 base64 + gzip/zlib

`decodeBase64()` 解出的字节先过 `maybeInflate()`：

- 只按**魔数**识别（`0x1f8b` = gzip，`0x78` 开头 = zlib），识别不出原样返回 —— 绝不盲目试解压；
- gzip 走 `GZIPInputStream`（gzip 有独立 10 字节头 + 8 字节尾，deflate 的 `Inflater` 解不了）；
- **输出上限 4MB**：解出多少由入参决定，不设限就有被构造包吃光内存的风险；超限直接放弃。

### A5 请求头统一

`L1SubHeaders`（纯 Java、零 Android 依赖、有桌面用例）持有 UA / Accept / Accept-Language /
Cache-Control 常量与 `referer(url)`（取源站根地址，丢弃路径与查询 —— 路径里常带 token，透传既无必要也多余）；
`OkGoHelper.subHeaders(url)` 做"塞进 OkGo 头表"的胶水。三处调用（启用拉配置 / 添加订阅 / 编辑后重新识别）
统一成一行 `.headers(OkGoHelper.subHeaders(地址))`。

> `Subscription` 里原来的 `SUB_UA` 常量已删除（闸门里锁死该写法的那条断言同步改写）。

### A6 准确结论

`L1SubContent.diagTip()` 给出面向用户的短结论：`地址没有返回内容` / `返回的是网页，不是订阅配置` /
`返回的内容不是订阅配置`。落点：

| 位置 | 文案 |
|---|---|
| `ApiConfig` 内容坏了且无缓存 | `订阅内容异常：<结论>` |
| `ApiConfig` 网络失败（重试用尽） | `订阅拉取失败，请检查网络`（异常原文进日志，不塞进提示） |
| `SubscriptionActivity` 添加/编辑失败 | `订阅失败：<结论>`；**拿不到响应内容时**才退回"请检查地址或网络状态" |
| `HomeFragment` | 直接显示 ApiConfig 给的结论（用 `showLong`，结论比"更新失败"长） |

> 新文案三条已进 `ToastSweeper` 白名单（`isHostToast` 是**允许列表**，不在里面的会被当 jar 弹窗移除）：`订阅内容异常`、`订阅拉取失败`、`订阅里没有可用站点`。

### A7 "0 站点"不再算成功

站点池为空在各层都是**正常返回**（装载确实完成了），边界上分不出"装完了但确实是空"与"本来就没内容"。
处理：`ApiConfig` 在**所有出口共用的** `parseJsonInternal` 末尾记下 `lastSiteCount`，
首页在 `success` 里读它 —— 为 0 时提示一次「订阅里没有可用站点，请检查源地址」。

- 同一份配置只提示一次（`mNoSiteWarned`），**切线路会重新武装**（新线路若也是空的，同样要说清楚）；
- 不改变回调语义（仍算成功，不阻塞首页渲染），只补上"说清楚"。

### B1 安全DNS 回退层

```java
// L1FallbackDns.lookup()
if (doh == null || doh.url() == null || L1DnsPolicy.directHost(hostname)) return Dns.SYSTEM.lookup(hostname);
if (policy.cooling(now)) return Dns.SYSTEM.lookup(hostname);
try { r = doh.lookup(hostname); if (非空) { policy.onOk(); return r; } } catch (Throwable ignored) {}
policy.onFail(now); return Dns.SYSTEM.lookup(hostname);
```

- `L1DnsPolicy.directHost()`：**IP 字面量**（IPv4/IPv6，含方括号形态）、**单段名**（`localhost`）、
  `.local/.lan/.internal/.home/.localdomain` ⇒ 一律直接系统解析，**一次 DoH 都不发**。
  对 IP 字面量做 DNS 查询本身也没有意义；
- **熔断**：连续 3 次失败 → 冷却 5 分钟（冷却期内直接系统解析，过冷却期放一次探测）；成功一次即清零；
- **超时收紧**：DoH 客户端 connect/read/write 各 **2 秒**（原来走 10 秒默认值）。
  超时不收紧，回退与熔断都来不及生效，整体就会变慢；
- `DnsOverHttps` 的失败改为如实抛 `UnknownHostException`（回退上移，见第二节事实 2）。

`L1DnsPolicy`（纯逻辑，零 okhttp/Android 依赖）+ `L1FallbackDns`（薄壳，只做胶水）的分层，
是为了让判断与熔断能在**桌面用例表**里全部验证，薄壳只剩 5 行调用。

### B2 默认开启 + 一次性迁移

- `OkGoHelper.DEFAULT_DOH = 1`（腾讯）作为**唯一默认值来源**，`App` 与给它的默认值都引用它；
- 老用户 Hawk 里存的还是旧的 `0`，改 `putDefault` 对他们**无效** ⇒ 新增 `upgradeDohDefault()` 显式抬一次；
- **只执行一次**（`DOH_UPGRADED` 标记），用户之后主动关掉不会再被改回去；
- 用户在设置页选过就留痕（`DOH_USER_SET`）—— 从此任何默认值调整都不再干涉他的选择。

> 说明：本次迁移对"曾经主动关过"的老用户同样生效（旧版本没记过 `DOH_USER_SET`，无法区分）。
> 敢这样做的前提是 B1 已经把"打开会让本地链路全挂"这个坑堵死（本地/私有地址现在根本不走 DoH）。

## 四、用例表抓出来的一个新问题：「行注释」清洗会把正文吃光

A3 最初实现支持 `//` 行注释（删到行尾）。用例表立刻报红：输入
`{\n// 说明\n"sites":[...]\n}` 得到的结果是**孤零零一个 `{`**。

根因：**`L1SubUrl.stripInvisible()` 会删掉所有不可见字符，包括换行**。
进到 `cleanJson` 时字符串已经是 `{//说明"sites":[...]}` —— 注释与正文**粘死、无法界定边界**，
"删到行尾"在没有换行可找时一路删到字符串末尾，把整份配置吃光。

两条修复（都已落地）：

1. **删掉行注释处理**（保留块注释：`/* */` 自带结束标记，删得安全）。理由写进代码注释，
   避免后人"好心加回来"；
2. **新增结果守门 `looksParsable()`**：括号平衡 + 字符串闭合 + 字符串外无 `//` `/*` 残留。
   半截产物（`{`）从此不会被当结果返回 —— 这类产物一旦返回，会一路带到 Gson 才炸，
   报出来还是笼统的"解析配置失败"，**比我方判失败更差**。

> 这是"用例表先于真机"价值的直接体现：这个 bug 在真机上会表现为"某个源以前能用，现在解析失败"，
> 极难定位；在用例表里是**一秒钟报红**。

## 七、口径与风险（不粉饰）

1. **A 档 7 项不是"普遍提高成功率"**，而是把"遇到就必败"的那几类变成可用。
   真实幅度完全取决于手上的源有多不规范：规矩的 JSON 源两版几乎没差别。
2. **本批最大的价值是 B1**：它把"安全DNS 可以默认开着"变成事实。
   在这之前，默认开启是**有害**的（本地链路全挂），所以旧版本只能默认关闭 ——
   代价是"DNS 被污染"的那整类源在默认状态下完全没有可用性。
3. **仍然救不了的两类**（与本批无关，继续保持）：
   - 源站自己就没那几集数据（取链空返回）；
   - SNI 阻断（如用户那台 nxog：DoH 能拿到正确 IP，但 TLS 握手仍被 RST）。
4. **默认开启 DoH 的代价**：极少数环境（运营商劫持恰好"可用"、DoH 服务器不通）下可能变差。
   用户随时可在设置 → 安全DNS 选"关闭"，且本次选择会被永久尊重（`DOH_USER_SET`）。
5. **没有做的**：自检面板（用户已否）、B3 网络恢复自动重拉、B4 https 双向回退、B5 多仓字段宽松识别、B6 UA 切换重试 ——
   按方案留在后续批次，需要时再单独开。
