已定位 **8 个短板**，其中 **S1 `loadConfig` 拼出空地址 `http://`** 与 **S2 `;pk;` 结尾数组越界**（潜在 FATAL）是确定性缺陷。

**第一批（`bl`）**：P0（解析层净化）+ P1（网络层对齐/多仓宽松收集/GBK 兜底）**全做**，自检面板（P2）**不做**；

容错逻辑做成**零 Android 依赖的纯 Java 类**（`L1SubUrl`/`L1SubContent`）⇒ 宿主机 JVM 跑用例表，不依赖真机。
产物 `bl.apk` 60,884,656 B / MD5 `e04ff49fc4980c82819088da787a2926`。

**第二批（`bm`，本批）**：A 档 7 项（**缓存回退** / 顶层数组 / 块注释与尾逗号清洗 / base64+gzip / **请求头补齐** / **准确失败结论** / **0 站点提示**）
＋ **B1+B2（安全DNS 回退与默认开启）**。
**本批最关键的发现**：内嵌 DoH 对**私有地址直接抛异常且不回退**（`127.0.0.1`、`192.168.x.x`、`localhost` 全命中
⇒ 默认开启会让净化 `/l1.m3u8`、网盘 `/proxy`、首页 `/l1home` **全部解析失败**），
且 DoH 失败原本是**静默回退**系统 DNS（⇒ 外层无从感知失败、**无法熔断**，每个未命中域名都要白等一次 10 秒超时）。
所以 B1 的真实内容不是"补回退"（回退本来就有），而是**堵这两个坑**：私有/IP 字面量前置绕开 DoH ＋ 失败如实抛出以支持熔断 ＋ 超时收紧到 2 秒；
B2（默认开启）才有前提。老用户存的旧默认值(0)由 `upgradeDohDefault()` **一次性**抬起（用户手动选择后不再被干涉）。
用例表 **75/75** 全绿（33 → 75），闸门 **478 条**全绿（445 → 478）。
**产物 `bm.apk` 60,892,848 B / MD5 `1ad8570366c08dcfe052b01ff5e419aa`，与设备 pull 出的 `base.apk` 逐字节一致。**

## 四、踩过的坑（高频复用，务必先看）

### 判据纪律
1. **闸门只断语义，不断字面写法/具体数值/具体方法名。** 已清 5+ 条这类断言。
2. **闸门四种失效形态**：① 只验"调用了某方法"不验"用对了没有"（气泡那条：旧代码形式合规、效果错误、**闸门全绿但气泡照弹**）② 锚在**死代码**上（`switchToNextInternalPlayer` 全工程无调用点，真正在跑的是 `compatFallback`）③ 锁死失效写法 ④ 锚在**局部变量名**（局部变量不进 dex 字符串池 ⇒ 打包校验阶段失败、**APK 不落盘**，不是编译失败）。
3. **写断言前先确认"这段代码真的会被执行" + 它进不进 dex。**
4. `mustnot` 判据要写成 `PlayerHelper\.xxx` 这种**实际调用形态**，否则会命中自己注释里的旧方法名而误报。

### 构建
5. **闸门绿 ≠ 能编译** ⇒ 大段编辑后第一道真验证＝跑一次构建。
6. **构建启动后又改源码 ⇒ 必须重跑构建再定版**（同名覆盖）。
7. 构建要 `dangerouslyDisableSandbox:true` ＋ `bash build_l1box.sh <基名>`；长任务用 `run_in_background`（`nohup &` 会被回收）。
8. **本机页面文件被禁用**（16GB 内存，构建期只剩 ~4.3GB）⇒ 改 Kotlin 后 `compileReleaseKotlin` 独立守护进程会**原生内存崩溃**（`os::commit_memory errno=1455`），**3 次自动重试救不回来**（同一根因）。已改用 in-process 策略规避。

### 真机验证 / adb
9. **`adb logcat -f` 带缓冲小数据不落盘**，设备端文件常 0 字节 ⇒ 宿主机 `adb logcat >>文件` 冗余通道才可靠；补读用 `adb logcat -d` 从环形缓冲捞。
10. **USB 频断**（09-18、09-19 多次）⇒ 装机/抓取前先 `adb devices` 确认。
11. **硬证据优先于日志**：清理是否成功，以 `ls /sdcard/Android/data/com.github.tvbox.osc/cache/` + 有无 `old-*` 残骸为准，不依赖某条日志是否被抓到。
12. **验证脚本先自测再交给用户**——这是省来回的关键。

### 操作纪律
13. **请用户改过持久化开关后，下一轮测试前必须明确要求改回来。**（09-18 让用户关「磁盘缓存」测一轮、忘让开回 ⇒ 整轮日志 `L1Cache` 一条都没有，白测。）
14. **首页连按两次返回 = `Process.killProcess` 杀进程 ⇒ 冷启动必清缓存。** 要验"会话内命中"，播放页按一次返回回详情页即可，**别退桌面**。

## 五、口径铁律

- **⛔ 不许提"自动换线路/自动换源/引导换源"。** 换线路是用户手动的事；目标是提高**单线路**成功率。
- **术语**：配置源＝订阅；线路＝线路名；影视站点＝播放来源；`首页.json`＝展示配置。
- **大原则**：减少崩溃必须、加速锦上添花。
- **风控判据＝五维**：并发连接数／请求速率／顺序特征／单位时间流量／命中缓存时的请求数。A（Exo 落盘缓存）五维全不增＝唯一零风控方案。
