## 一、目标

| # | 目标 | 性质 | 达标判据 |
|---|---|---|---|
| **G1** | 任何类型的订阅源都不因**我们自己的代码路径**杀掉进程 | **必须** | 冷启动首搜 + 退出重进首搜，各 5 轮：`Fatal signal 6` = 0、`JNI DETECTED ERROR` = 0 |
| **G2** | 搜索体验不低于 ab 基线，且**退出重进后的首搜明显快于 ab** | 增色 | 见第五节验收表 |

一句话：**G1 是修 bug，G2 只能靠"不重复加载"拿到。**

## 二、硬约束（本轮边界，不可越）

1. **不做任何提高 jar 初始化密度的事** —— 并发数保持 10（全员）、不做预热、不做 `quick=true`。这三条全部已被实验否掉（ae/ai/al/am 四版实证）。
2. **不做分源并发** —— `searchConcurrencyNonFamily` 整条链撤除，不再单独验证。
3. **保留全部既有防线**：`NATIVE_INIT_LOCK` 全局串行、进程级单飞、800ms 门禁、路由账本 + 身份终审、`JarKillNeutralizer` 合法替身名 —— 一条不撤。
4. **不动无关模块**：播放器、缓冲水位、首页展示、横幅清扫一律零改动。
5. **每批单独出包、单独验证，不混批** —— 混批是上一轮多耗 al/am 两版的直接原因。

## 三、提速手段白名单（**只有这三条**）

| 手段 | 原理 | 对崩险 |
|---|---|---|
| **A. jar 装载复用** | 同一个 jar 在一个进程里只装载一次 | **下降**（同时治 `mid==null`） |
| B. 搜索结果缓存 | 同关键词二搜直接命中 | 无 |
| C. 慢源分档超时 | 不等最慢的站点（当前只有全局 30s 看门狗） | 无 |

**永久移出白名单**：并发数、预热、`quick=true`、家族 jar 提前加载。这四条的"快"都以抬高初始化密度或互杀链为代价，已被实验逐一否掉。

## 五、验收标准（不靠"我这台机器没崩"）

**① 离线判据回归（PC 上跑，不需要设备）**

抽判据代码为纯 Java harness（只读 zip/dex 字节），输入订阅里**全部 jar**，输出每个 jar 的判定与命中信号。验收：
- **所有含 `DexNative` / 原生引用 / 子进程引用的 jar 必须 100% 判为家族 → 零漏判**
- 普通 jar **零误判**

这条是"换台机器也成立"的证据。**需要你提供订阅里 jar 的下载链接，或授权用 adb backup 从设备取。**

**② 真机固定口径**

- 路径：**① 等进程冷启动 → 立刻搜索　② 退出软件 → 重进 → 立刻搜索**，各 5 轮
- 判据：

| 指标 | 标准 |
|---|---|
| `Fatal signal 6` / `JNI DETECTED ERROR` | **0** |
| `killall begin` | 每进程 ≤ 1（首次启动），稳态 0 |
| `DexClassLoader` 创建数 | 每进程 ≤ jar 种类数（证明复用生效，批次二才有意义） |
| 加固 jar 的网盘源 | **仍可用**（证明没有过度拒载） |
| "本接口免费分享"弹窗 | 清扫器零漏网（现状已达标，回归确认） |

## 六、风险与边界（不美化）

1. 判据再通用，也**不能证明** 100% 覆盖未知 SDK 的所有形态。今天见过的形态（类名、原生引用、子进程引用、运行时探测四路）语义上已覆盖"要载原生 或 要拉子进程"的全部路径。
2. **误判代价**：家族 jar 拿不到本地代理 → 其网盘代理类源降级（503）；普通搜索、详情、普通播放不受影响；**绝不崩**。方向是 fail-safe：宁可多判家族。
3. 批次二的复用若遇到"服务端每次生成不同 md5"的 jar，会退化为每次重载 —— 行为与今天相同，**不会更差**。
4. ab 版**从未被证明不崩**（无留存真机日志），所以"回 ab"不等于回安全区；我们的目标是超过 ab，不是回到 ab。
