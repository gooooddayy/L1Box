## 一、总目标（贯穿全程，未变）

| # | 目标 | 性质 | 达标判据 |
|---|---|---|---|
| **G1** | 任何类型的订阅源都不因**我们自己的代码路径**杀掉进程 | **必须** | `Fatal signal 6`＝0、`JNI DETECTED ERROR`＝0 |
| **G2** | 搜索体验不低于基线，退出重进后首搜更快 | 增色 | 只能靠「**不重复加载**」拿，不靠提并发 |

**大原则（用户原话）**：**减少崩溃必须，加速锦上添花。**

### 1. 播放器线（`bc`→`bh`）→ **已收尾**

**三条作用域口径（`be` 定稿，至今有效）**

| # | 动作 | 作用范围 | 落盘 |
|---|---|---|---|
| 1 | 设置页「默认播放器 / IJK 解码」 | **没手动选过播放器**的片子（含看过的、所有线路） | 全局 Hawk |
| 2 | 播放页/详情页手动切内置内核 | **本片·本线路的所有集**（换线路互不影响） | 本片历史（按线路存档 `flagPlayerCfgMap`） |
| 3 | 外部播放器（MX/Reex/Kodi/附近TVBox/VLC） | **仅本次这一集** | 不落盘 |

**关键设计**：判据从「配置里有没有 `pl`」改成显式标记 **`plt`** ——
因为控制条上**任何**按钮（比例/速度/起播跳转）都会把整份配置写回历史，用 `pl` 判会误判成"用户选过"。
**手动选共三处入口**（控制条短按循环 / 控制条弹窗 / 解析档按钮），**每处都要 `markUserPicked`**；
**自动兜底不得打 `plt`**。

**`bh` 修掉的两个真 bug（都藏在没测到的路径上）**
1. **详情页选「IJK播放器(硬/软解码)」必然失败** —— `switchPlayerItem` 里 `if (item >= 10) return false`，
   而内置 IJK 硬/软解编号是 **100/101** ⇒ 被当成"外部"挡掉 ⇒ 弹「切换失败」。
   同一个选项**播放页能用、详情页不能用**。改判据为 `PlayerHelper.isExternalPlayer(item)`。
2. **控制条「解析档」按钮的选择记不住** —— 改了档名、写了存档，但**漏打 `plt`** ⇒ 退出重进被默认冲掉。

**判"是不是外部"必须用 `PlayerHelper.isExternalPlayer(item)`，永不用 `item>=10`。**

### 2. 缓存与起播线（`bi`→`bk`）→ **六项全绿，已收尾**

| 项 | 结论 |
|---|---|
| 磁盘缓存命中 | ✅ 同地址重播 **434→146ms**（快 3 倍），播放中命中读 697KB |
| 换集不串集（**红线**） | ✅ 含"同主机同路径仅参数不同"的边界案例 |
| 冷启动清理 | ✅ 151MB/35 文件，改名→删除 10.25s（**真删仅 0.25s**） |
| 水位 128MB | ✅ 9 次接管全 `300s/128MB`，升档 8/8 |
| 设置页开关 | ✅ 关/开即时生效 |
| 稳定性 | ✅ 13 次起播、FATAL 0 |

**风控五维**（并发连接数／请求速率／顺序特征／单位时间流量／命中缓存时的请求数）：
**A（Exo 落盘缓存）五维全不增＝唯一零风控方案**；多线程尽速预取＝四维异常，**不做**。
**红线**：`127.0.0.1` 的 `/l1.m3u8`（净化）与 `/proxy`（网盘）**每集同址**，
而 Exo 缓存 key 取 URI ⇒ 必须排除（已排除本机/localhost/`[::1]`/`0.0.0.0` + `file/content/asset` + `rtmp/rtsp`）。
**起播门槛对 HLS 是伪命题**（缓冲按整片跃升）⇒ **保留 1500ms 不动**，"自适应门槛"整批取消。

### 3. 订阅源解析线（`bl`/`bm`）

解析分两段：①添加订阅 `SubscriptionActivity`／②启用拉配置 `ApiConfig.loadConfig`，**失败面互不相同**。
容错逻辑做成**零 Android 依赖的纯 Java 类**（`L1SubUrl`/`L1SubContent`）⇒ 宿主机 JVM 跑用例表，不依赖真机。

- **`bl`（P0+P1 全做，自检面板 P2 不做）**：解析层净化 + 网络层对齐/多仓宽松收集/GBK 兜底；
  **用户实报的「切源了还在用上一源线路数据」一并修** ——
  根因＝多仓取 `activeLineUrl` 而编辑只改 `name/url` ⇒ **`isMultiRepo/lines/activeLineUrl` 三件套必须一起作废** ＋ 按新地址重识别。
- **`bm`（A 档 7 项 + B1/B2）**：缓存回退 / 顶层数组 / 块注释与尾逗号清洗 / base64+gzip /
  请求头补齐 / 准确失败结论 / 0 站点提示；**B1** 安全DNS 回退包装 ＋ **B2** 默认开启。
  **本批最关键发现**：内嵌 DoH **对私有地址直接抛异常且不回退** ⇒ 只把默认值改"开"会让
  净化 `/l1.m3u8`、网盘 `/proxy`、首页 `/l1home` **全部解析失败＝必现**。B1 的真实内容是**堵这两个坑**：
  私有/IP 字面量前置绕开 DoH ＋ 失败**如实抛出**以支持熔断 ＋ 超时 10s→**2s** ＋ 3 败熔断 5 分钟。

**「比旧版提高多少」口径**：只能说**确定性「必败→可用」6 类**
（①多仓子线路漏 `http://` ②`;pk;` 结尾 split 越界可闪退 ③裸/URL-safe/双层 base64
④BOM/夹文字/HTML 外壳 ⑤GBK 乱码 ⑥添加订阅无 UA/超时/重试）。**绝不给"N 个百分点"。**
**没提高的**：源站自身无数据、网络层阻断（SNI 被 RST）。

### 4. 搜索与网络层（`bn`，当前定版）

**`bn` 只做三件事，零行为变更**
| 改动 | 为什么必要 |
|---|---|
| `Spider.safeDns()` 由**裸 DoH** 改挂包装层 `fallbackDns` | 裸 DoH 遇私网/IP 字面量直接抛；bm 又把"静默回退"改成"如实抛出"⇒ 走这个入口的 jar 由"慢但能通"变"直接失败" |
| `L1FallbackDns` 补 4 类计数 ＋ 失败 `Log.w("L1Dns")` | 原 `catch (Throwable)` **静默吞掉一切** ⇒ 日志判断不出 DoH 有没有生效 |
| `FastSearchActivity` 增 `搜索首条结果`／`搜索耗时…DNS(窗口内)`／`本轮装载增量` | 搜索侧此前**零耗时日志**，"慢多少、慢在哪"只能靠体感 |

**实证收益（真机 09-22）**：全轮 `L1Dns` 只打 **2 条失败**
（`api.<订阅源A>.com`／`api.<订阅源B>.com`，DoH 上游查不到）——
**因挂的是包装层，失败被接住并回退系统 DNS，站点活了下来**。若仍是裸 DoH，这两次会直接抛进 jar 内部。

## 五、口径铁律（容易踩的）

1. **⛔ 不许提"自动换线路/自动换源/引导换源"。** 换线路是**用户手动**的事；目标是提高**单线路**成功率。
2. **术语**：配置源＝订阅；线路＝线路名；影视站点＝播放来源；`首页.json`＝展示配置。
3. **一个 APK / 周期**；不主动提 GitHub。
4. **闸门只断语义**：不断字面写法/具体数值/方法名。
   四种失效形态：①只验"调用了某方法"没验"用对没有" ②锚在死代码 ③锁死失效写法
