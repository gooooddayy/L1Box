## 一、🔴 最危险的一条：横幅清扫器（`ToastSweeper`）会把自家播放器"吃掉"

**症状**：播放中**上下滑**调亮度/音量 → 视频画面 + 全部控件**瞬间消失**、按钮点不动、只有杀进程能恢复。
左右滑（进度）、双击（暂停）**完全正常**。

**为什么会这样（完整机制）**

```
手势滑动 → 播放器显示「亮度50%」「音量30%」
   ↓ 恰好命中横幅特征（BANNER_HINT_RE 里有 `.*%$` 分支）
   ↓ 播放器整块又满足「loc[1]≤400 + 宽≥400 + 含 ProgressBar(SeekBar)」
被 JudgedAsJarBanner → hideTreeBanner()
   ↓ 打成 0 尺寸 + translationY=-10000 + alpha=0 + INVISIBLE
   ↓ 并写进 hiddenBanners **永久保持**
= 画面与控件整块消失；只有杀进程能恢复
```

- **只有上下滑触发**：左右滑浮层是「30:10/40:10」**无 `%`**、双击无 `%` ⇒ 不命中。
  （与用户原话"一上下滑就黑、左右滑双击正常"**完全吻合**。）

**引入点**：`r` 版（09-10）新增的 `scanTreeForBanners` 树内扫描 —— 正是用户说的"昨晚 22 点前的版本"。

**修法三件套（缺一不可）**
1. `BANNER_HINT_RE` **删掉 `.*%$` 分支**（百分比不能单独作横幅特征）；
2. 新增 `containsHostView()`，宿主自有类前缀（`com.github.tvbox.osc.` / `xyz.doikki.`）——
   `scanTreeForBanners` 命中宿主布局**只往下找、绝不整体隐藏**；
3. `isLikelyBannerAtAdd` 与 `hideJarBanner` 同样加**宿主布局放行**。

### ⚠️ 由这条推出的三条"新增 UI 铁律"（后续所有浮层/Toast 都要遵守）

| # | 铁律 | 原因 |
|---|---|---|
| 1 | **新浮层里绝不放 `ProgressBar`** | "顶部 + 宽≥400 + 含 ProgressBar" 正是被判为 jar 横幅的条件 |
| 2 | 新浮层文案**不以「正在」开头** | 「正在…」也是横幅特征 |
| 3 | **新增 Toast 文案必须加进 `HOST_TEXTS` 白名单** | 否则被 `sweepWindows` 当 jar 弹窗 `removeView` |

> 已在 `y` 版实际执行一次（连播倒计时浮层）：文案定「已从 」「已跳过片头 」并加进白名单，
> 浮层内零 `ProgressBar`。**这条流程要一直带着。**

### 附带的一条方法论教训

**`u` 版修错了地方**：播放器手势有**两份实现**，`VodController` 实际继承的是 **app 侧 `BaseController`**，
而 `u` 版修的 `doikki` 库 `GestureVideoController` 是**全项目无人使用的死副本**（死代码）。
⇒ **教训**：改之前先确认"这段代码真的在活路径上"——与闸门失效形态②（锚在死代码上）同族。
`x` 版已把两个误改文件 `git checkout` 回上游、**与上游逐字一致（diff 为空）**。

## 三、播放器体验四项（`y` / `z` 版落地）

| # | 项 | 关键实现 / 决定 |
|---|---|---|
| 1 | **断点续播** | 新建 `util/ProgressStore.java`：**独立 SP**，`MD5(键) → "进度\|时间戳"`，上限 **300 条**超限淘汰最旧，`progress≤0` 即删。口径：**<10 秒不提示**、**≥95% 视为看完从头开始**、最后一集停在最后一帧 |
| 2 | **连播倒计时** | 唯一新增 UI：`next_episode_tip` 浮层 + 5 秒。`STATE_PLAYBACK_COMPLETED` 与片尾到点**共用** `showNextEpisodeTip()` + `mNextTipShowing` 防重（原先两条路径各跳一次，不防重会**连跳两集**）。**停表三处**：`onDetachedFromWindow`／`onWindowVisibilityChanged`（退后台时 View 不 detach）／`STATE_IDLE` |
| 3 | **缓冲二级色** | 根因是**配色**不是没实现：缓冲段 `#e6e6e6` 与进度段 `#ffffff` 在 3dp 细条上无法区分（代码一直在 `setSecondaryProgress`）⇒ 改 **`#8C8C8C`** |
| 4 | **片尾跳过** | 不另加提示，**复用倒计时浮层**（它本身就是提示） |

### 🔴 为什么进度**不能**塞进 Room 的 cache 表（重要设计决定）

`cache` 表与历史/收藏同在 Room 库 `tvbox.vN.db`，而 `AppDataManager.dbPath()` 把**版本号写进文件名**
⇒ 给表加字段必须升版本 ＝ **换库文件 ＝ 历史收藏全丢**
（且项目内 `1_2`~`4_5` 的 migration **全被注释**，从不走 `ALTER` 路径）。
⇒ 改用独立 SP：**零迁移风险**，与缓存/历史解耦。「一键清理」会删 `shared_prefs` 目录 ⇒ 进度天然被清。

### `z` 版自查补出的两个 bug（说明"自查"必要）

1. **连播浮层「取消」形同虚设**：点了取消只收浮层，视频播到真结尾会**再触发一次
   `STATE_PLAYBACK_COMPLETED`** ⇒ 浮层重弹、5 秒后照样跳集。片尾跳过点通常在结尾前 ~90s ⇒
   等于取消无效。修法：新增 `mNextTipCancelled`，取消走 `dismissNextEpisodeTip()` 落标记，
   `resetSpeed()` 每集复位。
2. **跨设备隐患**：新浮层原用 `paddingHorizontal/paddingVertical`（**API 26+ 才生效，minSdk 24**）
   ⇒ API 24/25 设备内边距被静默忽略、文字贴边。改 `paddingStart/End/Top/Bottom`。
   （全项目其余布局仍有同类写法，属既有基线，未动。）

## 六、环境坑（这几天的，补进工具表）

1. **宿主 Git Bash PATH 损坏**时（`dirname`/`sleep`/`tail`/`grep` 全找不到、shim 报 `cd: null directory`）：
   先 `export PATH="/c/Users/Administrator/.workbuddy/binaries/PortableGit/versions/1.2.0/usr/bin:$PATH"` 即可恢复全部 coreutils
   —— 比逐条绕路快得多。
2. **后台构建命令必须在同一行先 `export` 完整 PortableGit PATH（`usr/bin`+`bin`+`cmd`）再 `cd` 调脚本**，
   否则 `build_*.log` 里只有 `bash: command not found`。
3. **`Get-Content` 默认按 ANSI 读** ⇒ UTF-8 中文日志全成乱码 ⇒ **本工作区 md 读写一律走 python `io.open(encoding='utf-8')`**。
4. 对设备做管道操作时，**放进 `adb shell "cmd | grep"` 在设备端执行**；宿主端只用绝对路径 `adb.exe` 单命令。
5. 构建**偶发瞬时中断**（跑到 `compileReleaseKotlin` 无报错即停）⇒ **同参数重跑即恢复，不是代码问题**。
