## 一、构建 / 签名链路（08-19 ~ 09-08）

| 问题 | 根因 | 最终修法 |
|---|---|---|
| GitHub Actions 反复构建失败/无产物 | CI 环境不可控 | 放弃纯 CI，本地构建；脚本固化四道闸门 |
| 老设备/部分手机装不上 | 缺 v1(JAR) 签名 | `apksigner --min-sdk-version 17` 强制 v1(SHA-1)+v2+v3；**验证也必须带此参数**否则 v1 显示 false |
| gradlew 直调触发 wrapper 重新下载 | 环境 distinct | 构建一律走 `build_l1box.sh`（GRADLE_USER_HOME 指向工作区 `.guserhome2`，JAVA_HOME 指 `dl/jdk11`） |
| daemon 闪断 / "Could not receive a message from the daemon" | 进程/锁残留 | 清理 java/gradle 进程后重跑；脚本内自动重试 |
| 资源名混淆 | — | **勿 apktool 重打包**（会破坏混淆资源名） |
| 09-08k：Guard 站点 getSpider 返回 null | 加固 jar 校验宿主签名白名单 | 切回官方 TVBoxOSC.jks 签名（部分闪退就此消失） |

**坑**：构建机内存波动会假报失败；`&` 后台化优先级不可靠，长构建用 run_in_background + TaskOutput。

## 二、首页加载 / 闪退系列（09-02 ~ 09-05）

1. **首页"一直加载"**（多轮反复）：
   - 四个卡死点全修：①`onPause` 只 cancelHomeWatchdog ②spider 判空用 `isNullOrEmpty()` ③spider 空时 loadJar 无回调需放行 ④30s 看门狗覆盖 initData+reloadSitePool。
   - **OkGo 3.0.4 超时坑**：其默认超时/重试行为会挂住链路，须显式设超时。
   - 防复发：新增 `validate_home_config.py` 校验首页配置无死链。
2. **架构级修正（09-02，最重要）**：首页源池（`homeSiteList`←assets）与订阅站点池（`sourceBeanList`←当前线路）**严格隔离**；首页.json **绝不能走 parseJson**（上一版因此被订阅覆盖出致命 bug）；spider 各用独立 jar+loader；读写全 synchronized，搜索/详情只用快照。
3. **首页每次进入都自动刷新（09-04）**：ViewPager 相邻页销毁重建 → `offscreenPageLimit=fragments.size`（治本）+ `init()` 三分支（空源/有缓存/首次，防重复拉取）。
4. **固定豆瓣热播 → 降级站点推荐（09-03）**：评估后判定不值得修（依赖外链+加固链路），主动降级方案，用户拍板。
5. **加载源闪退（09-03 需求4）**：疑似 jar 调 killProcess 自杀（09-09 才真正终局，见第四节）。

**坑**：修复后必须回头 review（多次"交付后自检"发现漏网分支）；空源分支不能删（否则不显示"添加订阅源"）。

## 三、加固 jar 闪退大战（09-08 ~ 09-09，贯穿 e→w 共 18 版）

**现象**：41 个 Guard 加固 jar 站点搜索必现闪退，且伴随神秘横幅弹窗。

**闪退根因链（层层钉死）**：
1. 后台线程未捕获异常杀进程 → e 版：装后台线程安全网（非主线程只 Log 不杀）。
2. 真凶 JNI abort：`DexNative.getSpider` loader=null（加固 jar 校验宿主签名不过）→ f/g 版：加载前预检 DexClassLoader 就绪与否，broken 降级 SpiderNull。**f 版失手**：只查静态字段，实际是实例字段（get() 单例持有）——反编译修正。
3. 终局 W^X（m 版）：targetSdk 30→28（Android 10+ 禁可写目录 dex 加载）+ **JarKillNeutralizer**（重写 jar 内 dex 的 method_ids，把 System.exit/killProcess 等调用改指不存在符号→抛可捕获 NoSuchMethodError，重算 SHA-1/Adler32）+ jar setReadOnly。
4. **"闪退后连杀两次"真凶是自己**：BaseActivity `isNormalStart=false` 时 relaunchApp+killProcess 自身，系统重启跳过 Splash 又触发自杀 → App.onCreate 置 isNormalStart=true 根除。

**横幅/弹窗系列（q~w 版，五版全败后的终局）**：
- q 版 Choreographer 帧钩子扫 TYPE_TOAST 窗口（零闪现、反射静态缓存）。
- n 版 ContextWrapper 桥接 → **ClassCastException 回归**（jar 内部把 Context 强转 Application）→ 桥必须 `extends Application` + 全委托。
- r/s 版拦错对象（猜 jar 拿窗口的路径，猜一个改一个）；t 版反射签名写错（updateViewLayout 应为 `(View, ViewGroup.LayoutParams)`）→ NoSuchMethodException **拖死整个清扫器**。
- v 版窗口普查取证 → 铁证：横幅不是独立窗口、不是 Toast、**uiautomator 从未抓到文本 = 自绘 Canvas 画字**。
- w 版终局 `sweepDecor`：Activity DecorView 的子 View index>=1 且非白名单类（android./androidx./com.google.android/宿主/com.scwang.）→ alpha 0+GONE（不 removeView，jar 零感知）。

**方法论教训（本项目最值钱的）**：
- **识别手段要先验证能感知对象，再写拦截逻辑**（q~u 五版全败皆因未验证"视图里有 TextView"假设）。
- 给加固 jar 传 Context 包装类：必须同时满足**类型兼容**（含 Application 强转）与**行为代理**。
- 反射初始化里新加方法查找必须**独立 try-catch、可空降级**，一个失败不能拖死整个清扫器。
- 诊断日志**同时落 logcat 与文件**（/sdcard 权限可能没批，logcat 一定可用）。
- 修复动作最小化：隐藏（y=-6000/alpha=0/GONE）优于 removeView（jar 后续 removeView 会 IllegalArgumentException）。

## 六、性能 / 机制托底 / 体积（09-09 ~ 09-11，p→s 版）

- **p 版托底**：`L1Executors` 统一线程池（SAFE_REJECT：饱和非主线程直跑、主线程转 l1box-overflow，绝不 shutdown）；`DeviceProfile`（isLowRamDevice 强制低档、内存压力只降不升）；`StartupGuard`（连续 3 次启动失败清 home_cache）；HomeCache 600ms 合并写盘；内存反射回收全 catch(Throwable)。
- **q 版**：DLNA 接统一池、旋转/分屏重算 AutoSize density（按 360dp）、9978 局域网门禁（管理操作默认关）。
- **r 版**：ToastSweeper 帧循环节流至 ~11Hz（耗电）、删 conscrypt -3.4MB（先证明 OkHttp 的 ConscryptPlatform 在 Android 上是死引用）、61.44→58.03MB。
- **s 版播放兼容**：失败入口唯一化（errReplay）、确定性降级阶梯（备用地址→IJK软解→Exo，副本不污染设置，每集≤2 次）、自动切换只限内置、软解按选项值识别、重播先 release()、Exo 2.18 extractors 走构造函数第 2 参。
- **真机实证全过**（09-11）：HTTPS 全链路零 SSL 异常、播放/换线正常、零崩溃零 ANR。

## 七、通用工具坑（跨全程复用）

- logcat 缓冲会被挤掉 → `adb logcat -b all -v time > file &` 全程后台抓。
- CAOC 崩溃是同进程恢复（pid 不变、Application 不重跑）→ 运行期崩溃归 CAOC，StartupGuard 只管进程级。
- 点击前先 `dumpsys` 确认前台；其他 App 弹窗一律忽略。
- 取证优先反编译：javap 字节码 / 反编译 jar / dex 结构偏移（string_ids@56…）直接改字节。
- 无线 adb 掉线时：走"反编译依赖字节码"静态定位，不依赖真机栈。
- 宿主 Git Bash PATH 损坏：`export PATH="...PortableGit.../usr/bin:$PATH"` 一行修复。
- 一次构建只落一个 APK 到 `FreeBox-src/`，旧版归档 `_archive_old_builds/`；未要求不 git push。
- 流程铁律：先列根因与方案 → 用户确认 → 再动手；"单机实测通过"不算结论，要有机制兜底。
