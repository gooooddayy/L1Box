## 三、裁了什么（三类，全部是字段级，**不动结构**）

### 1. 重复注入的对话摘要去重 —— 省 10.09 MB
每条用户消息前都被注入一份 200 KB 级的 `<cb_summary>`（整段对话摘要），**同一份摘要重复注入 110 次、合计 12.43 MB**。
处理：**保留最后 2 份完整摘要**（最新最全），其余 109 处替换为一行标记：
`〔此处原有 N 字符的对话摘要，与最后一次注入的内容重复，已去重〕`

### 2. 超长字段按预算裁短（内容保留可读的开头 + 裁剪标记）

| 字段 | 预算 |
|---|---|
| 工具结果正文（`toolResult.content` / `output.text`） | 500 字 |
| 工具结果渲染数据（`renderer.value` / `rawResponse`） | 200 / 300 字 |
| 工具入参 `arguments` | 800 字（**JSON 感知**：保住键名与命令，只截值） |
| 思考 `providerData.reasoning` | 300 字 |
| 思考 `rawContent[].text` | 400 字 |
| 其余未列字段 | 600 字 |

裁剪标记形如：`…〔已裁剪，原文 496,312 字符〕`

### 3. 快照登记表收口
`file-history-snapshot.snapshot.trackedFileBackups` 每个快照重复列举几十个文件路径 → 只保留前 3 项。

**关键设计：不减行、不动任何 `id` / `parentId`。** 这份记录是 `id → parentId` 串起来的一条链，删行会断链；只截字段则链条天然完整 —— 所以上面 `parentId` 断链是 0。
