## 三、⚠️ 磁盘缓存本轮完全没启用（必须查清）

**现象**：整份 134 行日志里 **`L1Cache` 一条都没有** —— 没有「磁盘缓存已就绪」、没有「命中读取」、没有「缓存目录拿不到」。

**推理链**（每一步都用源码验证过，不是猜）：

1. 若 `useCache=true`，`newCache()` 成功必打 `磁盘缓存已就绪 上限 256MB`；拿不到目录必打 `缓存目录拿不到，本次直连`；创建异常必打 `磁盘缓存创建失败`。
2. 三条**一条都没有** ⇒ `useCache` 压根是 `false`。
3. `useCache = ExoCacheConfig.isEnabled() && ExoCacheConfig.isCacheableUrl(path)`。
4. 本轮起播地址是 `https://cdn.ryplay11.com/…/index.m3u8`、`https://cdn9.ryplay9.com/…` 等 —— **都不是本机地址**，`isCacheableUrl` 必然返回 true。
5. ⇒ **`isEnabled()` 返回了 false** ⇒ `PlayerHelper.init()` 读到的 `Hawk.get(EXO_DISK_CACHE, true)` 是 **false**。

**最可能的原因**：**设置页「磁盘缓存」开关处于关闭状态。** 09-18 那次测试我请你做过一步「把磁盘缓存关掉，再播一集确认还能正常播」—— **关掉之后没有开回来**，而开关是持久化的（Hawk），之后每次启动都会同步成 false。

**连带解释了两个现象**：
- **11:12:08 有一次进程重启**（PID 18379 → 21612，疑似「划掉 App 重开」），但**没有清理日志**。这**不是 bug**：清理逻辑只在 `exo-video-cache` 目录**存在**时才改名打日志；由于缓存从未创建，该目录不存在 ⇒ 静默跳过，符合设计。
- **11:12:15 那次同地址重播没有变快**（3099ms vs 首次 3615ms）—— 因为根本没缓存可命中。

**确认方法**（设备重连后一条命令，或直接看 UI）：
```bash
adb shell "ls -la /sdcard/Android/data/com.github.tvbox.osc/cache/"
```
若**没有** `exo-video-cache` 目录 ⇒ 坐实"缓存未启用"。
UI 侧：设置页 →「磁盘缓存」开关是否为开。
