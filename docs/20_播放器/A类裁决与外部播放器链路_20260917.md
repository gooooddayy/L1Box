## 三、外部播放器：什么情况会被吊起、怎么手动吊起

### 3.1 全工程只有 **1 个调用点**

`PlayFragment.startPlayUrl()` 第 **1547** 行 —— 也就是说，外部播放器**只会作为"这一集选定的播放器"被吊起**，
没有任何"失败时自动唤起"的分支。

**已确认不会自动吊起的地方**：

- 失败兜底阶梯 `PlayerHelper.buildCompatFallbackPlan()` —— 只含**内置**（IJK 软解 → Exo）；
- 短按循环 `PlayerHelper.getBuiltinItems()` —— 只含**内置三项**（Exo → IJK 硬解 → IJK 软解）；
- `errReplay()` 整条阶梯（换地址 → 回退直连 → 换协议 → 换内核 → 终态提示）—— **一步都不含外部播放器**；
- `VodController` 里短按/长按都不存在"失败即唤起"的逻辑。

### 3.2 会**持续生效**的三个入口（这才是"自动吊起"的真正来路）

| 入口 | 代码位置 | 列表来源 | 生效范围 |
|---|---|---|---|
| ① **设置页「默认播放器」** | `SettingActivity.kt:185` | `PlayerHelper.getExistPlayerTypes()` —— **含外部播放器**（装了 MX/Reex/Kodi/VLC 就会出现） | 写入 Hawk `PLAY_TYPE` ⇒ **全局默认**，**此后每次播放都自动吊起** |
| ② **播放页长按「播放器」** | `VodController.java:529` | `PlayerHelper.getAllPlayerItems()` = 内置三项 + 已装外部 | 写进该剧集的 `mVodPlayerCfg`，**并立即重播一次**；此后**该剧集每一集都用它** |
| ③ **订阅站点下发 `playerType`** | 解析：`ApiConfig.java:604`；应用：`PlayFragment.java:1750` | 站点 JSON 里的字段，默认 `-1`（= 跟随设置页） | 站点写 `playerType: 14` ⇒ 该站点**首次播放即自动吊起 VLC** |

> 也就是说：**②是"手动选、之后持续"，①和③是"配一次、此后自动"**。

### 3.3 手动吊起的操作

进播放页 → 焦点移到 **「播放器」** 按钮 → **长按 OK**（不是短按）→ 弹出「请选择播放器」→ 列表里选
**MX播放器 / Reex播放器 / Kodi播放器 / 附近TVBox / VLC播放器** → 自动用该播放器重播。

- **短按**：「播放器」按钮只在**内置**三档里循环，**永远不会吊起外部播放器**（这是上一轮刻意做的，防误触）。
- 列表里**只会出现已安装的**外部播放器（`getPlayersExistInfo()` 逐个探测包名，没装的不显示）。

### 3.4 需要你拍板的两个点（都直接对应"不建议自动吊起"）

1. **设置页现在能选外部播放器当"默认"** ⇒ 这是唯一"配一次、此后每次自动吊起"的路径。
   要不要**只在设置页列内置**，把外部播放器限制在长按菜单里、按次使用？
2. **外部播放器吊不起来时没有回退**：外部分支是 `runExternalPlayer(...) → return;`。
   若配置指向 VLC 但**没装 / 调用失败**，界面只提示「调用外部播放器VLC播放器失败」，
   **不会退回内置播放器继续播** —— 这一集就播不了。要不要加"吊不起来就退回内置继续播"？

### 3.5 顺带一个观察（**没改**）

`PlayerHelper.getPlayersExistInfo()` 里写死 `playersExist.put(0, false)`，
把 **系统播放器（0 号）恒标为"不存在"** ⇒ 设置页与长按菜单**都选不到它**，
只有站点下发 `playerType: 0` 才用得上。你若希望它可选，也是一行的事（**未改，等你一句话**）。
