# 播放器改造复查：收尾状态 + 两个真缺陷（2026-09-18 · bh）

用户提问：这几轮播放器优化是否收尾、有没有其他 bug。逐处复查 be / bf / bg 全部改动后的结论如下。

**结论先说**：功能主体已收尾（口径全部落地、闸门 + 构建 + 装机指纹齐全），但复查**又找到 2 个真 bug** ——
两个都藏在你没测到的路径上，已一并修掉。另有 1 处判据收口、1 处死代码标注。

## 二、真 bug ①：详情页选「IJK播放器(硬解码/软解码)」必然失败

**位置**：`PlayFragment.switchPlayerItem()`（详情页弹窗选内置项的入口）

```java
if (item >= 10) return false;        // ← 错在这里
```

**为什么错**：内置项里 **IJK 硬解 = 100、软解 = 101**，都大于 10。这条判据本意是"外部播放器不走这里"，
结果把两个内置项也一起挡掉了 ⇒ `switchPlayerItem` 直接返回 false ⇒ 详情页弹 `"切换失败，请稍后重试"`。

**触发路径**（100% 复现）：详情页 → 点「播放器」按钮 → 选「IJK播放器 (硬解码)」或「(软解码)」→ 必然失败。
而同样这两个选项在**播放页**走的是另一条路（`VodController` 里用的是 `isExternalPlayer`）⇒ 能用。
**同一个选项、两个页面表现不同**，正是"详情页与播放页同步"这条口径上的漏网之鱼。

**修法**：改用统一判据 `PlayerHelper.isExternalPlayer(item)`（10~14）。

> 这是"`item >= 10` 粗判"的**第三处**遗留。前两处（控制条、详情页）在 bf 那轮修掉了，
> 唯独这处藏在 `PlayFragment` 里没被闸门覆盖 —— bf 的断言只查了 `VodController` 与 `DetailActivity`。

## 三、真 bug ②：控制条「解析档」按钮的选择记不住

**位置**：`VodController` 里 `mPlayerIJKBtn`（就是"硬解码 / 软解码"那颗按钮）的点击处理

它改了 `ijk` 档名、也写回了存档，但**没有打 `plt`（用户手动选过）标记**。

**后果**（可复现）：
1. 进某片 → 控制条点「解析档」把硬解码切成软解码 → 本次生效、看着没问题；
2. 退出再进这片子 / 下一集 → `isUserPicked == false` ⇒ 按设置页默认**重新刷新** `pl` 与 `ijk`；
3. **用户的软解码选择被冲掉**，回到默认档。

**为什么这是 bug**：切硬解/软解与弹窗里选「IJK播放器(硬解码/软解码)」是**同一件事**，
但两个入口一个记得住、一个记不住 —— 口径不一致。按你 09-18 拍板的
"切换播放器后（exo/ijk软解硬解）适用同线路本片的所有集"，这个入口也应该算"手动选过播放器"。

**修法**：在这个入口补 `PlayerHelper.markUserPicked(mPlayerConfig)`。

## 四、判据收口（零行为变化）

`PlayFragment.startPlayUrl()` 里另有一处 `if (playerType >= 10)`。它的输入是配置里的 `pl`
（只可能是 0/1/2/10~14，100/101 会被 `applyPlayerItem` 转成 `pl=1`+档名），**当前不会出错**。
仍改成 `isExternalPlayer(playerType)`：把"哪些编号算外部"这件事收口到一个地方，
避免以后再出现 100/101 这种被粗判误伤的内置项。

## 五、死代码标注（保留，未删）

`VodController.switchToNextInternalPlayer()` —— **全工程没有任何调用点**。
真正的失败降级走 `PlayFragment.compatFallback()` → `startPlayUrl(临时副本)`。

它是**危险的死代码**：内部会调 `listener.updatePlayerCfg()`，一旦被接上就会把"自动切换"写进
用户存档（`plt` 已经是 1 时下次不再刷新 ⇒ 自动切换把用户的选择顶掉）。
按你"无用的代码宁愿先保留"的口径**保留**，但在 javadoc 里写明了无调用点与启用前必须先去掉那次写回。

## 六、已知边界（本轮记录，未改）

**当订阅里没有下发"硬解码"分组时**，`currentPlayerItem()` 对 `pl=1` 仍返回 100（硬解档），
而候选清单里不会有 100 ⇒ 详情页/播放页弹窗的勾选会落在第一项（系统播放器）上，与标题回显的
"当前：IJK播放器 (硬解码)"不一致。属于极端订阅配置下的显示偏差，点了也只是切到另一项，无功能性损坏，
本轮不动。

## 七、闸门补强（398 条）

之前那两条断言也是**弱断言**，这也是它们没拦住上面两个 bug 的原因：

| 原断言 | 问题 | 新断言 |
|---|---|---|
| `must "$VC" 'PlayerHelper\.markUserPicked\('` | 只验"有调用"，别处有调用就绿了 ⇒ 解析档漏标记照样通过 | `count ... 3`：控制条三处手动入口**逐一计数** |
| 兜底检查锚在 `switchToNextInternalPlayer` | 锚在**死代码**上，等于没有保护 | 新增：锚在真正生效的 `compatFallback`，不许出现 `updatePlayerCfg/savePlayerCfgToLine/markUserPicked` |
| `mustnot "$VC" 'if \(item >= 10\)'` | 只认这一种写法，且 `$PF` 完全没覆盖 | `mustnot "$PF/$VC/$DA" '>= *10\)'`，并新增 `$PF` 的 `isExternalPlayer` 正向断言 |

> 判据用 `>= *10\)`（比较到右括号）而不是 `item >= 10`：注释里会写"不能用 `item >= 10`"这种说明性文字，
> 直接用字面量当判据会**命中自己的注释而误报** —— 这个坑已经在总纲里，本轮再确认一次。
