# 播放器清单口径 + 外部吊起失败回退（2026-09-17 bc）

**用户最终口径（09-17 二次澄清）**

1. **列表只列"本机确实可用"的播放器** —— 装了外部就显示、没装就不显示。
   目的是**不让用户点到"点了吊不起来"的项**；**不是把外部播放器封掉**。
   - 装了外部：系统 + Exo/IJK + 该外部
   - 没装外部：系统 + Exo/IJK
2. **手动切了外部但吊起失败 → 退回内置接着播**（不能就此算这一集播不了）。
3. **系统播放器不该被写死成"不存在"**。
4. **短按循环只在内置内核里走**。

> ⚠ 我在 bb 版里把第 1 条误读成"只列内置、封掉外部"，并把"外部不得作默认"当成铁律
> （设置页移除外部 + 全局默认强制归一化到 Exo）。**bc 版已按上面四条重做**：
> 判据回到"**存不存在**"，与"是不是外部"无关。

### 为什么本地播放页仍然不列外部
判据不是"是否外部"，而是"**这里能不能用**"：`runExternalPlayer` **全工程只有点播页一个调用点**，
本地播放页根本没有吊起外部播放器的通路 ⇒ 本地页列出外部就是"点了也播不了"的无效项，
正是用户第 1 条要避免的东西。而且本地页短按会循环经过列表，误触代价更高。

### 外部播放器的识别是"装了且启用"
`MXPlayer/ReexPlayer/Kodi/VlcPlayer.getPackageInfo()` 查的是 `ApplicationInfo.enabled`
——用户若在系统设置里**停用**了某个播放器，同样算不可用、不列出。
MX 同时识别 `com.mxtech.videoplayer.pro` 与 `.ad` 两个包名。
「附近TVBox」的判据是 Hawk 里的 `REMOTE_TVBOX`（局域网搜索到才有值），不是包存在。

### 回退行为的确切语义
- **只改本次播放的临时配置副本**，`Hawk` 与 `mVodPlayerCfg` 都不动 ⇒ 下次仍然先尝试吊起外部。
- 吊起成功（`startActivity` 未抛异常）→ 维持原行为：本页不再起播。
- 吊起失败（`getPackageInfo()==null`、`ActivityNotFoundException`、其它 Exception）→ 用副本接着走内置起播，
  这条路径本来就有起播看门狗与兜底链兜着，不引入新机制。
- 副本构造失败（理论上不会）才走错误出口，显示可点「重试」。

## 二、闸门（`check_l1box_regressions.sh`）

**331 条全绿**（AC 节 16 条）。AC 节断言已按最终口径重写，其中三条是"防我改回去"的：
- `mustnot normalizeBuiltinPlayerType` —— 设置页**不得再把外部一律踢回内置**（那等于封掉外部）
- `mustnot mPlayersExistInfo` —— 存在性**不得再静态缓存**（装完外部必须立刻可见）
- `must (int) Hawk.get(HawkConfig.PLAY_TYPE, 2)` —— 站点未指定时**照用全局默认**（设了外部就真的用它）

## 四、边界（未做、也做不了的）

1. **"吊起成功但实际没播"感知不到**：外部播放器的 `run()` 只能证明 Intent 发出去了。
2. **VLC 仍然拿不到请求头能力**：VLC 的 Android Intent API 不支持自定义请求头 ⇒ 需要 Referer/UA 的源
   用 VLC 必然失败（B 类，用户已缓做）。
3. **系统播放器能力弱**：走 `AndroidMediaPlayerFactory`，HLS/私有封装大多不支持。它是"可选"而非"默认"。
