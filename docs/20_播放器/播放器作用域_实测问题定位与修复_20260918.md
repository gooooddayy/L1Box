## 二、B：切线路串味（真 bug，09-18 那版改动引入）

### 现象
线路1 手动切到 IJK 软解 → 切到线路2/3，**全都变成 IJK 软解**（应各自走设置页默认 Exo）。

### 根因
`PlayFragment.initPlayerCfg()` 的三分支里，**"本线路没存档"这一支没有落脚点**：

```java
mVodPlayerCfg = new JSONObject(mVodInfo.playerCfg);   // ① 先读「影视级快照」
String lineCfg = mVodInfo.getLinePlayerCfg(mVodInfo.playFlag);
if (!TextUtils.isEmpty(lineCfg)) { 用存档 }
else if (isLegacyOnlyCfg()) { 认领旧数据 }
// ← 本线路没存档、又不是旧数据时，什么都不做：mVodPlayerCfg 还是 ① 那份
```

而 ① 那份 `mVodInfo.playerCfg` 是**上一条线路最后写下的快照**（`savePlayerCfgToLine()` 每次都把它同步成当前线路的内容），里面**带着上一条线路的 `pl=1`（IJK）和 `plt=1`（用户选过）**。

于是往下走 `if (!PlayerHelper.isUserPicked(mVodPlayerCfg))` 时被判为"用户选过" → **不跟设置页默认走** → 新线路继承了上一条线路的播放器。

### 修复
给"本线路没存档"补一个显式分支，**重建空白配置**（往下一路按设置页默认补齐）：

```java
} else {
    mVodPlayerCfg = new JSONObject();   // 不继承任何别条线路的快照
    cfgFrom = "无存档重建";
}
```

### 验证判据
切线路后日志里应出现 `来源=无存档重建`，且 `plt=0`。

## 三、编号判据 + 详情页勾选 + 设置面板入口

### 3.1 `item >= 10` 误判（新发现）
- 候选编号：内置 **0=系统 / 2=Exo / 100=IJK硬 / 101=IJK软**；外部 **10~14**。
- `VodController` 与 `DetailActivity` 两处都用 `if (item >= 10)` 判"是不是外部" → **100/101 被误判**。
- 修复：新增 `PlayerHelper.isExternalPlayer(int)`（`item >= 10 && item <= 14`），两处改用它。

### 3.2 详情页弹窗勾选位置
- 根因：`dialog.setAdapter(..., items, 0)` —— **默认位置写死 0**，所以永远勾"系统播放器"。
- 修复：新增 `PlayFragment.getCurrentPlayerItem()` 返回当前候选项编码，详情页算出 `defaultPos` 再传入。

### 3.3 全屏设置面板缺切换入口
- `dialog_playing_control.xml` 的「播放器」一行（`player` = 短按循环、`decode` = 解码档）右侧新增 `player_pick`（文案「切换播放器」）。
- 点击**复用控制条那颗按钮的完整逻辑**（`mController.mPlayerExtBtn.performClick()`），先关掉本弹窗避免叠加 ——
  不另造一份清单，两个入口语义天然一致。
- `PlayingControlDialog`（底部）与 `PlayingControlRightDialog`（右侧）共用同一布局，两处都绑了。

## 四、历史记录：堆积 / 无图 / 点进去转圈

### 4.1 已确证的部分
- 卡片左上角那行字是**站点名**（`HistoryAdapter` → `tvYear` = `ApiConfig.getSourceName(sourceKey)`），
  右下角那行是 `playNote`（集名）。
- 历史去重键是 **(sourceKey, vodId)**：`insertVodRecord` 先按这两者查，查不到就**插一条新的**。
- 从操作序列看，这轮测试里用户从搜索页**进过 4 个不同站点**（热播影视 / 苹果 / WexAiYueYue / 剧圈99）——
  同一部片在不同站点是不同 sourceKey，本来就各存一条，这是**原生的按站点分条**行为。

### 4.2 高度怀疑（已按此修复，并有埋点待下一轮证实）
**源详情接口返回的 video 缺 `id` 字段。** 三个症状能被同一个原因串起来：

| 症状 | 机制 |
|---|---|
| 历史堆很多条 | 写入用 `vodInfo.id`（源详情给的，为空），读取用本次请求的 `vodId` → 两边对不上 → 每次都被当成新记录 |
| 点进去空白转圈 | 卡片带着空 id 跳详情页 → `loadDetail(null, ...)` 里 `if (vid != null)` 不成立 → 根本不发详情请求 → 一直转圈 |
| 卡片不显示图片 | 同一个源详情缺字段（片名已经在用 `fallbackTitle` 兜底过 —— 说明这源的详情确实是缺字段的） |

**修复**：详情数据回来时给 id 兜底 ——

```java
if (TextUtils.isEmpty(mVideo.id)) {
    mVideo.id = vodId;     // 用"请求这个片子时用的 id"，保证写进去的键下次还读得出来
}
```

### 4.3 需要用户处理
**已经写进去的坏记录救不回来**（它们的 `vodId` 就是空值，拿不到任何 id 去请求详情）。
建议在历史记录页**长按逐条删除**或右上角**清空**一次，之后的记录就不会再出这个问题。
