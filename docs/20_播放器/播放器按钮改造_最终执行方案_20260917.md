## 0. 先纠正我上一轮的一个错误结论（重要）

我上一轮说「设置页没有 MX 是真 bug，我立刻查」。**查清了：不是 bug，是我的前提错了。**

| 项 | 实测值 |
|---|---|
| `pm list packages -d`（已停用） | **含 mxtech** |
| `pm list packages -e`（已启用） | 不含 mxtech |
| `dumpsys package com.mxtech.videoplayer.pro` | `enabled=2`（= COMPONENT_ENABLED_STATE_DISABLED）、`stopped=true` |

**MX Player Pro 在这台手机上处于「已停用」状态**（手机管家的应用速冻/省电优化会做这件事，也可以被手动停用）。

而我们的代码是这样判的（`MXPlayer.java:46-48`）：

```java
ApplicationInfo info = ...getApplicationInfo(pkg.packageName, 0);
if (info.enabled) return pkg;      // 停用时 info.enabled == false
```

⇒ 判它「不可用」⇒ 不列进候选。**这个行为是对的**：被停用的应用用显式 Intent 吊起会抛 `ActivityNotFoundException`，列出来才是「点了没反应」。

> **为什么你看到的是 3 项**：bc 的列表 = `系统播放器 / Exo播放器 / IJK播放器`，正好 3 项。完全吻合。
>
> **顺带排除**：设备上还装着另一个包 `com.github.tvbox.osc.jun`（versionCode=1、20260819 构建、8-23 安装），它不是我们这个包。但它的旧代码列表逻辑会显示 2 项（IJK/Exo），与你的「3 项」不符 ⇒ **可以确定你看的就是我们的 bc**。

**想让它出现 MX，只需在系统设置里把 MX Player Pro 解除停用**（设置 → 应用管理 → MX Player Pro → 启用），然后重进设置页，应该变成 4 项。这个动作只有你能做（我不会去改你手机的应用状态）。

### D. 附带修一处真实隐患：`<queries>` 补全外部播放器包名

**这不是本次现象的原因，但它是真实存在的隐患，我建议一起修。**

- 现状：`AndroidManifest.xml:6-8` 有 `<queries>`，但**只声明了 IDM 下载器**
- 风险：Android 11+ 有包可见性过滤。我们 targetSdk=28，**恰好又声明了 `<queries>`** —— 声明了 queries 的应用会进入「按声明过滤」的模式。一旦过滤生效，`getApplicationInfo("com.mxtech.videoplayer.pro")` 会抛 `NameNotFoundException`，**装了 MX/VLC/Kodi 也检测不到、也吊不起来**
- 修法：把 5 个包名补进 `<queries>`
  ```
  com.mxtech.videoplayer.pro / com.mxtech.videoplayer.ad   (MX)
  xyz.re.player.ex                                        (Reex)
  org.xbmc.kodi                                           (Kodi)
  org.videolan.vlc                                        (VLC)
  ```
  （「附近TVBox」不走包名检测，读的是配置，不需要声明）
- 代价：**零**。`<queries>` 只影响「能不能看见某个包」，不申请权限、不改运行时行为、不触发商店审核问题

> **可验证性**：你第 5 条的 MX 现象已经证明「至少在当前状态下包是能看见的」（否则早就不显示 MX 了）——等等，恰恰相反，**当前 MX 因为 `enabled=false` 被过滤，我们无法从这次现象判断可见性是否正常**。所以 D 是「无法自证但必须补」的防御性修改，补了只有好处。

## 3. 气泡（悬浮提示）全清

**来源已用反编译实证**：Material 1.4.0 的 `NavigationBarItemView` 会调 `TooltipCompat.setTooltipText(this, 菜单标题)`；Android 14 上这就是你看到的长按灰色小气泡。另外 5 个图标是靠布局里的 `contentDescription` 出气泡的。

全部 7 处（一个不漏）：

| # | 位置 | 触发它的文本 |
|---|---|---|
| 1 | 底部导航「首页」 | `menu/main_bottom_navigation.xml` title |
| 2 | 底部导航「我的」（你说的"设置"） | 同上 |
| 3 | 播放页 旋转按钮 | `player_vod_control_view.xml:77` |
| 4 | 播放页 投屏按钮 | `player_vod_control_view.xml:323` |
| 5 | 详情页 投屏按钮 | `activity_detail.xml:103` |
| 6 | 详情页 下载按钮 | `activity_detail.xml:220` |
| 7 | 订阅列表「更多操作」/ 分享弹窗「二维码」 | `item_subscription.xml:39`、`dialog_share_subscription.xml:26` |

**清法**：对以上每个 View 调 `setTooltipText(null)`（底部导航那两处需遍历 `BottomNavigationView` 的子 View，并在菜单变化后再清一次兜底）。

**只清气泡，不动功能**：长按该干的事（旋转按钮的长按、播放器的长按菜单等）**全部保留**；也**不删 `contentDescription`**（那会连带破坏无障碍描述，得不偿失）。

**风险**：极低。唯一要注意的是——如果清完后某处仍弹，说明那个气泡不是 `tooltipText` 来的，我再单独定位（不会硬猜）。

## 4. 本地播放页死代码：本轮**零删除**

你说了「宁愿先保留」，我完全同意，而且查到的事实支持这个判断——**牵连面比看上去大**：

| 文件 | 被谁引用 | 能否安全删 |
|---|---|---|
| `VideoListActivity.kt`（本地视频列表页） | **只有 manifest**（全工程无任何启动点） | 孤点，但删它要先从 manifest 摘掉 |
| `LocalPlayActivity.java` | manifest + `LocalVideoController` + `VideoListActivity` + 布局 | 依赖链中段 |
| `LocalVideoController.java` | 只有 `LocalPlayActivity` | 依赖孤点 |
| `LocalVideoAdapter.java` | 只有 `VideoListActivity` | 依赖孤点 |
| `VideoInfo.java` | **7 处**：含 `PlayService`、`FolderAdapter`、`VideoFolder` | **不能乱删**，它被别的功能用着 |
| `PlayService` / `FolderAdapter` / `VideoFolder` | 互相引用 + 被 VideoInfo 牵连 | **必须保留** |

**结论**：能删的是一个「孤岛」（列表页 → 播放页 → 本地控制器/适配器 四个文件 + 两处 manifest 声明 + 若干布局），但删了**不影响任何用户可见功能**（入口本来就不可达），而删错的代价是编译不过或运行时崩溃。

⇒ **本轮不动**。清单已经列好，你若想要"干净一点"，我可以在**下一次**单独做一轮纯删除（独立构建、独立验证，不和功能改动混在一起，出问题好回退）。**你也可以直接说"不删"，那就永远不动它。**
