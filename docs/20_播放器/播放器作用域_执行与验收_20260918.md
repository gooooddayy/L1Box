## 二、关键设计：为什么要加 `plt` 标记

旧判据是「配置里有没有 `pl`」，它是坏的：控制条上**任何**按钮（比例 / 速度 / 起播跳转）都会把整份配置（含 `pl`）写回历史 ⇒ 用户只是调了下比例，这片子的播放器就被永久固化，之后改设置页默认再也影响不到它。

新判据是显式标记 `plt`（写进配置 json）：

- **打标记**：手动切播放器的三个入口（控制条短按、控制条弹窗、详情页弹窗选内置）；
- **不打标记**：比例 / 速度 / 起播跳转的时间写入、以及**播放失败时的自动兜底换内核**（`switchToNextInternalPlayer`）；
- 进播放页时 `plt != 1` ⇒ 播放器与解码档重新跟默认走。

## 四、兼容与边界

1. **换线路的正确性**：`playFragment.setData()` 全工程只有一处调用（`jumpToPlay`），换线路/换集必经它 ⇒ 按 `playFlag` 取存档天然成立，**未改动换线路逻辑本身**。
2. **换到没存档的新线路**：`isLegacyOnlyCfg()` 要求"整张线路表为空 + 有影视级配置"才算升级前老记录 ⇒ 不会把上一条线路的播放器选择搬到新线路（避免串味）。
3. **升级前老数据**：`pl` 与当前默认（或站点默认）一致 ⇒ 视为"只是调过比例带出去的值"，继续跟默认走；不一致 ⇒ 视为当年手动选的，认领为该线路存档并打标记，**不冲掉**。判不出来时按手动处理。
4. **外部吊起的"退回"**：退回的是**当前线路配置**（没手动切过时＝设置页默认）。手选过 Exo 就还是 Exo，不会被冲掉。
5. **站点默认**：`defaultPlayerType(sourceBean)`＝站点指定优先、其次设置页默认；且**不做归一化**，设成外部真的会用（吊不起来在 `startPlayUrl` 里回退内置）。
