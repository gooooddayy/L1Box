## TVBox(竖版 FreeBox) APK 签名兼容性修复 — 最终结论

### 设备情况
用户设备安装失败 → 报"安装包没有签名文件" → 实为 **Android <7.0**(只认 v1/JAR 签名,不认 v2)。

### 根因(最终定位)
1. **AGP 默认 v1 用 SHA-256 摘要**:`com.github.tvbox.osc` v1.1.1 的 manifest minSdk=24,AGP 构建出的 v1(JAR)签名用 SHA-256。Android <7.0 的 JAR 校验器**只认 SHA-1 的 v1** → 读不懂 SHA-256 的 v1 → 报"没有签名文件"。
2. 原始签 v2-only(minSdk 24 默认)→ 老设备直接不认 v2。
3. APK 内有一个文件名乱码资源(`assets/js/lib/µ¿íµ¥┐.js`,构建产物中文名变乱码),会让 JAR 签名器逐条清单出错 → 已改名为 ASCII(`plugin_renamed.js`)。
4. Gradle 产出 APK 条目带 Unix POSIX 属性(create_system=3)→ 重打包时清掉。

### 最终可用修复(已密码学验证有效,交付物已生成)
用 **apksigner 强制 v1 用 SHA-1** + 保留 v2/v3:
```
# 1) 从 AGP 已签名 APK 出发, Python 重打包清 POSIX + 改乱码文件名为 ASCII
#    (ZipInfo: external_attr=0, create_system=0, extra=b'')  保留原文件名字节
# 2) zipalign 先对齐
zipalign -p 4 <ascii_base>.apk <aligned>.apk
# 3) apksigner 签 v1(SHA1, 靠 --min-sdk-version 17 强制) + v2 + v3
apksigner sign --ks TVBoxOSC.jks --ks-key-alias TVBoxOSC \
  --ks-pass pass:TVBoxOSC --key-pass pass:TVBoxOSC \
  --v1-signing-enabled true --v2-signing-enabled true --min-sdk-version 17 <aligned>.apk
```
- `--min-sdk-version 17` 是关键:apksigner 默认 minSdk≥18 时 v1 用 SHA-256;强制 17(<18)才用 **SHA-1**,正好老设备可识别。
- 结果: v1(SHA-1) + v2 + v3 三签齐全。

### 验证要点(重要坑)
- **apksigner verify 会报 `v1 scheme: false`,但这是误报**(因强制的 --min-sdk-version 17 与 manifest 的 minSdk 24 不一致,apksigner 校验逻辑判定 v1 不适用);v2/v3 仍 true,整体 `Verifies`。
- **权威验证法**:用 Python 重算 APK 内每个非 META-INF 条目的 SHA-1,与 `META-INF/MANIFEST.MF` 的 `SHA1-Digest` 逐条比对(本例 1099/1099 全吻合)、`.SF` 的 `SHA1-Digest-Manifest` 匹配 MANIFEST 整体字节、`.RSA` 证书存在 → 证明 v1 密码学有效,Android JarVerifier 必接受。
- **jarsigner 路线不可靠**:jarsigner 对本 APK 报 `nonexistent signed entries`(Python zip 与 jarsigner 校验器在条目名匹配上的系统性怪异,纯 ASCII 也中招),且其重签会剥离 apksigner 的 v2。**不要用 jarsigner 修此包。**
- 对齐顺序:**先 zipalign 再签名**(签名必须最后一步);先签后对齐会破坏 v1 摘要。

### 交付物
`FreeBox-src/app/build/outputs/apk/release/MBox_v1.1.1_release_20260823_signed.apk`
- v1(SHA-1) + v2 + v3,4 字节对齐(zipalign -c 通过),包名 `com.github.tvbox.osc` v1.1.1,原生库含 arm64-v8a/armeabi/armeabi-v7a/x86/x86_64。

### 注意
- `app/build.gradle` 的 `signingConfigs` 目前 `v1SigningEnabled true; v2SigningEnabled true`,但 AGP 仍会用 SHA-256 做 v1 → **直接 assembleRelease 产出的 APK 在老设备仍装不上**,必须走上面的 apksigner 重签流程。
- 关键路径: JDK11 `<工作区>/dl/jdk11/jdk-11.0.32+9`(gradlew.bat 必须 `C:/` 格式);SDK `<本机>/AppData/Local/Android/Sdk`;build-tools 33.0.2。

## 本地订阅"重启循环"崩溃修复 (2026-08-23 后续)

### 现象
用户加载本地订阅(`clan://localhost/...` 文件)后,App 反复重启/崩溃循环,无法进入。

### 根因(最终定位)
`ApiConfig.parseJson()` 解析配置时,第 315 行 `infoJson.get("sites").getAsJsonArray()` **未判断 `sites` 是否存在**。用户手选的本地订阅配置文件(或格式/内容不对)常常**没有 `sites` 数组** → 该行直接 **NPE 且不在任何 try 内** → `HomeFragment` 启动即崩 → 自定义崩溃助手(customactivityoncrash, `App.java` 配置 `restartActivity(MainActivity.class)`) + 系统反复重启 App → "重启循环"。坏的 `clan://` 地址已存入 `Hawk(API_URL)`,每次启动都崩。
- 仅"本地订阅"触发:在线订阅通常含 `sites`,且崩溃是本地特有(启动期对 clan URL 的处理)。
- 注:`parseJson` 里 `parses`/`rules`/`lives` 也有类似隐患(`has()` 后未校验 isJsonArray,或 `lives` 未 `has()` 直接 getAsJsonArray)。

### 修复(已构建验证)
`FreeBox-src/app/src/main/java/com/github/tvbox/osc/api/ApiConfig.java`:
1. `sites` 循环加 `if (infoJson.has("sites") && infoJson.get("sites").isJsonArray())` 包裹;逐字段 `obj.has("key"/"name"/"type"/"api")` 判空,空 siteKey 不入表。
2. `parses`、`rules` 同样加 `isJsonArray()` 校验。
3. `clanToAddress()` 加 null/无 `/` 兜底(避免 `getAddress(true)` 返回异常);`convertResponse()` 整体包 try/catch(失败返回空串,转 error 提示而非崩溃)。
`ControlManager.getAddress()` 加 `mServer == null` 兜底返回默认地址。

效果:本地订阅无论格式如何,**最多弹"解析配置失败"提示,绝不再崩溃循环**;用户可经错误提示回到订阅页换正确配置。

### 交付物(重要更正: 见下)
AGP `assembleRelease` 产出的 `MBox_v1.1.1_release_20260823.apk` 是 **v2-only**(`v1 scheme: false`),**不能直接交付**——用户设备是 **Android <7.0**(最初"没有签名文件"即铁证;能装上并跑到本崩溃的也是此前手签的 v1-SHA1 版)。崩溃修复版必须用 apksigner **重签补 v1(SHA-1)**:
```
zipalign -p 4 <v2only>.apk <aligned>.apk
apksigner sign --min-sdk-version 17 --v1-signing-enabled true --v2-signing-enabled true \
  --v3-signing-enabled true --ks TVBoxOSC.jks --ks-key-alias TVBoxOSC \
  --ks-pass pass:TVBoxOSC --key-pass pass:TVBoxOSC --out <signed>.apk <aligned>.apk
# 验证必须用 --min-sdk-version 17 模拟老设备, 才会显示 v1 scheme: true
apksigner verify --verbose --min-sdk-version 17 <signed>.apk   # 期望 v1=true v2=true v3=true
```
- 最终交付物 = `MBox_v1.1.1_release_20260823_signed.apk`(**v1(SHA-1)+v2+v3, 含崩溃修复**),已清掉 v2-only 中间包。`--min-sdk-version 17` 强制 apksigner 用 SHA-1(默认 minSdk≥18 用 SHA-256, 老设备拒认)。
- ⚠️ 教训: 切忌把"能跑起来报崩溃"误判成"设备 ≥7.0"。能运行只说明装的是 v1-SHA1 旧包,不代表 v2-only 新包能装。所有给用户(老设备)的包, 必须走 apksigner --min-sdk-version 17 重签 + `--min-sdk-version 17` 校验 v1=true。

### ⚠️ 构建机内存环境坑(重要, 每次构建前必看)
- 构建机 **16GB RAM 且无页面文件**,用户常开壁纸/音乐/微信等,**已提交内存常达 ~15GB,仅剩 <1GB 提交余量**。
- Gradle 编译 TVBox 需 ~3GB 提交余量 → 直接构建会因 daemon 被系统 OOM 杀掉(现象:`os::commit_memory failed` / kryo `connection forcibly closed` / `Insufficient memory malloc`)。
- **构建前必须先释放内存**:关掉占内存的后台程序。实测 `twinkstar`(动态壁纸, 会 spawn 50+ 进程, 占 ~2GB 提交)、`SodaMusic`(音乐)、`DeskDynamicWallpaper64`、`360tray` 关掉后提交余量从 ~900MB 升到 ~4.9GB,构建即通过。用 `taskkill /F /IM <名>.exe`(Bash 里可执行;PowerShell 在内存极紧时会自身 OOM 起不来)。
- `gradle.properties` 已调为 `org.gradle.jvmargs=-Xmx3072m -XX:MaxMetaspaceSize=512m`、`org.gradle.parallel=false`、`org.gradle.workers.max=1`(避开 4096m 起不来 / 2048m 编译爆 的中间地带)。
- 注:本机无页面文件,加虚拟内存需重启生效,一般不走这条路。
