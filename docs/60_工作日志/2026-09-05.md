## 首页加载闪退修复（加载源后易闪退）
- 根因：onResume 每次切回首页都 `removeCallbacksAndMessages(null)` + 全量重置三标志 + 提前把 mReloading 置 false，导致两次 loadConfig 并发，`ApiConfig.parseJson` 里 `sourceBeanList.clear()+put()` 被撕裂，取站点拿半空 Map 触发 NPE 闪退。
- 修复（HomeFragment.kt）：
  1. onResume 删掉 removeCallbacksAndMessages(null)；新增 mLoadInFlight 在途标记，与 mReloading 共同防重入；不再提前解锁。
  2. mLoadInFlight 在 sortResult observer / forceFinishHomeLoad / startHomeLoad 空源分支释放。
  3. reloadSitePool 也置 mLoadInFlight，两路共用锁。
- 修复（ApiConfig.java）：parseJson 拆出 parseJsonInternal，用 `synchronized(sourceBeanList)` 串行化 clear+put，防并发撕裂。
- 构建坑（重要）：改了 ApiConfig.java 后触发了 Kotlin+Java 联合编译，暴露了历史遗留问题——`sourceBeanList`/`ijkCodes` 字段 private 但 FastSearchActivity/SettingActivity 用 `.sourceBeanList`/`.ijkCodes` 属性访问。正确解法是保持 private（Kotlin 属性访问自动映射到 getSourceBeanList()/getIjkCodes() 这两个 public getter），**不能**改成 public（会变成 Map 类型对不上）。之前误改 public 又回退。

## 多仓切换源点击即崩（commit 9f5c0b3）
- 现象：订阅管理里点"切换影视源"（或"使用源"胶囊）直接弹 CaocConfig 崩溃页（showRestartButton(true)，显示"重启"按钮）。
- 排查：静态分析 + 反编译 XPopup 2.10.0 全链路（show→attachToHost→initPopupContent→onCreate 顺序正确，先 inflate 后 onCreate，findViewById 不会 null）+ 实测 Gson 2.8.6 反序列化行为。
- 关键结论：Gson 反序列化用 Unsafe 绕过构造，**显式 `"lines":null` / `"activeLineUrl":null` 会反序列化成 null**（字段初始化器对显式 null 不生效）。这是最可能的运行时 NPE 来源。
- 防御性修复（3 处）：
  1. Subscription.getLines()/getActiveLineUrl()/getEffectiveUrl() 对 null 兜底（空集合/空串）。
  2. openLinePickerForMultiRepo 选到空线路不写入（对齐 HomeFragment 的"绝不写空 API_URL"防护）。
  3. ChooseSourceDialog.onCreate 里 getActivity() 判空，避免 LinearLayoutManager(null)。
- 未 100% 定位确切崩溃栈（无设备 logcat、无崩溃详情截图），需用户提供 CaocConfig error details 才能精准锁定。
- 产物：L1Box_v1.1.1_release_20260905.apk（64,391,556 字节）。
## 多仓切换源点击即崩——真因定位（ShadowLayout ripple NPE）
- 用户给到 CaocConfig 完整崩溃栈，根因**不是 commit 9f5c0b3 的 Gson null**，而是布局期 NPE：
  - `Binary XML file line #2: com.github.tvbox.osc:layout/item_source`
  - `Caused by: java.lang.NullPointerException: 使用了ShadowLayout的水波纹，必须设置hl_layoutBackground属性`
  - `at com.lihang.ShadowLayout.initAttributes(ShadowLayout.java:304)`
- 排查路径：grep 全工程 12 处 ShadowLayout 用法，**只有 item_source.xml** 用了 `hl_shapeMode="ripple"` 且没配 `hl_layoutBackground`；其他 selected/默认模式都已正确配背景。
- 修复：`app/src/main/res/layout/item_source.xml` 第 10 行删 `app:hl_shapeMode="ripple"`（TextView 自带 background+点击响应，不依赖 ripple）。
- **教训（重要）**：commit 9f5c0b3 的 Subscription null 兜底并非无用，仍是有效防御（防 Gson 显式 null），但**真正崩溃栈在 layout inflate 阶段**，不在 Java 代码路径上。往后 CaocConfig 报错一律先看堆栈最顶层 cause，不要被表象"Gson 反序列化"误导。
