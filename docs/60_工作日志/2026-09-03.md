### 难度评估结论：固定豆瓣热播**不值得继续修**
依赖链 5 环，任一断首页就没数据：
`内置 csp_home.jar` → `localhost /l1home 路由` → `外置 CDN txt（在线）` → `filesDir 缓存` → `assets 快照`
外加：豆瓣 spider 是第三方黑盒 jar；豆瓣只提供片单，点击后仍要跳搜索页用订阅站点搜 → **首页内容与播放能力割裂**。

### 排查出的 4 个真实卡死点（都已修）
1. **`onPause()` 里 `mHandler.removeCallbacksAndMessages(null)`**（最隐蔽）
   会连带清掉 `initData` 的 `postDelayed(50ms)` → 从其他页面返回后 `initData` 永不再执行 → **永久停在 loading**。
   改为只 `cancelHomeWatchdog()`。
2. **`spider` 为 null 时 NPE**：`private String spider = null;`（ApiConfig:74），只有 `parseJson` 执行后才非空。
   `loadConfig().success()` / `reloadSitePool().success()` 里的 `ApiConfig.get().spider.isEmpty()` 会 NPE → 回调中断 → initData 不再调用。
   全部改为 `spider.isNullOrEmpty()`。
3. **`spider` 为空时 `loadJar()` 无任何回调**：`loadJar()` 整体包在 `if (!spider.isNullOrEmpty())` 里，为空则静默返回，`jarInitOk` 永远 false → 死循环停在 loading。
   在 `initData` 的 `dataInitOk && !jarInitOk` 分支里前置判断：spider 空 → 直接 `jarInitOk=true; startHomeLoad()`。
4. **无总超时兜底**：任何一环回调不来就无限转圈。加 25s 看门狗强制结束加载态 → 明确空状态。

### 改造方案：首页 = 站点推荐（自动调用源站点信息）
**关键杠杆（改造能如此干净的原因）**：
`SourceViewModel.getList()` 硬编码用 `ApiConfig.get().getHomeSourceBean()`（第 238 行）。
→ 只要把首页源**指向订阅站点**，`getSort()`（分类）和 `getList()`（列表）会**自动一起切换**，无需改任何方法签名。

- `ApiConfig.setHomeSite(SourceBean)`（新增）：只设 `mHomeSource`，**不写** `HawkConfig.HOME_API`（避免污染订阅侧首页源选择）。
- `HomeFragment.startHomeLoad()`：构建候选站点列表 → 逐个尝试。
- `buildHomeSiteCandidates()`：当前线路站点列表（`getSourceBeanList()`）+ 末尾追加内置首页源兜底，`take(8)`。
- **顺延机制**：observer 里若 `sortList` 为空 → `tryNextHomeSite()` 自动换下一个站点重试（一条线路通常多站点，任一可用即可）。
- **看门狗 25s**：`forceFinishHomeLoad()` 强制 `showSuccess()` + 空状态 + Toast。
- `adjustSort(..., withMy=false)`：不再强制插入 `my0`（固定"主页/豆瓣热播" tab）。
- `initViewPager()`：全部标签用 `GridFragment`，**不再有 UserFragment（豆瓣热播）**。
- 切线路后（`reloadSitePool` / `loadJar` success+error）重新 `startHomeLoad()`，首页内容随线路刷新。

`getCSP()` 分流逻辑天然正确：站点来自 `sourceBeanList` → `homeSiteList.get(key)==sourceBean` 为 false → 走订阅 spider `jarLoader`；只有内置豆瓣源（在 homeSiteList）走 `homeJarLoader`。

## 追加：加载链路全链路加固（自检发现的遗漏）
完成删除死代码后，我又做了一次"卡死路径审查"，发现看门狗**只覆盖 `startHomeLoad()` 阶段**，`loadConfig`/`loadJar` 阶段裸奔。已加固：
1. 看门狗提前到 `initData()` 的 `showLoading()` 后启动（覆盖 内置配置→订阅→jar→取数 全链路）
2. `reloadSitePool()`（切线路/长按刷新入口）起步也启动看门狗 + `showLoading()`
3. `loadJar` 的 `retry()` 原本是空实现 → 补齐 `jarInitOk=true` + `initData()`（否则一旦被回调就永久停在加载态）
4. 看门狗 25s → **30s**：单站点最长 15s，25s 会在第二个站点出结果前判定超时，浪费顺延机会
5. 候选站点 `take(8)` → `take(3)`（每站点最长 15s，试太多会拖长等待，且失败站点往往成片失效）
6. `onPause()` 不再取消看门狗（加载中切走再回来仍需它兜底），只在 `onDestroy()` 取消

构建 exit 0，三道闸门全过。产物 65,428,881 字节（13:09），仍是唯一 APK。git：`498771f`
