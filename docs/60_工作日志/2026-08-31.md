## #8 DLNA 投屏（已落盘 + 编译 + 重新签名交付，最终版）
目标：#8 在播放器加投屏按钮，搜局域网设备并推送视频。
决策：**零第三方依赖**实现（避免 cling 重依赖破坏已验证构建）。SSDP 发现用 `MulticastSocket`，AVTransport 控制用 `HttpURLConnection` 发 SOAP。Manifest 早已具备 INTERNET / ACCESS_NETWORK_STATE / ACCESS_WIFI_STATE / CHANGE_WIFI_MULTICAST_STATE，无需改权限。
改动文件：
- 新 `bean/DlnaDevice.java`：设备模型（name/location/controlUrl/ip，equals 按 controlUrl/location）。
- 新 `util/DlnaManager.java`（单例 + ExecutorService + 主线程 Handler）：
  - `discover(ctx, timeoutMs, cb)`：WifiManager.MulticastLock 获取 → MulticastSocket(0) join 239.255.255.250:1900 → 发 2 次 M-SEARCH(MX:3, ST=MediaRenderer:1) → 收响应解析 LOCATION → GET 描述 XML → 取 friendlyName + AVTransport 的 controlURL（正则 `<service>` 内匹配 serviceType 含 avtransport）→ 解析为绝对地址 → 主线程回调 List<DlnaDevice>。
  - `cast(device, url, title, cb)`：SOAP SetAVTransportURI（带 DIDL-Lite metadata，mime 按扩展名猜测，默认 video/*）+ Play(Speed=1)；SOAPACTION 头 `urn:schemas-upnp-org:control:AVTransport:1#Action`；超时 5s。
- 新 `ui/dialog/CastDialog.java`（XPopup CenterPopupView，复用 `dialog_cast.xml` 的 rv + 刷新）：进入即 `discover(4000)`，点设备回调 `OnDevicePickedListener.onPick`；内嵌 `DlnaAdapter`（RecyclerView，item_dlna_device.xml）。
- 新布局 `res/layout/item_dlna_device.xml`（tv_name + tv_ip）；新矢量图标 `res/drawable/ic_cast.xml`（Material cast 图标，控制条用 app:tint=@color/white）。
- `res/layout/player_vod_control_view.xml`：底部按钮行 background_audio 后新增 `iv_cast`（34dp，同风格）。
- `player/controller/VodController.java`：`initView()` 给 iv_cast 绑 `listener.cast()`（VodControlListener 已有 cast() 钩子）。
- `ui/fragment/PlayFragment.java`：原空 `cast()` stub 实现——取 `getFinalUrl()`（=mCurrentUrl，无则提示"当前没有可投屏的视频"）；标题取 mVodInfo.name+当前集 vs.name；弹 `CastDialog(activity, device -> DlnaManager.get().cast(device, url, title, cb))`，回调 Toast "已推送到 xxx" / "投屏失败：xxx"。import 加 CastDialog / DlnaManager。

初版把投屏按钮放进直播播放器右侧菜单 `PlayerMenuView`（`dkplayer_layout_menu_view.xml`）+ `LiveNewController` 的 `OnPlayerMenuClickListener.onCast()`。但验证发现：直播播放器是 **非全屏** 布局（`activity_live.xml` 里 VideoView 仅占顶部约 300dp，下方是频道列表），`LiveActivity` 从不调用 `mVideoView.startFullScreen()`，播放器始终处于 `PLAYER_NORMAL` 状态；而 `PlayerMenuView` 的显隐被 `onVisibilityChanged`/`onPlayerStateChanged` 里的 `mControlWrapper.isFullScreen()` 门控——所以那个菜单在直播里是**永不显示的死 UI**（原 fork 的 expand/setting 按钮同样失效）。直播播放器的真实可用控件是 `activity_live.xml` 里的活动级 `ic_setting`/`ic_pre_source`/`ic_next_source`（EPG 栏）。

## 构建/签名坑（本轮修正，补进记忆）
- 本机 build-tools 的签名工具是 `apksigner.bat`（非 `apksigner`）；Git Bash 直接调 `apksigner` 会 command not found（exit 127），必须用 `apksigner.bat` 全名。`zipalign` 则是 `zipalign.exe`，可直接调用。
- 链路：`zipalign -p 4 in.apk aligned.apk` → `apksigner.bat sign --min-sdk-version 17 --v1/v2/v3-signing-enabled true --ks TVBoxOSC.jks --ks-key-alias TVBoxOSC --ks-pass pass:TVBoxOSC --key-pass pass:TVBoxOSC aligned.apk` → `apksigner.bat verify --verbose --min-sdk-version 17 aligned.apk`（须 Verified + v1/v2/v3 全 true；META-INF 一堆 WARNING 是 AGP 元数据，可忽略）。
- **新坑（zipalign 长文件名）**：构建产物名 `L1Box_v1.1.1_release_20260901.apk`（跨午夜日期）直接喂给 `zipalign.exe` 会报 `Unable to open '...apk' as zip archive`（但 Python zipfile 能正常打开，文件没坏）。** workaround**：先 `cp` 成短名 `in.apk` 再 `zipalign -p 4 in.apk out_aligned.apk`，再 apksigner 签名。构建原始名仍可能跨午夜变 `..._20260901.apk`，但最终产物统一覆盖为 `L1Box_v1.1.1_release_20260831_dlna_signed.apk`。
