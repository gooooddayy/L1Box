## 15:00~15:15　第七批 az：全量审查（用户："检查有没有问题、流程是否清晰、是否有 bug、是否引入新问题"）

**审查方法**：把 10 个"会动手干预"的机制逐个读实现 + 逐个问"它会不会在源本来能播的情况下动手"；再沿"最坏等待"这条线把判死点与预算判据算了一遍。

**结论：机制本身没有误伤正常源的判据（0/10），但发现 2 个真 bug + 1 个健壮性缺陷，已全修。**

1. **P0 本集预算形同虚设**：预算判据是"当前是否已超预算"，而判死点固定在 **32/64/96 秒**（每次降级重播都重新布防 20+12s）⇒ **65 与 90 都卡在 64 与 96 之间，一次降级都拦不住，最坏等待始终 96 秒**。ax 那批「90→65」是**无效果改动**，且注释声称"最坏 96 秒太长"与行为不符（这正是它长期没被发现的原因）。**修**：判据改成 `elapsed + 20s + 12s > 预算`（含下一个完整窗口），取值 **70s**（= 一次降级 + 一个窗口 64s，另留 6s 给取链/起播开销）⇒ 允许一次降级、**最坏 64s**。
2. **P0 预算用尽后仍会再开一个 32 秒窗口**：预算用尽那一支走 `errorWithRetry` → `autoRetry` → 又排一次重新取链 = 又布防一次 32s 看门狗。此前只被 `autoRetry` 内那个 8s 取链预算**巧合**挡住（elapsed 早已 >8s），一旦有人调那个值，最坏立刻弹到 160s。**修**：新增终态出口 **`errorFinal(String err)`**——显示形态与 `errorWithRetry` **完全一致**（同一个 `setTip(err,false,true)`），唯一区别是**不触发自动重取**；用在"预算用尽"与"起播兜底全试尽"两处。**没有恢复被废除的 `finish` 参数**（那是"只弹 Toast 不关浮层"，与"是否重试"是两件事）。
3. **P1 排队中的退避重取无法取消**：Runnable 里只比对集标识，用户**在同一集**点「重试」时集标识没变 ⇒ 队列里那次照跑，与刚发起的那次**撞成两个并发取链**（正常流程下"显示提示"意味着队列已空，所以此前只是"靠巧合安全"）。**修**：加 **`mRetryGen` 代次**，换集 / 手动重试 / 主动重播三处自增，Runnable 比对代次不等即作废。

**闸门**：净增 3 条语义断言（预算判据含下一窗口 / 必须有 `errorFinal` 且预算用尽必须走它 / 重取必须按代次作废）→ **314 条全绿**；**又清掉 1 条"锁死日志文案"的旧断言**（`本集自动尝试预算用尽`，文案一改闸门就红）——这是第 5 条同类教训。

## 16:11　用户提新方向：提高"播放器对直链的解析能力/兼容性" —— **只讨论，代码一行未改**

**用户原话要点**：提高播放器对链接的解析能力、对多种直链的解析，目的提高兼容让视频尽量播出来；问 ① 有没有必要 ② 是不是很多播放器写死了 ③ 会不会触动播放器风控 ④ 有没有其他三方播放器能提高兼容 ⑤ 市面大部分播放器配什么、怎么配。要求"先商量方案"。

**侦察到的关键事实（带出处，供后续复用）**：

1. **播放器清单**（`util/PlayerHelper.java`）：内置 0 系统 / 1 IJK（硬解 100、软解 101 拆成两项）/ 2 Exo；外部 **10 MX / 11 Reex / 12 Kodi / 13 附近TVBox / 14 VLC**。短按只在内置三档循环（`getBuiltinItems`：Exo→IJK硬→IJK软），外部**只在长按菜单**（避免误唤起）。
2. **自动换内核已存在**：`PlayerHelper.buildCompatFallbackPlan()` = IJK 软解 → Exo（与当前档相同则跳过），每集重置。触发链 `PlayFragment.errReplay()`：换地址 → `fallbackToRawUrl` → `retryVariantUrl` → `compatFallback` → `errorFinal`。**市面多数 fork 只有手动切，没有自动降级 ⇒ 我们这点在主流之上。**
3. **直链判定写死**：`SourceViewModel.getPlay():728` 用 `DefaultConfig.isVideoFormat(url)`，实现是 `DefaultConfig:112-136` 的**正则白名单**（只认 .m3u8/.mp4/.flv/.avi/.mkv/.rm/.wmv/.mpg/.m4a + 少量平台特征）。**没命中 ⇒ 一律推去走解析**（type 0 普通嗅探 = `PlayFragment.doParse` 里 WebView + `sendEmptyMessageDelayed(100, 20*1000)`，最长白等 20 秒）。
4. **协议相对地址被硬补 http**：`PlayFragment.jsonParse():2225` `if (url.startsWith("//")) url = "http:" + url;` ⇒ https-only CDN 失败。同行 2228 非 http 直接 `return null`（magnet/ed2k 走 Thunder 通路，不受影响）。
5. **UA/Referer 前导空格**：`jsonParse():2234/2238` 写的是 `headers.put("User-Agent", " " + ua)`（上游遗留）。Exo 侧 `ExoMediaSourceHelper.createHttpDataSourceFactory` 会 trim，**IJK 侧不 trim** ⇒ 两边不一致。
6. **IJK `protocol_whitelist`（`player/IjkMediaPlayer.java:99`）里没有 `rtmp/rtmpt`** ⇒ RTMP 直链会被 FFmpeg 拦掉。Exo 侧有 `RtmpDataSource`（`ExoMediaSourceHelper:87`，scheme==rtmp 时生效）与 `RtspMediaSource`（:90）。

8. **订阅规则通路已存在**：`VideoParseRuler.addHostRule/addHostFilter`（`ApiConfig:840-880` 从订阅 `rules/filter` 装载）、`checkIsVideoForParse`（`PlayFragment:2547` 嗅探时用）⇒ "对多种直链的解析"其实有订阅侧可扩展的钩子。

- **必要性：有，但预期要压低。** 依据 av 全场景 43 次点播 7 次失败的构成：源站空返回 2 / 网盘本地代理 2 / 非 http 伪地址 3 —— **0 次是"地址能播但播放器或解析不认"** ⇒ 解析侧改动对当前成功率直接影响 ≈ 0，修的是"结构性潜在失败面"。

2. **悬浮提示＝Material 自带长按 tooltip（反编译实证）**：`classes2.dex` 中 `NavigationBarItemView.initialize()` 调用 `TooltipCompat.setTooltipText(this, tooltip)`（Material 1.4.0，`app/build.gradle:103`），Android 14 上长按即弹灰气泡。**全工程能弹气泡的地方只有 6 处**：底部导航「首页/我的」（`navigation_home`/`navigation_dashboard`，content-desc 由 menu title 来）、播放页「旋转」「投屏」、详情页「投屏」「下载」（后四者靠 layout 里的 `contentDescription`）。**取消办法**：`TooltipCompat.setTooltipText(v, null)`；底部导航每次切 tab 后 Material 会重建 item view ⇒ 需补清一次。**不动任何点击/长按功能**。（另：`TabLayout$TabView`、`NavigationMenuItemView` 也有该调用，本项目未用。）
3. **本地播放页＝本地视频播放页，整条链已不可达**：`VideoListActivity`（本地文件夹列表）**全工程无任何启动点**（只在 manifest 注册），`LocalPlayActivity` 只由它启动 ⇒ **事实移除**。所以 bb/bc 轮里我对本地播放页播放器列表的收口**无任何可感知影响**。
4. **设置页应有 MX**：`getAvailablePlayerTypes()` = 系统+Exo+IJK+已装外部（实时查、不缓存）；MX 识别含 `.pro`/`.ad`（`MXPlayer.java:20-21`）；设备 `pm list packages` 确有 `com.mxtech.videoplayer.pro` 且未停用。**待用户确认**：① 看的是旧版 bb（bb 只列内置）② 打开的是设备上另一个包 `com.github.tvbox.osc.jun`（v20260819-1640，8/23 装，不是我们的包）③ 看的不是"默认播放器"项。
5. **设备环境补充**：Android **14（API 34）/ 机型 测试机**；`com.github.tvbox.osc`=bc（`da5df7ab…` 一致）；另有 `com.github.tvbox.osc.jun`（`dfe8e73c…`）易混淆。
