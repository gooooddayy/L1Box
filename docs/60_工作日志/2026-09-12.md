## 2026-09-12 L1Box：Exo 缓冲水位方案定稿（未动代码）

**反编译实证（exoplayer-core-2.18.7.aar，javap）——推翻上一轮的"默认 12.5MB"说法**：
- `ExoPlayerImplInternal.prepareInternal()` 先调 `LoadControl.onPrepared()` → 无 overwrite 时
  `targetBufferBytes = 13107200`（12.5MB）；随后 `handlePeriodPrepared()` → `updateLoadControlTrackSelection()`
  → `onTracksSelected()` → `targetBufferBytes = calculateTargetBufferBytes()` = **视频125MB+音频12.5MB=137.5MB**
  （`getDefaultBufferSize` tableswitch：AUDIO(1)=12.5MB、VIDEO(2)=125MB、其余=128KB）。**稳态是 137.5MB。**
- 默认 `minBufferMs = maxBufferMs = 50000`（50 秒）。`shouldContinueLoading` 判停 =
  `buffered >= maxBufferUs || allocator.getTotalBytesAllocated() >= targetBufferBytes`；
  `buffered < minBufferUs` 才继续加载。**→ 现状真实水位 = min(50 秒, 137.5MB÷码率)。**
  `minBufferMs` 是"重启加载下限"，`maxBufferMs` 是"停止上限"，二者构成滞回区间（易踩坑）。
- `shouldStartPlayback`：门槛是**纯时间**（`bufferForPlaybackMs` 2500 / afterRebuffer 5000），
  且有 `(!prioritizeTimeOverSizeThresholds && allocator 满) → 也起播` 的兜底 → **水位不影响首帧**。
- 构造器 5 条断言（违反即抛 IllegalArgumentException）：`start>=0`、`afterRebuffer>=0`、
  `min>=start`、`min>=afterRebuffer`、`max>=min`；另有 `backBuffer>=0`。
- `targetBufferBytes` 是 **private 非 final**，`calculateTargetBufferBytes` 是 **protected**；
  `DefaultAllocator.setTargetBufferSize(int)` 为 public，**仅当新值<旧值才 trim()**（只释放空闲块，
  正在播放的块不动）→ 运行期降档可立刻还堆、绝不伤播放。
- `DefaultAllocator.allocate()` 无上限检查（不会抛异常）→ **"报错"只有两条路：参数断言 + OOM**。
- `AndroidManifest.xml:59 android:largeHeap="true"` → 4GB 机可用堆 ≈512MB（`getMemoryClass()` 仍报 192/256）。
- **DeviceProfile 分档盲区**：4GB 机 `getMemoryClass()`=192/256、`isLowRamDevice()`=false
  → 被判**中/高档**，不是低档。已定稿为它单开"保守档"（`MemoryInfo.totalMem <= 4.5GB`），
  且新增判定**只用于缓冲档位、不动 `tier()`**。
- 注入点：`player/.../exo/ExoMediaPlayer.initPlayer()` 的 `if (mLoadControl == null) new DefaultLoadControl()`；
  压力回落挂 `App.java:168`（TRIM_MEMORY_RUNNING_LOW）与 `:188`（onLowMemory）。

**定稿参数**（起播门槛 1500ms 全档统一；阶段一恒为现状 50 秒，10 秒后升档，靠覆写
`shouldContinueLoading` 读 `playbackPositionUs` 触发 → 无需 Activity/定时器，切集自动复位）：
低档(heap<=128/低内存/压力后) 不接管 | 保守(<=4.5GB) 150s/48MB | 标准 240s/72MB | 激进 300s/96MB。
字节闸门比 Exo 默认 137.5MB **更紧**（低码率水位变长、高码率内存反降）；升级前用
`avail = maxMemory-(total-free)` 做 `min(档位, avail/3)` 夹取。

**待用户点头**：4G 上网是否也进阶段二（每集多耗 15~20MB 流量），或仅 WiFi 进入。
方案文档：`缓冲水位方案定稿_20260912.md`。**代码未改，等确认。**
