- **根因（代码定位）**：
  1. `SourceViewModel.getSort` 第 120 行 `Executors.newSingleThreadExecutor()`（**默认 ThreadFactory → 线程名 `pool-NN-thread-1`**）；`finally` 里只 `shutdown()`（温和关闭，**不中断**正在执行的任务）；而 `future.get(15s)` 超时后 `cancel(true)` 的中断**不被 spider 的 OkHttp 同步调用响应** → 线程一直活到 spider 返回。
  2. `DetailActivity.searchResult()` 第 748 行 `Executors.newFixedThreadPool(DeviceProfile.detailConcurrency())`（同样默认 ThreadFactory）——虽已"先关旧再建新"，但 shutdownNow 同样不保证线程立即退出。
  3. `newFixedThreadPool`/`newSingleThreadExecutor` 的 **core 线程永不超时**（`allowCoreThreadTimeOut` 默认 false）→ 池不关则线程永驻。
- **为什么"我这台没事、别的设备会崩"**：8 核/11.4GB 撑得住 250 线程 + 990MB PSS；**4 核/2GB 低端机 = 线程调度抢占 + 虚拟内存压力（每线程约 1MB 栈）→ 卡顿/ANR/被 LMK 杀**。这就是"通用预备案"要覆盖的场景。
- **待甄别（诚实标注）**：`Act` 增长中**可能含脚本栈堆积成分**（日志多次出现「前台=FastSearchActivity，回首页」说明返回键未可靠关页，`to_front` 用 monkey 启动 LAUNCHER 不会清栈）。但**线程池泄漏与 Activity 栈无关，是独立的真泄漏**，不受此影响。后续需用"单次进出 + 静置 30s"最小实验区分两者。
- **兼容性审计结论（本轮）**：
  - ✅ 已达标无需动：ABI 双架构 v7a+arm64 各 14 个 so；无 GMS/Firebase 依赖（无 Google 服务设备安全）；通知渠道已建（Android 8+）；EventBus 注册/反注册 5:5 配平；网络层宽松 SSL + CLEARTEXT + 可切 DOH（腾讯/阿里/360）+ `retryOnConnectionFailure(true)`；播放层 IJK/EXO/系统三内核 + 硬软解切换 + SurfaceView/TextureView 切换；autosize `setExcludeFontScale(true)` 已规避系统字体放大溢出。
  - ⚠️ 发现缺口：① **`configChanges` 声明了 `orientation|fontScale|uiMode` 但全项目 `onConfigurationChanged` 为 0 处** → 旋转后 autosize 不重算 ② 固定 dp 高度（`dialog_checkbox_search` 450dp、`dialog_quick_search` 400dp、`activity_detail` 250dp）在横屏/小屏会溢出 ③ 缺 `FOREGROUND_SERVICE_MEDIA_PLAYBACK` 权限（targetSdk 34+ 的前瞻项，当前 targetSdk 28 不强制）④ **实际 `targetSdkVersion` 是 28 不是 30**（记忆已纠正）⑤ 本地服务器 9978 端口无鉴权（同 WiFi 可读/删文件、改订阅源）⑥ `ToastSweeper.topActivity` 为 `static Activity` 强引用（有清理逻辑，风险低）；`ControlManager.mContext` 为 `public static Context`（待确认赋的是 Application 还是 Activity）。
