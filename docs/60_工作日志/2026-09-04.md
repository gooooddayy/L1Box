## 修复：①首页每次进入都自动刷新 ②投屏一点就闪退（"出现意外错误，重新启动"）

### ② 投屏闪退 — 根因（已定位到字节码，可复现级确认）

**现象**：点投屏按钮 → 立刻弹出崩溃页"出现意外错误，重新启动"（CustomActivityOnCrash 的
`DefaultErrorActivity`，在 `App.java:160` 配置 `.restartActivity(MainActivity.class)`）。

**根因**：`CastDialog extends CenterPopupView`，三处调用都是 **直接 `new CastDialog(...).show()`**。
反编译 XPopup 2.10.0 `BasePopupView.show()` 字节码（javap -c）可见：

```
19: getfield  #44  // Field popupInfo
22: ifnonnull 35
25: new  #24       // IllegalArgumentException
29: ldc  #45       // "popupInfo is null, if your popup object is reused, do not set isDestroyOnDismiss(true) !"
34: athrow         ← 直接抛异常
```

`popupInfo` **只有 `XPopup.Builder.asCustom()` 会赋值**（已 javap 确认：
`asCustom` 内 `popupView.popupInfo = builder.popupInfo`）。直接 new + show → popupInfo 为 null →
抛 `IllegalArgumentException` → 未捕获 → 崩溃页。

**旁证**：全工程其他所有弹窗（DetailActivity / LiveActivity / LocalPlayActivity / SettingActivity /
SubscriptionActivity / FastSearchActivity）一律用 `XPopup.Builder(ctx).asCustom(dlg).show()`，
**只有 CastDialog 用了直接 `.show()`** —— 这就是它独有的崩溃原因。

**修复**：3 处调用点全部改为 `new XPopup.Builder(ctx).asCustom(dialog).show()`，并包 try/catch 兜底
（失败只 Toast"投屏暂不可用"，不再杀进程）：
- `PlayFragment.java` cast()（约 339 行）
- `LocalPlayActivity.java`（约 242 行）
- `LiveActivity.java`（约 588 行）

> 排查路径备忘：`DlnaManager` 是零第三方依赖的纯 SSDP/SOAP 实现，`discover()` 本身已跑在
> `executor` 后台线程（不是 NetworkOnMainThread），且内部 `catch (Throwable)` 会把异常转成
> error 文案回调，不会崩。所以崩溃必然在弹窗 show 之前/之中 —— 即 XPopup 这条路径。
> `dialog_cast.xml` 的 view id 与 `b.xxx` 引用也逐一对齐过，不是 NPE。

## 18:20-18:50 上下集正倒序 bug 修复 + 选集同步（commit 8f69ef2，BUILD SUCCESSFUL）

### Bug 现象
切换正倒序后点"下一集"，第 8 集会跳到第 22 集（乱跳）。

### 根因
`PlayFragment.playNext()` 无条件 `playIndex++`。但 `DetailActivity.sortSeries()` 里
`vodInfo.reverse()` 是**列表原地反转**，倒序时列表下标方向与集数方向相反：
index+1 对应的是**集数更小**的那一集。30 集的剧正序第 8 集在倒序列表里 index=22，
点下一集跑到 index=23 → 集数反而倒退。

### 修法（PlayFragment.java）
新增 `private int nextSeriesIndex(int targetStep)`：
1. 基准取"**当前 selected 的那一集**"而不是 `playIndex`——切换正倒序后两者可能错位
   （`sortSeries()` 里已把 playIndex 重映射为 `size-1-playing`，但历史恢复路径可能不一致）。
2. `int step = mVodInfo.reverseSort ? -targetStep : targetStep;`——正序 +1 / 倒序 -1，
   保证无论正倒序，"下一集"播的都是**集数+1** 那集。越界返回 -1。
`playNext/playPrevious` 改为先算目标 index → 写回 `mVodInfo.playIndex` → `markSeriesSelected()` → `play(false)`。

### 选集同步
`markSeriesSelected()` 除更新 `selected` 外，增加同步刷新：
`if (mActivity instanceof DetailActivity) da.seriesAdapter.notifyDataSetChanged()`。
播放器与 DetailActivity 共用同一 VodInfo（`App.getInstance().setVodInfo/getVodInfo` 单例），
两个选集弹窗（AllVodSeriesRightDialog / AllVodSeriesBottomDialog）都复用 `DetailActivity.seriesAdapter`，
所以 notify 一次即可全链路同步。

### 关键前提（已核实）
- `VodInfo.reverseSort = true` ⟺ 列表已原地反转。切换（`sortSeries()`）与历史恢复
  （`vodInfo.reverseSort = vodInfoRecord.reverseSort; if (reverseSort) vodInfo.reverse();`）两条路径都一致。
- `mActivity` 在 `BaseLazyFragment` 里是 `protected Activity`。
