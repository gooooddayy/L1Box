## 【重要架构修正】拆分首页源池与订阅站点池

### 概念层级（用户澄清，此前理解有误）
- **配置源** = 订阅链接。多仓 = 含多条线路；单仓 = 本身就是一条线路
- **线路** = 肥猫 / 饭太硬 …（配置源内部的一条）
- **影视站点** = 荐片 / 文采 …（线路内部，搜索和播放的实际来源）
- 首页.json 只是**首页展示配置**，不是线路，不提供播放资源

### 上一版引入的致命 bug（已修）
- `parseJson()` 会 `sourceBeanList.clear()` 后用 `sites[]` 重填
- 上版 `loadLocalHomeConfig()` 直接调 `parseJson(首页.json)` → 站点池被清成只剩 1 个 Douban 源
- `DetailActivity.searchResult()` 用 `getSourceBeanList()` 搜索 → **点开任何影视都搜不到播放资源**
- 现象：首页能看，点进去全废

### 正确架构：两个完全隔离的池
- `ApiConfig.homeSiteList`（新增）：首页源池 ← 内置首页.json，永不被订阅覆盖
- `ApiConfig.sourceBeanList`（原有）：订阅站点池 ← 当前选定线路，可切换
- `homeLocalLoaded` 标志：首页被内置配置接管后，`parseJson` 不再覆盖 `mHomeSource`
- 消费路径本就分离：`getHomeSourceBean()` → GridFragment/SourceViewModel（首页展示）；`getSourceBeanList()` → DetailActivity/SearchHelper（搜索播放）

### spider jar 隔离（拆分后才暴露的冲突）
- 首页源 type=3 需要 spider；首页.json 与订阅源的 spider jar 可能不同
- 原 `jarLoader` 单实例、固定 `csp.jar` → 两者会互相覆盖
- 方案：新增 `homeJarLoader` + `csp_home.jar`
  - `loadJar()` → csp.jar / jarLoader（订阅站点）
  - `loadHomeJar()` → csp_home.jar / homeJarLoader（首页源）
  - `getCSP()` 用**引用比较** `homeSiteList.get(key) == sourceBean` 分流（避免同名 key 误判）

### 首页.json 内置进 APK（用户拍板，最优解）
- `assets/home_config.json`（桌面 首页.json 复制，1582 字节，无 BOM）
- `HomeConfigLoader` 重写：外置 `/sdcard/首页.json`（调试覆盖）> 内置 assets
- 彻底解决 targetSdk 30 分区存储权限问题，**SAF 导入引导全部删除**
- `App.onCreate` 不再调 `HomeConfigLoader.prepare()`

### 用户拍板的 3 个决策
1. 无订阅（站点池空）时点开影视 → 用首页.json 豆瓣源兜底
2. 切换线路 → **不重启** App，后台静默重载站点池
3. 找不到首页.json → **嵌入 APK 内部**（做不到才取消）。已实现内置

### 具体改动
- `ApiConfig`：homeSiteList/homeLocalLoaded/homeJarReady/homeJarLoader 字段；抽出 `parseSite()` 共用；新增 `parseHomeJson()`；`loadLocalHomeConfig()` 重写（含首页 spider 异步加载，失败也不阻塞首页）；`getSourceBeanList()` 空时返回首页池兜底；`getCSP()` 分流；`loadJar` 参数化
- `DetailActivity.searchResult()`：删掉把首页源塞进搜索列表的 3 行
- `HomeFragment`：新增 `homeDataOk`（首页→订阅→jar→getSort 四段状态机）；单仓显示 `R.string.app_name`(L1Box)；`showLinePicker()` 走 `reloadSitePool()` 不重启；`onResume` 检测 API_URL 变化自动重载；删 SAF 三件套
- `SubscriptionActivity.finish()`：不再重启 MainActivity
- `App.java`：删 `HomeConfigLoader.prepare()`

### 自检复查补修（交付后回头 review 发现）
上一版之所以出致命 bug 就是没做自检，故本轮交付后主动复查，又抓到 3 处：
1. **切线路会闪首页加载态**：`reloadSitePool()` → `loadJar()` → 回调里 `initData()` → `showLoading()` + `getSort()`。
   违反"切线路不改变首页展示"。修法：加 `mSilentReload` 标志，`loadJar` 成功/失败回调置位时直接 return，
   不调 `initData()`、不弹 `queryHistory()` 的"上次观看"浮窗。仅在即将调 `loadJar()` 前置位。
2. **`refreshHomeSources()`（长按左上角）仍在重启 MainActivity**：首页已内置固定，重启毫无意义。
   改为 Toast 提示 + `setupHomeTitle()` + `reloadSitePool()`。
3. **兜底逻辑吞掉"暂无订阅"提示**：`UserFragment` 用 `getSourceBeanList().isEmpty()` 判断有无订阅，
   而我给 `getSourceBeanList()` 加了"空则用首页池兜底"，导致该判断永远为 false → "暂无订阅" Toast 失效。
   修法：新增 `ApiConfig.hasSubscription()`（只看 `sourceBeanList`），UserFragment 两处改用新方法。
   **教训：给已有查询方法加兜底/fallback 时，必须全局排查所有调用点，确认没有把"是否为空"当业务判断在用。**
4. 清理：`SubscriptionActivity` 空的 `finish()` 重写 + 失效的 `mBeforeUrl` 删除
   （`mSelectedUrl` 仍在 10 处赋值但无读取，属历史遗留死状态，暂留未动）。

### 首页"影视信息一直加载" bug 修复 (2026-09-02 晚)
**现象**：首页影视信息（豆瓣源）一直转圈加载不出来。
**连通性核查（home_config.json 各 URL）**：
- 顶层 `spider` 字段 `http://<源站地址>/...jpg;md5;...` → **HTTP 404 已失效**（致命：这是首页专属 spider jar 的下载地址）
- 站点 `ext` `https://<源站地址>/...txt` → **HTTP 200 正常**（6160 字节，豆瓣 spider 初始化数据）
- `logo` → 302 跳转（正常）；`wallpaper`（IDN 中文域名）→ 302 可疑；`doh` 沙箱内 502（属沙箱网络限制，非真机结论）
**根因（真正导致"一直加载"的代码 bug）**：
- `SourceViewModel.getSort(key)` 调 `getSource(key)`，但 `ApiConfig.getSource()` 只查 `sourceBeanList`（订阅站点池），而首页豆瓣源只在 `homeSiteList`。查不到 → `sourceBean.getType()` 在后台线程 NPE 且未被捕获 → `sortResult` 永不 post → 加载圈永久转。
**修复（ApiConfig.java）**：
1. `getSource(key)` 增加 `homeSiteList` 兜底查找（首页展示源也能被 getSort/getDetail/getSearch 按 key 命中）。
2. `getCSP()` 首页源优先走 `homeJarLoader`；若返回 `SpiderNull`（首页专属 jar 未就绪/URL 失效）→ **回退到订阅 spider jar（jarLoader/csp.jar）**，保证首页能取到数据，不再依赖已失效的专属 jar URL。
- 重新构建 + zipalign + apksigner v1/v2/v3 `--min-sdk-version 17` 全部 true，产物覆盖 `FreeBox-src/L1Box_v1.1.1_release_20260902.apk`。
- 注：若用户**未配置任何订阅**，两个 jar 都空，首页仍空白（但不再转圈）；此时需给首页 `spider` 字段填一个可用的 spider jar URL 或配置订阅。

### ⚠️ 重大构建流程 bug（本轮发现，已修正）
- **症状**：删掉 `home_config.json` 的死 `spider` 字段并 clean 重编后，APK 里该字段**依然在**。排查发现根因不在源码，而在**签名步骤读错了输入 APK**。
- **根因**：`assembleRelease` 的输出在 `app/build/outputs/apk/release/L1Box_v1.1.1_release_20260902.apk`，但签名脚本里 `$APK` 指向的是 `FreeBox-src/` **根目录** 的 `L1Box_v1.1.1_release_20260902.apk`（一份很早之前遗留的陈旧 APK）。`zipalign 根目录旧APK aligned.apk` → 签名 → `mv aligned.apk 根目录旧APK`，等于**每次都只把陈旧 APK 重新签名**，新编译产物从未被采用。

- **修正**：签名脚本改为先 `SRC=app/build/outputs/apk/release/L1Box_v1.1.1_release_20260902.apk`，再 `zipalign "$SRC" aligned.apk` → 签名 → `mv aligned.apk 根目录.apk`。
- **验证**：重签后 `zipfile` 读 APK 内 `assets/home_config.json`，`"spider"` 与 `oss4liview` 均为 False（死链已彻底移除）；dex 内 `homeSiteList`/`SpiderNull`/`getCSP` 字符串均在，确认代码修复已编入。v1/v2/v3 全 true。
- **教训**：签名前必须用 `unzip -l`/`zipfile` 校验 `assets/home_config.json` 与关键 class，确保签名输入 = 刚编译产物，而非根目录遗留文件。
