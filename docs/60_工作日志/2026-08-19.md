## 第二次构建失败 (commit 75c8b07, run 32247012865)

**根因**: YAML 语法错误 - 第 39 行（base64 内容行）和第 40 行（KS_EOF 闭合行）失去前导 10 空格缩进，导致 GitHub Actions workflow 解析失败 "Invalid workflow file ... line 39"。

Web 编辑器粘贴时，2840 字符长行的前导空格不可靠地被吞掉了。

**修复**: 不再用 heredoc + 多行 base64，改用 `env: KS_B64: "<2840字符>"` 单行嵌入 - YAML 缩进规则简单，无转义噩梦。

## 第三次"成功"但无 APK (commit b658d18, run 32250318596)

**症状**: workflow 1m46s "success", Release v1 创建，**但 Assets 没 APK**，只有 Source code 压缩包。

**根因**: Build APK 步骤用了 `cmd 2>&1 | tee build.log`，**没有 `set -o pipefail`**。Gradle 失败时 `tee` 退出 0，整个 step 退出 0，CI 判定 success，Release 创建时 `output/*.apk` 为空。

旁证: cache service 全程 500 (`/home/runner/.gradle/...` 多个恢复/保存失败)，`--build-cache` 也是死路。

**修复 (test_new2.yml)**: 
1. `set -o pipefail` 在 Build APK 步骤顶部
2. 移除 `--build-cache` (cache 挂了)，加 `--no-daemon`
3. `if [ $rc -ne 0 ]; then exit $rc` 显式硬失败
4. `Prepare APK` 步骤末尾 `apk_count=0` 时显式 `exit 1`
5. `Upload build log (always)` 不再 `if: failure()`，无论成败都上传
6. 加 `Inject Google + MavenCentral` 步骤防子模块 `repositories {}` 被掏空
7. 顺手加 4thline.org 移除（UPnP 库)

## 第四次"失败" (commits 8cd4e1f, 925c460, runs 32335570442, 32336545386) — 2026-08-20

**症状**: Build APK #4 #5 #6 全部 11-19s 红色失败。Step 6 "Strip aliyun and 4thline mirrors" 退出码 2。Step 5 (Decode keystore) 一直 success。

**根因**: test_new2.yml 第 53 行 sed 字符串里有**未转义的嵌套双引号**:
```
sed -i -E "/maven...url[[:space:]]+"(https?:\/\/(maven\.aliyun\.com|.*\.4thline\.org)[^"]*)"[[:space:]]*\}/d" "$f"
```
外层 `"` 开启后，内层 `"(https?:...` 的 `"` 直接把外层字符串关闭，bash 解析整个 sed 表达式断裂 → sed: -E expression #1 error → 退出 2。

**修复 (test_new3.yml)**: 彻底简化 sed，**只删整行**: `sed -i -E '/(aliyun|4thline)/d' "$f"`（单引号包正则，双引号包文件路径，零冲突）。同样修正 `Fix keystore path` 的 sed 改用单引号。

## 给下次自己的注意点 (再次更新)

1. **shell 双引号里不能裸嵌套双引号** —— sed/awk/grep 的 regex 用单引号包，变量用双引号包，是唯一安全组合
2. **YAML `run: |` 块里的内容会被原样交给 bash** —— 任何双引号嵌套都是 bash 解析事故
3. 每次生成 workflow 后，**用 Python 把每行 sed/awk 的双引号数 (排除转义) 打印出来**做自动检查
4. 长 base64 用 `env: KS_B64: "..."` 绝对比 heredoc `<<KS_EOF` 安全
5. `cmd | tee file` 不带 `set -o pipefail` 时是隐藏 bug
6. cache service 偶发 500，避免 `--build-cache`
