# 2026-08-20 工作记录

## FreeBox / TVBoxOS 竖版 APK 自动构建（GitHub Actions 修复）

**关键根因（本次构建失败）：**
`android-actions/setup-android@v4` 默认拉最新 cmdline-tools（20.0），其 `sdkmanager` 强制要求 JDK 17+；但 TVBoxOS 项目用 JDK 11（AGP 7.2.2 + Gradle 7.3.3），导致 sdkmanager 启动即被 JDK 版本检查打死（exit 1）→ SDK 没装上 → 后续步骤全跳过 → 找不到 output/*.apk。

**修复方案：**
彻底弃用第三方 `android-actions/setup-android@v4`，改为手动安装：
- 下载 cmdline-tools **10.0**：`commandlinetools-linux-9862592_latest.zip`（**关键**：cmdline-tools ≥12.0 / 11.0 最低都要 JDK17；只有 10.0(9862592) 和 9.0(9477386) 兼容 JDK11；之前用 11076708=12.0 报 UnsupportedClassVersionError class file 61.0）
- `unzip` → `mv cmdline-tools latest` → 写入 PATH
- `yes | sdkmanager --licenses`（加 `SKIP_JDK_VERSION_CHECK=1` 保险）
- `sdkmanager "platform-tools" "platforms;android-33" "build-tools;33.0.2"`
- 通过 `$GITHUB_ENV` 导出 `ANDROID_HOME` / `ANDROID_SDK_ROOT`（供后续 local.properties 用）

**约束要点：**
- 密钥 KS_B64 必须整串嵌入（2840 字符），构建脚本里不能用 Read/Write 手动粘贴（会被 UI 截断）—— 用 Python 脚本从 ks_b64_oneline.txt 读取后拼 yml 最稳。
- ubuntu-24.04 runner 自带 Android SDK 但缺 cmdline-tools 正确版本，手动装到 `${{ github.workspace }}/android-sdk` 即可。
- 所有仓库写操作仍由用户在 GitHub 手动完成（拖文件 + 勾 Replace）；MCP 只读、沙箱无外网。

**第三环根因（logs_87683137094）：** 上版 workflow 里有一句 "Strip aliyun mirrors"（`sed -i "/aliyun/d"`），把根 build.gradle `allprojects.repositories` 里的 `maven.aliyun.com/repository/public` 和 `/releases` 删了。项目的 5 个依赖全是 jitpack 库（loadsir/okgo/tv-recyclerview/flowlayout-lib/dlna-dmc），jitpack.io 直接拉会 404，原作者能构建是**靠 aliyun 镜像代理这些 jitpack 库**。删掉 aliyun → 依赖解析失败 → `:app:mergeReleaseNativeLibs` 报 `Could not resolve ... releaseRuntimeClasspath`。

**最终修复（test_new2.yml，13 步）：**
- 删掉 "Strip aliyun" 步骤，保留仓库自带 aliyun 镜像（它是 jitpack 库的唯一可用来源）
- 保留：手动装 cmdline-tools 10.0（9862592，JDK11 兼容）、复制 keystore 进 app/、删 ndk block、修正 storeFile 路径、local.properties 写 sdk.dir、管道失败硬退出
- <源站地址> 镜像保留（dlna-cast 的 cling 依赖需要）

**本地无法构建 APK**：本机只有 workflow+keystore，无 FreeBox 源码、无 JDK/Android SDK，且沙箱禁网。只能走 GitHub Actions CI 出 APK。

**当前状态：** test_new2.yml 已生成本地（13 步），YAML 校验通过、KS_B64 校验一致。待用户上传并触发构建验证。

## 本地直接构建 APK 成功（放弃纯 CI）

**转折点**：用户本机有 Android Studio，改本地构建。clone 源码到 `FreeBox-src/`，下载 JDK11（清华镜像 mirrors.tuna.tsinghua.edu.cn/Adoptium/11）、platforms/android-33、build-tools/33.0.2 到真实 SDK（`<本机>/AppData/Local/Android/Sdk`）。

**投屏剥离**：`DLNA-Cast:dlna-dmc:V1.0.0` 在 jitpack 永久 404，剥离 DLNA 投屏模块——删 3 文件（bean/CastVideo、ui/dialog/CastListDialog、ui/adapter/CastDevicesAdapter）+ 改 5 处 Java 引用 + 4 个布局按钮 + `PlayerMenuView` 接口 `onCast()` 抽象方法（漏删会导致匿名类编译失败）。核心播放不受影响。

**本地构建关键坑**：
1. `JAVA_HOME` 必须用 `C:/...` 原生格式——`gradlew.bat` 由 cmd.exe 执行，不认 Git Bash 的 `/c/...` 路径（0 秒判 invalid 退出）。
2. `gradle.properties` daemon 堆内存默认 2GB，大项目 OOM 被 Windows 杀 → "远程主机强迫关闭连接"。改 `-Xmx4096m -XX:MaxMetaspaceSize=1024m` 并 `org.gradle.parallel=false`。
3. 收尾写 `.gradle/7.3.3/fileChanges/last-build.bin` 偶发"拒绝访问"（Defender/文件锁），但 APK 已先生成并签名完成，不影响产物。

**产物**：`MBox_v1.1.1_release_20260821.apk`（69.9MB），包名 `com.github.tvbox.osc`，v2 签名，`apksigner verify` 通过，可安装。位置 `FreeBox-src/app/build/outputs/apk/release/`。构建命令：`JAVA_HOME=C:/.../jdk-11.0.32+9 ANDROID_HOME=<本机>/AppData/Local/Android/Sdk ./gradlew.bat assembleRelease --no-daemon`。
