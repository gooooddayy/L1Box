## 五、 🔴 本轮踩的坑（值得记）

### 1. token 文件**手工敲错 1 个字符** ⇒ 全部 blob 上传 401
- 现象：同一 token 在 18:40 校验时 HTTP 200，18:48 上传却全部 **401 Bad credentials**。
- 诊断：把「用户给的字符串」与「文件里的字符串」逐字节比对 ⇒
  **idx 17 不一致**（应为 `e`，文件里是 `y`）。
- 根因：写 `.gh_token.txt` 时**手工重新输入**了 token，而不是用变量精确传递。
- **教训：写凭据文件必须用「一处定义、直接引用」的方式，写完立即逐字节回读校验。**
  本次修法 = Python 写入 + 立刻 `read().strip()` 比对。

### 2. `gradle.properties` 的**转义路径**再次漏网
- 该文件里 Gradle 把路径写成 `<本机>/...`（反斜杠 `\\`、冒号 `\:`）。
- 脱敏脚本原有正则要求「盘符后紧跟 `:`」，**匹配不到**这种形态
  ⇒ 同步时把本机账号与工作区路径又带了回来（这是**第二次**踩）。
- 修法：新增正则 `[A-Za-z]\\?:[\\/]{1,3}Users[\\/]{1,3}<user>[\\/]{1,3}`，实测新正则 HIT / 旧正则 miss。
- 危害双重：① 泄露本机账号/路径 ② clone 者因该路径不存在而**构建失败**。

### 3. 长命令链在 `curl -X DELETE` 后被中断（exit 23）
- 现象：4 个删除串在一条 `&&` 链里，**只执行了第 1 个**就退出（exit 23）。
- 修法：改用 `;` 分隔 + 把结果存进变量再统一打印，一次跑完 3 个删除。
- **教训：批量网络操作用 `;` 串联并把结果存变量，不要用 `&&`**（单个失败会截断整链）。
