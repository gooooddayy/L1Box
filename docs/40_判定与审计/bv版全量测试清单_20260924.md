# 三、bv 修了什么（本轮 5 组，共 30 处落点）

> 定稿方案：`_l1_docs/30_成功率与崩溃/bv统一修法方案_定稿_20260924.md`（八节，含根因/修法/边界/复测判据/闸门 dex 同步项）。

## A 组：搜索"不收敛"（A2 复测暴露）

**现场**：bu 复测 A2 四轮**全部跑满 30 秒看门狗**且**永远不收敛** —— 用户等不到任何结论。

| 洞 | 根因 | bv 修法 |
|---|---|---|
| **4** | 判据② 拿 `roundAsked` 比 `roundSiteCount`，而两者在发起时被赋成**同一个值**（`FastSearchActivity.kt:1162`）⇒ **恒真**，测不出"有没有站点没被问到" | 判据② 改比 **`roundDone`（真实回调数）**：`!roundEndedByTimeout && roundDone >= roundSiteCount && roundSiteCount > 0`；`roundAsked` 字段整体删除 |
| **5** | 池签名含 `JarLoader.loadSeq()`（**装载活动计数器**，每轮都在动）⇒ 判据③「池未变」**恒假** ⇒ S3 每 1 秒又起一整轮 30 秒 | 签名撤出 `loadSeq`，改用 **`poolKeySig()`＝站点 key 集合排序哈希**（纯内存读，零请求）。"jar 装上了⇒站点可搜"改由判据⑥ 覆盖 |
| **6** | `SourceViewModel.getSearch` 两处出口（「源里查不到该 key」「类型不在 0/1/3/4」）只投**无人订阅的 LiveData** ⇒ 该站点永不回调 ⇒ 计数漏一格 ⇒ 判据② 永远"没问全" | 两处改走 **`EventBus.getDefault().post(RefreshEvent(TYPE_SEARCH_RESULT, null))`**（唯一被订阅的通道）。现全文件共 **7 处** |
| **新增** | 0 结果的搜索即使站点早就不动了，也要**白等满 30 秒** | **停滞检测**：`在途>0 ∧ 结果=0 ∧ 静默≥10s` ⇒ 提前按超时收尾（`搜索停滞：N 秒无站点回调（在途=…）`）。**有结果时绝不打扰** |
| **新增** | 「没问全」以前只能冒用「暂无数据」 | S3 兜底出口：池已稳定但仍有站点未响应 ⇒ 独立结论 **「部分站点未响应，未找到结果，请稍后重试」** ＋ 埋点 `个站点未响应（已回 N/M）` |

## D 组：外部播放器 / 投屏「无法播放」（D1-MX 回归）

**根因链**（bu 三条实验已闭合）：m3u8 清单里 **554 个分片全是相对路径** ⇒ 播放器拿**清单 URL（＝本机转发端点）**当 base 去补全 ⇒ 拼成 `http://127.0.0.1:9978/<分片名>` ⇒ 本机没这个路径 ⇒ NanoHTTPD 回 **HTML 首页** ⇒ FFmpeg 在 open 阶段读到 HTML ⇒ **`AVERROR_INVALIDDATA`（status=-1094995529）** ⇒ 197ms~1.8s 就弹「无法播放」（bt 时是 ~10 秒才结束，**这是回归**）。

**修法**：转发端点**就地重写 m3u8 清单**，把相对分片改成**经本端点转发的绝对地址**。

| 要点 | 说明 |
|---|---|
| 端点是哪个 | `RemoteServer.servePlayForward`（`/l1play`）—— 本机外部播放器与投屏**共用同一个方法**，所以一次修两家 |
| 端点前缀怎么来 | 取**请求的 `Host` 头**：本机自动 `127.0.0.1:9978`、电视自动 `192.168.x.x:9978`，不需要这里判断"我是谁" |
| 为什么不把 base 换回上游 | 那样分片就由播放器**直连上游**，站点没下发的 Referer 又丢了 ⇒ 回到 403 老路。分片**必须继续走转发**，只是地址变绝对 |
| 只有 200 全量清单才重写 | `code==200 ∧ 无 Content-Range ∧ 长度已知且 ≤8MB ∧ 像 m3u8`。206 带 Range 语义，改了字节账对不上 |
| `EXT-X-KEY/MAP/MEDIA` 的 `URI="…"` | 一并重写（否则加密流照样死） |
| 投屏怎么带请求头 | 分片复用**同一个一次性码**（`?t=<码>&u=<分片绝对地址>`），请求头从登记里取，**不放进局域网明文** |
| 地址解析 | **纯字符串**，不用 `java.net.URI`（清单地址常含 `\|`／空格／中文 pkey，`new URI(...)` 直接抛异常 ⇒ 整条重写废掉） |
| 已指向本机的不再包一层 | `resolveUrl` 里 `127.0.0.1` / `/l1play` ⇒ 返回 null（防自嵌套） |
| 出错怎么办 | **原样透传**（退化，不是报错）—— 不赌 |

**顺带查出并修掉**：转发端点**无条件回 `Accept-Ranges: bytes`**，而上游实测**忽略 Range**（发 `Range: bytes=0-1023` 仍回 200 ＋ 完整 197865 字节、无 `Content-Range`）⇒ 等于对播放器**谎报"支持拖动"**。改为：**上游没给就不回**。

**断言口径纪律（血泪）**：闸门用 **`grep -E`（ERE）** ⇒ 正则里 `(` `)` `.` `+` **必须转义**（裸 `+` 是量词"一个或多个前一字符"，裸 `(` 是分组起始 —— 都会让断言**永不命中**）；`count` 是「**≥N**」；`mustnot` 写成**实际调用形态**（注释里出现也会被判失败）；**遇文件缺失即 FAIL**。

## 本轮踩的坑（记下来）

1. **闸门用 `grep -E`（ERE）⇒ 断言自身的写法错也会让闸门红**（本轮三处红全是这个）：
   - `$SVM` / `$FSA` / `$OKG` **变量名不存在**（闸门里叫 `SV` / `OG`）⇒ `unbound variable`；
   - 正则里**裸 `(` 是分组起始、裸 `+` 是量词**（"一个或多个前一字符"）⇒ 断言**永不命中**。实测：`" \+ host + "` 只转义一个＝0 处，两个都转义＝1 处；
   - `count` 是「**≥N**」，且**次数要按实测真值填**（EventBus 那串实测是 **7** 处，不是 6）。
   - **判据**：看到闸门红，先分清是"源码错"还是"断言错" —— 看 `grep -c '!!'` 为 0 却 exit 1，基本就是**脚本级错**（变量名/语法）。
2. **Kotlin `val` 不能自引用**（这一个坑分两段才走通）：
   - `private val stallRunnable = Runnable { … postDelayed(stallRunnable, …) }` ⇒ `Type checking has run into a recursive problem`（类型推断递归）；
   - 加上 `: Runnable` ⇒ 换一个错：`Variable 'stallRunnable' must be initialized`（**`val` 的初始化表达式里引用自己＝未初始化就使用**，语言级限制）；
   - **唯一稳的形态**：体里只调一个方法 `Runnable { stallCheckTick() }`，自引用发生在 `run()` 被调用时（与同文件 `flushRunnable` 同一写法）。**判据：lambda 体内出现自己的名字 ⇒ 抽成方法。**
3. **删字段要连赋值一起删**：删 `roundAsked` 字段时漏了 `roundAsked = siteKey.size` 那行 ⇒ `Unresolved reference: roundAsked`。
   **闸门只锚"不该有的写法"，锚不到"漏删的赋值" ⇒ 编译才是最终判据**（本轮闸门全绿、编译才报）。

# 六、附：本次新发现的崩溃（**独立缺陷，不属于本轮测试项**）

> 判定书全文：`_l1_docs/40_判定与审计/崩溃判定_DslTabLayout_20260924.md`

**现象**：测「图片」时（**2026-09-24 21:32:29**）崩溃一次。

**一句话根因**：**上游 Tab 库 `DslTabLayout` 自己的缺陷** —— 手势回调把 `e1` 声明成非空，而 Android 框架在 `ACTION_CANCEL` 之后会传 null 进来。

| 项 | 内容 |
|---|---|
| 异常 | `NullPointerException: Parameter specified as non-null is null: … parameter e1` |
| 崩溃点 | `com.angcyo.tablayout.DslTabLayout$_gestureDetector$2$1.onScroll` |
| 源码 | `TabLayout/src/main/java/com/angcyo/tablayout/DslTabLayout.kt:1511`（`onScroll(e1: MotionEvent, …)` **非空签名**；`onFling` 同患） |
| 触发机制 | `GestureDetector` 收到 `ACTION_CANCEL` ⇒ 内部 `mCurrentDownEvent` **置 null** ⇒ 同一批（batched）里的 `ACTION_MOVE` 仍调 `onScroll(null, …)` ⇒ 撞非空检查 ⇒ NPE |
| 为什么偶发 | 需三条件同时成立：Tab 可滚动 ＋ 手势中出现过 CANCEL ＋ 同批还有位移 ≥1px 的 MOVE |
| 影响面 | **两页共用这个类**：搜索页左侧站点竖栏（`activity_fast_search.xml:130` `VERTICAL`）＋ 首页分类栏（`fragment_home.xml:96`）⇒ **修一处覆盖两页** |

| 崩溃后 | App **自动重建**、可继续用（pid `29690`→`758`）；本次会话**只崩这一次**，无第二次 FATAL |
