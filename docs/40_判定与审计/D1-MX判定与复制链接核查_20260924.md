## 五、「复制链接必须复制原链接」核查

### 5.1 现状：代码上**已经是**原链接

全工程**视频复制链接只有一个入口**：

`DetailActivity.java:963` `use1DMDownload()`（详情页下载图标 ＋ 播放中复合弹窗的下载按钮共用）

```java
String url = TextUtils.isEmpty(playFragment.getFinalUrl()) ? vod.url : playFragment.getFinalUrl();
...
cm.setPrimaryClip(ClipData.newPlainText("video_url", url));   // :973
```

追 `getFinalUrl()`（`PlayFragment.java:2715`）：

```java
return TextUtils.isEmpty(mCurrentUrl) || !RegexUtils.isURL(mCurrentUrl) ? "" : mCurrentUrl;
```

追 `mCurrentUrl`（**全文件只有一处赋值**，`PlayFragment.java:1303`，位于 `playUrl(String url, …)` 入口，**在净化之前**）：

```java
mCurrentUrl = url;   // ← 站点下发的原始播放地址
```

而转发包装只发生在**喂给播放器的那一瞬**，是个**局部变量**、不回流：
`PlayerHelper.java:308`
```java
String playUrl = isHeaderForwardPlayer(playerType) ? wrapForExternalPlayer(url, headers) : url;
//  ↑ 局部变量，用完即弃；mCurrentUrl 不受影响
```

⇒ **按当前代码，点下载按钮复制出来的就是站点原始直链**（如 `https://vod.feifei-kan.com/…/index.m3u8`），**不是** `http://127.0.0.1:9978/l1play?u=…`。

### 5.2 那用户为什么提这条？

有三种可能，需要一次实测（2 秒可判）来区分：

| 可能 | 说明 | 是否要改 |
|---|---|---|
| **① 预防性叮嘱** | 用户知道 #8 改了外部播放地址，提前要求"别把复制链接也改坏" | ❌ 不用改，现状已符合 |
| **② 在 MX 里复制到的** | MX 自己带分享/复制，它拿到的就是本机端点 ⇒ 复制出来是 `127.0.0.1` —— **这必然如此**，MX 不拿到转发地址就没法带请求头 | ❌ 无法改（改了就播不了） |
| **③ 站点原始地址本身就是 `127.0.0.1`** | 部分站点（clan/ali 类本地代理）下发的"原链接"本身就是本机地址 | ❌ 这是真·原链接 |

**实测方法**：在 App 里点一次下载按钮 → 粘贴到任意输入框 → 看开头是 `https://` 还是 `http://127.0.0.1:9978/l1play`。
- 若是 `https://…` ⇒ **①**，现状即符合，无需改动；
- 若是 `http://127.0.0.1:9978/l1play?u=…` ⇒ **真缺陷**，说明有未发现的路径把包装地址写进了 `mCurrentUrl`，**必须改**。
