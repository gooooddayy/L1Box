## 一、口径（用户拍板）

- 「刷新」= 重新加载 + **自动跳回**点它那一刻的位置；**不提示、直接跳**。
- 必须走**独立路径**：不得与「片头跳过」（`getSavedProgress` 钩子 → 内核自动 seek）和「点击跳转」落点提示（`showResumeTip`）共用同一条管道。
- 「重播」保持原样：清该集进度、从头播。

## 二、实现（只动 `PlayFragment.java` 一个文件，7 处，全部只增不删）

1. **新字段**：`mRefreshResumeMs`（要回去的位置）/ `mRefreshIntent`（刷新意图）/ `mRefreshSeekApplied`（防重复跳）+ 两个常量 `REFRESH_RESUME_MIN_MS=3000`（门槛）/ `REFRESH_RESUME_TAIL_MS=3000`（片尾保护）。
2. **`replay(false)`（只刷新这条路径）**：点下去瞬间取内核真实位置与时长；`位置 ≥3 秒且时长 >0` 才置意图（直播 duration=0 天然排除；刚开头几秒不值得跳）。埋点 `刷新回位点 xxms`。
3. **`prepared()` 回调**：`if (mRefreshIntent) → applyRefreshResume(); else → showResumeTip();`——**两者互斥**，刷新路径绝不出现「点击跳转」。
4. **`applyRefreshResume()`**：`mVideoView.post(...)` 延后一帧再 `seekTo(位置)`，含片尾保护（最多到「时长-3 秒」）；埋点 `刷新回位 xxms`。
5. **`playing()`**：真正出画 ⇒ 意图结束。
6. **换集块 / 重播 reset 块**：清意图（换集重播与刷新无关）。

### ⭐ 本轮唯一的技术坑（已处理）：为什么必须 post 一帧

`prepared()` 是**同步**回调（发生在 `VideoView.onPrepared()` 内部，`setPlayState → onPlayStateChanged → listener.prepared()` 全在主线程同一栈上）；而内核「片头跳过」的那次 `seekTo(mCurrentPosition)` 在 `setPlayState` 返回**之后**才执行——
⇒ **在 `prepared()` 里直接 seek 会被片头跳过那次盖掉**。`post` 到消息队列之后执行，才能保证最终生效的是刷新回位。

## 五、真机测试指引（建议顺序）

1. 播放任意一集，拖到 ~10 分钟后；
2. 打开播放设置弹窗（控制条「设置」）→ 点「**刷新**」；
3. **预期**：重新取链 → 起播后**直接回到 ~10 分钟处**，全程无提示；
4. **回归点**（确认没被牵连，任一异常即回报）：
   - a. 从详情页正常进入（该集有历史进度）：仍是「**点击跳转 xx:xx**」浮层，点了才跳；
   - b. 片头跳过：配了片头秒数的片子，进入时照旧自动跳片头 + 「已跳过片头 N 秒」提示；
   - c. 点「重播」：仍从 0:00 开始、无提示；
   - d. 换集 / 下一集：行为照旧；
   - e. 位置不足 3 秒时点刷新：不跳（无感，符合预期）。
5. 排查用日志关键词：`刷新回位点`（点击瞬间）/ `刷新回位`（真正跳转）。
