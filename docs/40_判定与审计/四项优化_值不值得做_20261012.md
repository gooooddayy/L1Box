## ⓪ 先回答：G1「不拒载」是什么意思，要不要改

**G1 不是让你去做什么，是让你替我确认"我没有写错"的一条防呆检查。**

dk 那版我给"jar 自检未通过"新加了一个状态：**它照常可用，只是不被记成"本地代理的持有者"**。
这个状态**最危险的写错方式**是顺手把它**拒掉**（不认这个 jar）—— 因为历史上真踩过：
`ap` 轮一次误拒载发生 **458 次**，结果就是**那批 jar 的站点成片消失**（你当时实测"搜索为空"）。
所以 G1 的预期就是"**站点一个都不能少**"。

**判定：不需要改。** 依据：
1. 你要测的那条路径（受控路径的第三态）**本次一次都没触发** —— 因为自检失败的 jar 走的是另一条分支（普通分支本来就不做任何代理登记）；
2. `降级其站点` 日志 **0 次** ⇒ 没有任何 jar 被拒载；
3. 你说的"没什么问题"与日志一致。

⇒ **这条就此关闭**，不需要动作。我仍会把它记成"**受控路径第三态至今未被真正检验**"（等哪天真的走到那条路才能补上）。

## ① 安装包体积：**有 2 个真机会，1 个是纯赚，1 个要你决定**

### 现状构成（57.84 MB 压缩后／60.82 MB 磁盘）

| 部分 | 体积 | 占比 |
|---|---|---|
| **`lib/arm64-v8a`** | 27.29 MB | 47.2% |
| **`lib/armeabi-v7a`** | 20.49 MB | 35.4% |
| `classes*.dex` ×3 | 7.80 MB | 13.6% |
| `resources.arsc` + `res/` | 1.47 MB | 2.5% |
| `assets/`（js 运行时/ua.db/内置配置） | 0.67 MB | 1.2% |

**so 占了 82.6%** —— 体积问题基本就是 so 的问题。最大的几项：

| so | arm64 | v7a | 合计 |
|---|---|---|---|
| `libijkffmpeg.so`（IJK 播放内核） | 12.00 | 9.50 | **21.50 MB** |
| **迅雷三件套** `libxl_thunder_sdk` + `libp2p` + `libxl_stat` | 5.35+5.04+0.80 | 3.51+3.62+0.48 | **18.80 MB** |
| `libquickjs-android-wrapper.so` | 1.18 | 0.79 | 1.97 MB |

| `libplayer` / `libijksdl` / `libconceal` / `librtmp-jni` | 1.33 | 0.77 | 2.10 MB |

### ✅ 机会 A（纯赚）：so 目前**不压缩**，压一下 **省 26.6 MB**

事实：APK 里所有 so 都是 **STORED（未压缩）**（`12.00 MB → 12.00 MB`），因为清单里
`android:extractNativeLibs="false"`。改成 `true`（AGP 里是 `useLegacyPackaging = true`）后：

| | 现在 | 改后 |
|---|---|---|
| **下载体积** | 60.8 MB | **约 34.2 MB（−26.6 MB，−44%）** |
| 安装后设备占用 | ≈ 60 MB（so 留在 APK 里） | ≈ 34 MB(APK) + 约 48 MB(解压后的 so) ≈ 82 MB（**多占约 22 MB**） |
| 首次启动 | 直接 mmap，最快 | 首次解压 so，**略慢一点**（之后不再受影响） |
| Android 6.0 兼容 | 同样支持（M 起两种都支持） | 同样支持 |

- 实测依据：我把包内 so 逐个 deflate 实测，47.79 MB → 21.21 MB。
- ⚠️ 唯一代价是"设备上多占 22 MB + 首次启动稍慢"。对 **GitHub 分发（下载体积敏感）** 明显划算。
- ⛔ 顺带说明：项目历史上**从来没做过**这项（`_l1_docs` 里没有任何 `extractNativeLibs`/`useLegacyPackaging` 记录）⇒ 不是重复劳动。

### ⚠️ 机会 B（要你定）：迅雷三件套 **18.8 MB**，但它**还在被用**

不是死代码：`App.getp2p()` → `P2PClass.loadLibrary("p2p")`、`PlayFragment` → `Thunder.stop/play`、
`SourceViewModel` → `Thunder.parse`、`Jianpian`（荐片）P2P 下载。用途是**磁力/荐片类地址的 P2P 播放与下载加速**。
⇒ **删掉能省 18.8 MB，但会失去磁力/荐片那类站点的播放能力**。这属于产品取舍，**要你决定**。

### ⛔ 明确**不做**的（收益小或风险大）

| 项 | 为什么不值 |
|---|---|
| 开 R8/混淆（`minifyEnabled`） | dex 7.8 MB 里最多省 ~2.5 MB（占整包 3%），但我们与第三方 jar 之间大量靠**类名/方法名反射**调用（`SpiderDebug`/`Spider`/`Proxy`/`DexNative`…），混淆规则写漏一条就是"站点全废"。**风险 ≫ 收益** |
| `shrinkResources` | 资源总共才 1.47 MB，且要开 minify 才有意义 ⇒ 同上 |
| `resConfigs` 裁语言 | `res/` 下只有 `values-night`/`values-v29`/`values-v31`，**本来就没有多语言冗余**，改了省不到 0.5 MB |
| 拆 ABI（拆成 arm64 / v7a 两个包） | 我们走 GitHub 分发，用户极易装错版本；而且 v7a 是给老盒子用的，与你的"兼容 6.0"直接冲突 |
| 删 assets 里的 `js/`（cat.js 等） | cv 轮已定：**spider 运行时，删了变砖** |
| 删 `epg_data.json`/`fakeboot.dex` | 合计不到 1 MB，收益太小 |

## ③ 权限：清单 10 项，**只有一个值得优化**（且不影响功能）

| 权限 | 用途 | 判定 |
|---|---|---|
| `INTERNET` / `ACCESS_NETWORK_STATE` / `ACCESS_WIFI_STATE` | 网络必需 | ✅ 保留 |
| `WAKE_LOCK` | 播放不熄屏 | ✅ 保留 |
| `FOREGROUND_SERVICE` | 后台播放 | ✅ 保留 |
| `CHANGE_WIFI_MULTICAST_STATE` | **DLNA 投屏**（`DlnaManager` 用 `MulticastLock`+`MulticastSocket`） | ✅ 保留（删了投屏就废） |
| `READ/WRITE_EXTERNAL_STORAGE`（都带 `maxSdkVersion=32`） | 本地视频/字幕 | ✅ 保留（**时机已是对的**：按需，不是启动即要） |
| `CAMERA` | 扫一扫加订阅源 | ✅ 保留，**时机已是对的**：只在 `SubscriptionActivity` 点扫码时才申请 |
| ⚠️ **`MANAGE_EXTERNAL_STORAGE`** | **仅**用于"加载本地字幕"时用**自研文件浏览器**（`ChooserDialog` 遍历 /sdcard） | **唯一候选**，见下 |

### 值得做的一项：本地字幕改用系统文件选择器 ⇒ 可**彻底去掉 `MANAGE_EXTERNAL_STORAGE`**

- 现在：`PlayFragment` 里用自研 `ChooserDialog` 从 `Environment.getExternalStorageDirectory()` 开始遍历，
  所以 Android 11+ 必须索要"**所有文件访问**"（最重的权限，还会把用户**弹到系统设置页**手动开）。
- 正解：**本地字幕走 SAF**（`ACTION_OPEN_DOCUMENT` / `ACTION_GET_CONTENT`）—— 用户自己选文件，
  **一分钱权限都不用**，Android 11+ 上反而更可靠（更不容易"选中了却读不到"）。
- 代价：要加一个"系统选择器"分支并验证"选字幕 → 解析 → 上屏"全链路；属于**中等工作量**，但**不减少任何功能**。
- ⚠️ 老版本（<Android 11）上 `ChooserDialog` 本来就能用，可保留为备选或一并切到 SAF。
