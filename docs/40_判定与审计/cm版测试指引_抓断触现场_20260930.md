## 二、怎么测（就一件关键事）

### 关键动作 ⭐

**要在"站点还在一个个冒出来"的那几秒里滑左栏** ——
因为 `needScroll` 的翻转点在 **站点 17→18 个**之间（三轮实测三次），
**只有在这个窗口里滑，才可能撞上翻转**。

具体：

1. 发起一次搜索（用结果多的词）
2. **搜索刚发起的前几秒**（左侧站点正在陆续出现时）→ **快速上下滑左栏，反复滑 5~10 次**
3. 期间如果感到"手被甩开/顿住" → **继续滑**，多来几次（断触是偶发的，多滑才有样本）
4. 等这轮搜索收尾
5. 切右侧 → 快速滑 + 松手，感受惯性，重复 3~5 次
6. 说「测完了」

> **建议再搜第二次**，重复步骤 2~5 —— 每轮搜索都会让 chip 从 0 涨到 40，
> 也就是**每轮必然有一次翻转**，多做一轮多一个样本。

### 小纪律

- 每轮搜索**开始的那几秒最重要**（chip 从少到多的窗口），别等站点全出来了才滑
- 一轮做完停 2~3 秒再进下一轮
- 别拔 USB

## 三、我会怎么判（数据一到就能出结论）

| 观察 | 结论 |
|---|---|
| `★CANCEL` 与 `★★可滚翻转` **时间重合**（前后几十毫秒内） | **A 成立**：断触由 `needScroll` 翻转造成 ⇒ 改法明确 |
| `★CANCEL` 与 `★左栏开始拦截` **时间重合** | 断触是"左栏开始接管"的正常副作用 ⇒ 要看能否让接管更早/更平滑 |
| `★CANCEL` 出现，但**上面两个都没出现** | 断触另有来源 ⇒ 继续查（父容器/其他） |
| `★CANCEL` **一次都没出现** | 说明用户的"断触"不是系统级 CANCEL ⇒ 是"滚动被卡住"的观感，要转向别处 |
| 右栏 `滑行` 的 **突变** 数很高 / 尾 6 帧不收敛 | 惯性被打断 ⇒ 查插入与图片 |
| 右栏 `滑行` 均匀（突变 0、尾帧收敛到 0） | 右栏惯性本身正常 ⇒ 顿挫来自别处（需再讨论） |
