## 二、四项改动（左侧 3 项 + 右侧 1 项）

### L-A. 左栏 fling 上界：`maxHeight` → `maxScrollY`

**文件**：`TabLayout/src/main/java/com/angcyo/tablayout/DslTabLayout.kt`（`onFlingChange` 竖向分支）

**原来**：fling 上界用 `maxHeight`（内容总高）；而真正可滚范围是 `maxScrollY = 内容高 − 视高`
⇒ **多算了一整个视高**，fling 在视觉抵达底部后仍继续跑。

### L-B. 竖向越界中止：补判 `currY`

**同文件** `computeScroll`：

```kotlin
// 原来：只查 currX ⇒ 竖向 fling 的 currX 恒为 0、minScrollX=0、maxScrollX≥0 ⇒ 条件永不成立
if (_overScroller.currX < minScrollX || _overScroller.currX > maxScrollX) abortAnimation()
// 现在：按横竖分支，竖向判 currY
```
⇒ **竖向 fling 不再无限空转**（ck 实测单段曾达 4668ms / 8348ms，而正常 fling 只有 1~2 秒）。

**L-A + L-B 合起来消灭的那个 bug**：

```
用户滑到中部（Y=517）→ fling 空转
   ↓  此时插入新 chip ⇒ 内容变高 ⇒ maxScrollY 变大（→1511）
   ↓  fling 每帧 scrollTo(0, currY)，被钳到**当时**的 maxScrollY
   ↓  scrollY 被一路"吸"到 1511（新底部）
⇒ 用户看到：滑着滑着，列表突然跳到底 = "卡住不跟手"
```
ck 实测原始记录：`前Y=517 后Y=1511 滚动段=4668ms/80次 上限=1511` —— **后Y 恰等于新上限**。

### L-C. 放开"追加"的守卫，只保留"清空重建"的守卫

**文件**：`FastSearchActivity.kt`（`flushSiteTabsNow` + `drainSiteTabQueue`）

| 操作 | 改动前 | 改动后 |
|---|---|---|
| **追加新 chip**（`addView`） | 滑动中一律禁止 | **滑动中也允许** |
| **清空重建**（`removeAllViews`） | 滑动中禁止 | **保持禁止**（这个才真会打断手势） |

**依据**：`addView` 是**追加到末尾**，不移除也不移动已有子 View；
且三轮实测中唯一一次滚动位置跳变（517→1511）由 **fling 空转**造成，**与 addView 本身无关**。

**修的是**：ck 实测用户滑 8.4 秒期间 chip **零更新**、停手后才一次性冒出（`批量=8`）
—— 即用户报的「**我一滑动，就停止出结果**」。

> **退路**：若真机上追加仍引发 ACTION_CANCEL，退化为「滑动中追加也限流」（如每 200ms ≤2 个），
> 而不是像现在一刀切全禁。

### R-A. 右栏关掉焦点项居中

**文件**：`app/src/main/res/layout/activity_fast_search.xml`

```xml
<!-- mGridView -->
app:tv_selectedItemIsCentered="true"   →   "false"
<!-- mGridViewFilter 保持 true 作对照 -->
```

**依据**：反编译 `com.owen:tv-recyclerview:3.0.0` 得知 `mSelectedItemCentered` 只在
`requestChildRectangleOnScreen`（**焦点滚动**路径）里生效、触摸滑动不经过它；
但触摸后 item 若获得焦点，仍可能触发一次"把选中项滚到居中"的额外滚动 ——
正是"松手停下后又顿一下"的形状。

## 四、⚠️ 本版**保留埋点**（与前次计划不同）

原本说"改完顺带撤掉埋点"，但**改为保留** —— 因为需要用它验证修复效果：

| 埋点 | 验证哪一项 |
|---|---|
| `左栏插入` 的 `前Y` vs `后Y` | **L-A/L-B 是否生效**：不应再出现 517→1511 式跳变 |
| `左栏插入` 在滑动中的出现频率 | **L-C 是否生效**：滑动中也应有插入 |
| `滚动段=Xms/N次` | 单段时长应**明显缩短**（不再有 4~8 秒的空转段） |
| `停稳收尾` / `帧耗时` | 回归对照 |

⇒ **验证通过后，下一版（`cm`）把埋点整体撤除**（沿用 ch 轮撤「分段耗时」的做法），
并在闸门里加反向断言钉住。

|---|---|
| R1/R2/R4（右栏停稳三件活、高频取消） | 三轮实测合计 **0~3ms**，不是问题 |

| 判死秒数 / 自动换线路 / 预建 chip / 滑动中暂停落地 | 长期纪律，一字未动 |
