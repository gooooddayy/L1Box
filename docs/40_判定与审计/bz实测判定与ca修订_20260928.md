# bz 实测判定（2026-09-28 15:25~15:27）与 ca 修订

> 判定依据：`logcat -d -b crash`（设备端 crash 缓冲，`_bz_crash.txt`）。**崩溃栈是硬证据，不是推测。**

## 一、崩溃：点“无结果的站点”必闪退（真机 ×3 次）

```
FATAL EXCEPTION: main   Process: com.github.tvbox.osc
java.lang.NullPointerException
    at FastSearchActivity.filterResult(FastSearchActivity.kt:324)
    at FastSearchActivity$initView$5$1.invoke(FastSearchActivity.kt:223)   ← 左栏 onSelectViewChange
    at DslSelector.selector(DslSelector.kt:202)
    at View.performClick(...)
```
15:25:00 / 15:25:10 / 15:27:23 三次同栈 ⇒ 用户点一次崩一次。

**根因（第 324 行）**：
```kotlin
val key = spNames[spName]
if (key.isNullOrEmpty()) return      // 老防线：只挡住"名字不在站点表里"
val list: List<Movie.Video> = (resultVods[key])!!   // ← 名字在、但该站点还没有结果桶 ⇒ null ⇒ NPE
```
**这条路径是 bz 自己造出来的**：bz 把"本轮全部站点 tab"预建出来，于是左栏出现了**尚未返回结果的站点**；
点它时 `resultVods[key]` 还是 `null`，`!!` 直接抛 NPE。
（原设计 tab 只在"有结果"时才出现，所以这条路径撞不到。）

**修法（两处，缺一不可）**：
1. **撤销"预建全部站点"**：恢复 tab 语义＝**只显示"有结果的站点"**（用户 09-28 明确否掉"点搜索就把所有站点列出来"）。
2. **加防线**：`resultVods[key]` 按可空取用，为 null 时给空列表（"该站点暂无结果"），不再用 `!!`。
   —— 这样即便将来任何来源让"暂无结果的站点"出现在左栏，也只是显示空，不会崩。

## 二、左栏拖动：补上"手指记账"这一环

bz 的"停手窗口"只看**滚动事件**，漏了**手指刚落下、还没产生滚动**的那几十毫秒 ——
那一刻若排队中的 tab 落地，照样会换掉子 View、系统随即发 ACTION_CANCEL，
正好对应你说的"起始滑动点无效"。

**修法（ca）**：在 Activity 的 `dispatchTouchEvent` 里旁观触摸流：
- 落点命中左栏 ⇒ 记 `siteTabsTouchDown = true`（并在抬手后把"停手窗口"重新起算）；
- 只有**左栏上没有手指**、且 400ms 内没滚动过，才允许落地 tab 的增删。

> 说明：`DslTabLayout` 自身"内容不超过视口时完全不接管手势"（`needScroll`）**仍未动库**。
> 那种情况下左栏只有两三个 chip、本来也确实没内容可滚；真正的"拖着突然断"不是它造成的。
