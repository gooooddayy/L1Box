## 二、根因（两处独立的时序缺陷）

### 缺陷 ①：捕获瞬间内核读空 → 直接放弃（无痕迹）
按下瞬间 `mVideoView.getCurrentPosition()/getDuration()` 可能瞬时读回 **0/0**（起播/释放的过渡窗口）。
原实现要求 `pos>=3000 && dur>0`，否则静默放弃 —— 于是"按了没反应"且**日志上完全看不出来**。

### 缺陷 ②：出画事件与"延后一帧 seek"竞态 → 回位被跳过
原实现在 `playing()`（真正出画）里清"刷新意图"。而回位任务（post 一帧）在某些时序下排在出画消息**之后**：
```
[M1 prepared] → 我们的回位任务 R 入队
[M2 出画 playing]（若 M2 先已在队列）→ 清意图
[R 执行] → 见意图已清 → 跳过 ⇒ 回位丢失
```
⇒ 日志上表现为"只有回位点、没有回位"。**凡是"依赖下游事件清位"，就有下游事件先到的竞态。**

## 三、修复（dp，只动 `PlayFragment.java`）

1. **捕获兜底**：0/0 时改用进度库（每秒刷新，≈刚才位置）取值；仍无效才放弃。
2. **跳过留痕**：`刷新回位点 跳过 pos=X dur=Y` —— 下次"没跳"一眼能看出按下瞬间读到了什么。
3. **seek 落地自清意图**：不再依赖 `playing()` 事件清位（该清位已移除）；回位任务自身完成后清。
4. **代次防互踩**：`mRefreshGen` —— 连点刷新时旧回位任务作废。
