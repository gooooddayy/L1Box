# dk → dl 差异对照（2026-10-12）

## ⓪ 本次改了什么（先看这段）

**一句话：给 jar 装载的"普通分支"补装上哨兵 —— 只多一行日志，装载结果与分支走向一动不动。**

| # | 文件 | 改了什么 |
|---|---|---|
| 1 | `crawler/JarLoader.java` | 普通分支（`isFamily == false` 时直接反射调 `Init.init`）里：**调用前取一次哨兵序号、之后比对**；命中就打一条 `加固 jar 自检未通过，但它走的是普通分支（非家族判据）⇒ 仅记录，不改变装载结果：<key>`。**`success = true` 仍是无条件**（结构断言已钉住） |
| 2 | `check_l1box_regressions.sh` | 新增 **5 条**断言，其中两条是结构检查：哨兵判断之后**不得**出现 `success = false`、且**必须**仍有 `success = true` |
| 3 | `build_l1box.sh` | 闸门 3 dex 符号表 +1 个校验符号（拿日志字面量） |

**为什么**：dk 现场实证 —— 那次自检失败的 jar 走的正是这条普通分支（`JarLoader`），
而 dk 的哨兵只装在 `ProtectedInitJar` 那一处 ⇒ **dk 的第三态一次都没触发**，
所以 G1「不拒载」当时并没有被真正检验到。判定书：
`_l1_docs/30_成功率与崩溃/dk轮G3验证与第三态未触发原因_20261012.md`

按甲方案：**本轮只观测**。理由＝那类 jar 在普通分支下**当前是可用的**，改分支走向（乙方案）要重跑 G1、有回退风险。
⇒ 这一版**行为上应当与 dk 完全一致**，唯一区别是多一行日志。

⛔ **没动的**：`ProtectedInitJar` 的第三态、`App.java` 的噪声分流、db 清池口径、零回退、de 节拍、dg 内容校验、
dh 归属判据、di 换源过渡、dj 去重窗口、画中画、判死秒数。

## ① 怎么读这份对照

- 「文件未变」＝**逐字节**相同（不是比大小）；体积又一次巧合相同（**+0 B**），**只能看 MD5**。
- 类符号增删必须都是 0；字符串池消失必须为 0、新增必须**逐条对得上**。
- 本轮是**观测型改动**：只允许新增 1 条字符串（那行日志），多一条都要查。
