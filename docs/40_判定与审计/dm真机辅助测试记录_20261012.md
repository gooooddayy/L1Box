### ⭐ 为什么「投屏中」这三个字足以证明"电脑收到了"

查了代码路径（`CastDialog.pickDevice`）：

```java
DlnaManager.get().cast(device, mUrl, mTitle, (ok, msg) -> {
    if (ok) enterCastingMode();                       // ← 只有 ok==true 才显示「投屏中」
    else { ToastUtils.showShort("投屏失败：" + …); refresh(); }   // ← 失败会退回设备列表
});
```

⇒ **「投屏中」只在 SOAP 请求（`SetAVTransportURI` + `Play`）被那台设备正常应答时才出现**；
失败会明确弹「投屏失败：设备无响应」并退回列表。所以此刻的状态＝**电脑端的 DLNA 渲染器已经受理了这次投屏请求**。

（推过去的地址是真实播放地址：详情页用的是 `castUrl`；播放页用的是 `PlayerHelper.wrapForCast(播放地址, 请求头)`。）

⇒ 满足你的标准「投屏的电脑有接收到信息」。**电脑端是否出现画面/开始播放，你瞄一眼 Macast 窗口即可**（我这边看不到电脑屏幕）。

> 手机上我**没有**替你按「停止」—— 投屏状态保留着，方便你去电脑上确认；确认完按「停止」或「关闭」即可。
